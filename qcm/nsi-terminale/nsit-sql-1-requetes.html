1. [Modèle relationnel] Ce que garantit une clé primaire

QCU, une seule réponse · bonne réponse en D

Objectif : Savoir qu'une clé primaire identifie chaque ligne de façon unique.

On considère la relation BATEAU (nom_navire, tonnage, #id_proprietaire), de clé primaire nom_navire.

Que garantit la contrainte de clé primaire sur l'attribut nom_navire ?

  1. Que le nom du navire est écrit en majusculesUne clé primaire ne contrôle pas l'écriture des valeurs. Elle garantit que deux lignes n'ont jamais la même valeur de clé.
  2. Que le nom du navire est lié à une autre tableFaire le lien avec une autre table, c'est le rôle d'une clé étrangère, comme #id_proprietaire ici.
  3. Que le nom du navire n'est pas une chaîne de caractèresUne clé primaire peut être de n'importe quel type : texte, entier… Ce qui compte, c'est l'unicité de ses valeurs.
  4. Juste · Que deux navires de la table n'ont jamais le même nomOui : la clé primaire identifie chaque ligne. Le SGBD refuse d'insérer un second navire avec un nom déjà présent.

2. [Modèle relationnel] Reconnaître une clé étrangère

QCU, une seule réponse · bonne réponse en A

Objectif : Nommer l'attribut qui fait référence à la clé primaire d'une autre relation.

Schéma : VILLAGE (id_v, nom_v), de clé primaire id_v ; PIROGUE (id_p, couleur, #id_v), de clé primaire id_p.

Comment s'appelle l'attribut #id_v dans la relation PIROGUE ?

  1. Juste · Une clé étrangèreOui : #id_v fait référence à la clé primaire id_v de VILLAGE. Elle relie chaque pirogue à son village.
  2. Une clé primaireLa clé primaire de PIROGUE est id_p. Le # devant id_v signale autre chose : une référence vers VILLAGE.
  3. Un attribut calculéid_v n'est pas calculé : il contient l'identifiant d'un village existant. C'est une référence.
  4. Une contrainte de domaineUne contrainte de domaine fixe les valeurs permises d'un attribut (par exemple un entier positif). Le # marque une clé étrangère.

3. [Modèle relationnel] Relation, attribut, ligne

QCU, une seule réponse · bonne réponse en C

Objectif : Associer le mot « relation » à une table.

Dans le modèle relationnel, à quoi correspond concrètement une relation ?

  1. À une colonne de donnéesUne colonne correspond à un attribut. La relation est l'ensemble : toutes les colonnes et toutes les lignes.
  2. À une ligne de donnéesUne ligne est un enregistrement, ou n-uplet. La relation regroupe toutes les lignes d'un même schéma.
  3. Juste · À une table de donnéesOui : une relation se représente par une table. Ses colonnes sont les attributs, ses lignes les enregistrements.
  4. À un logiciel de base de donnéesLe logiciel est le SGBD (système de gestion de bases de données), comme SQLite. Une relation est une des tables qu'il gère.

4. [Modèle relationnel] Compter les attributs d'un schéma

QCU, une seule réponse · bonne réponse en B

Objectif : Lire un schéma relationnel et compter ses attributs.

Schéma : RECIF (id_r, nom, #id_zone), de clé primaire id_r.

Combien d'attributs la relation RECIF possède-t-elle ?

  1. 1 (id_r)id_r est la clé primaire, mais tous les champs sont des attributs, clés ou non : il faut compter les trois.
  2. Juste · 3 (id_r, nom et id_zone)Oui : un attribut par colonne, que ce soit une clé primaire, une clé étrangère ou un champ ordinaire.
  3. 2 (id_r et nom)#id_zone est une clé étrangère, et c'est aussi un attribut de RECIF : il compte.
  4. Autant qu'il y a de lignesLes lignes changent quand on ajoute des récifs ; le nombre d'attributs, lui, est fixé par le schéma : 3.

5. [Modèle relationnel] La contrainte de domaine

QCU, une seule réponse · bonne réponse en B

Objectif : Définir une contrainte de domaine.

Qu'est-ce qu'une contrainte de domaine ?

  1. L'obligation d'avoir au moins 100 lignesLe nombre de lignes n'est jamais imposé par le schéma. Le domaine concerne les valeurs d'un attribut.
  2. Juste · L'ensemble des valeurs permises pour un attribut (par exemple, un entier positif)Oui : le domaine d'un attribut, c'est son type et ses limites. Une altitude, par exemple, est un entier positif.
  3. Le nom du serveur où la base est rangéeLe domaine n'a rien à voir avec un nom de domaine Internet. Il décrit les valeurs qu'un attribut peut prendre.
  4. L'interdiction de supprimer des donnéesCe n'est pas une contrainte du modèle relationnel. Le domaine fixe les valeurs permises d'un attribut.

6. [Modèle relationnel] La contrainte NOT NULL

QCU, une seule réponse · bonne réponse en A

Objectif : Savoir ce qu'impose NOT NULL sur un attribut.

Que signifie la contrainte NOT NULL sur un attribut ?

  1. Juste · Que le champ doit toujours être renseignéOui : chaque ligne doit avoir une valeur pour cet attribut. Une insertion qui le laisse vide est refusée.
  2. Que sa valeur doit être égale à zéroZéro est une valeur. NULL, c'est l'absence de valeur : NOT NULL interdit de laisser le champ vide.
  3. Que sa valeur doit être uniqueL'unicité, c'est la contrainte UNIQUE (ou la clé primaire). NOT NULL interdit seulement l'absence de valeur.
  4. Que sa valeur doit être un nombre positifCe serait une contrainte de domaine, écrite avec CHECK. NOT NULL interdit seulement le vide.

7. [SQL] Choisir les colonnes affichées

QCU, une seule réponse · bonne réponse en B

Objectif : Écrire un SELECT qui ne garde que certaines colonnes.

Table : MONTAGNE (nom, altitude, type_roche).

Quelle requête affiche seulement le nom et l'altitude des montagnes de Mayotte ?

  1. SELECT * FROM MONTAGNE;L'étoile garde toutes les colonnes, y compris type_roche. Pour n'en garder que deux, on les nomme.
  2. Juste · SELECT nom, altitude FROM MONTAGNE;Oui : on liste après SELECT les colonnes voulues, séparées par des virgules, puis la table après FROM.
  3. GET nom, altitude FROM MONTAGNE;GET n'est pas un mot-clé SQL : une requête d'interrogation commence toujours par SELECT.
  4. SELECT nom AND altitude FROM MONTAGNE;SQLite accepte cette requête, mais AND calcule un « et » logique entre nom et altitude : on obtient une seule colonne de 0 et de 1. Les colonnes se séparent par des virgules.

8. [SQL] Filtrer les lignes avec WHERE

QCU, une seule réponse · bonne réponse en B

Objectif : Placer une condition de filtre avec WHERE, après FROM.

Table : TORTUE (id_t, espece, poids).

Quelle requête donne les tortues de plus de 100 kg ?

  1. SELECT * FROM TORTUE HAVING poids > 100;HAVING filtre des groupes, après un GROUP BY. SQLite refuse ici : « HAVING clause on a non-aggregate query ». Pour filtrer des lignes, on écrit WHERE.
  2. Juste · SELECT * FROM TORTUE WHERE poids > 100;Oui : SELECT … FROM … WHERE condition. Seules les lignes où la condition est vraie sont gardées.
  3. SELECT * WHERE poids > 100 FROM TORTUE;L'ordre des clauses est fixe : SELECT, puis FROM, puis WHERE. Ici, SQLite signale une erreur de syntaxe.
  4. SELECT * FROM TORTUE IF poids > 100;IF n'est pas un mot-clé de requête SQL. Le filtre des lignes s'écrit avec WHERE.

9. [SQL] Un texte qui commence par… : LIKE

QCU, une seule réponse · bonne réponse en D

Objectif : Utiliser LIKE et % pour chercher un début de texte.

Table : LYCEE (nom, ville).

Quelle requête affiche les lycées dont le nom commence par « Lycée de » ?

  1. SELECT * FROM LYCEE WHERE nom = 'Lycée de%';Avec =, le % est un caractère ordinaire : on cherche un nom égal à « Lycée de% », qui n'existe pas. Les jokers demandent LIKE.
  2. SELECT * FROM LYCEE WHERE nom LIKE '%Lycée de';Le % placé au début veut dire « n'importe quoi avant » : on chercherait les noms qui finissent par « Lycée de ».
  3. SELECT * FROM LYCEE WHERE nom CONTAINS 'Lycée de';CONTAINS n'existe pas en SQL standard ni dans SQLite. Pour chercher un morceau de texte, on utilise LIKE avec %.
  4. Juste · SELECT * FROM LYCEE WHERE nom LIKE 'Lycée de%';Oui : avec LIKE, % remplace n'importe quelle suite de caractères. 'Lycée de%' veut dire « commence par Lycée de ».

10. [SQL] Un texte qui contient… : LIKE '%…%'

QCU, une seule réponse · bonne réponse en D

Objectif : Chercher un mot n'importe où dans un texte.

Table : RECIF (id_r, nom, id_zone).

Quelle condition garde les récifs dont le nom contient le mot « Corail », n'importe où ?

  1. WHERE nom LIKE 'Corail%'Sans % au début, on ne garde que les noms qui commencent par Corail : « Grand Corail » serait oublié.
  2. WHERE nom = '%Corail%'Avec =, les % sont des caractères ordinaires : aucun nom n'est égal à « %Corail% ». Il faut LIKE.
  3. WHERE nom MATCH '*Corail*'MATCH sert à la recherche plein texte de certains SGBD ; SQLite le refuse sur une table ordinaire. La recherche simple s'écrit avec LIKE et %.
  4. Juste · WHERE nom LIKE '%Corail%'Oui : un % de chaque côté veut dire « n'importe quoi avant, n'importe quoi après ». Le mot peut être au début, au milieu ou à la fin.

11. [SQL] Deux conditions avec AND

QCU, une seule réponse · bonne réponse en C

Objectif : Combiner deux conditions qui doivent être vraies ensemble.

Table : PLANTATION (id_p, type, age).

Quelle requête donne les plants de vanille de plus de 2 ans ?

  1. SELECT * FROM PLANTATION WHERE type = 'vanille' OR age > 2;OR garde une ligne dès qu'une seule condition est vraie : l'ylang-ylang de 5 ans serait aussi affiché.
  2. SELECT * FROM PLANTATION WHERE type = 'vanille', age > 2;Les conditions ne se séparent pas par une virgule : SQLite signale une erreur de syntaxe. On les relie par AND ou OR.
  3. Juste · SELECT * FROM PLANTATION WHERE type = 'vanille' AND age > 2;Oui : AND garde les lignes où les deux conditions sont vraies à la fois : c'est de la vanille, et elle a plus de 2 ans.
  4. SELECT * FROM PLANTATION WHERE type = vanille AND age > 2;Sans apostrophes, vanille est lu comme un nom de colonne : SQLite répond « no such column: vanille ». Un texte s'écrit entre apostrophes.

12. [SQL] Une valeur parmi une liste : IN

QCU, une seule réponse · bonne réponse en A

Objectif : Tester l'appartenance à une liste de valeurs avec IN.

Table : ECOLE (id_e, nom, ville).

Quelle requête sélectionne les écoles situées à Sada ou à Chiconi ?

  1. Juste · SELECT * FROM ECOLE WHERE ville IN ('Sada', 'Chiconi');Oui : IN teste si la valeur est dans la liste. C'est plus court que ville = 'Sada' OR ville = 'Chiconi', et équivalent.
  2. SELECT * FROM ECOLE WHERE ville = ('Sada', 'Chiconi');= compare à une seule valeur ; SQLite refuse une liste ici (« row value misused »). Pour une liste de valeurs, on utilise IN.
  3. SELECT * FROM ECOLE WHERE ville = 'Sada' OR 'Chiconi';SQLite l'accepte, mais lit « ville = 'Sada' » OR « 'Chiconi' », et un texte seul vaut faux : seules les écoles de Sada sortent. Il faut répéter ville = devant chaque valeur.
  4. SELECT * FROM ECOLE WHERE ville BETWEEN 'Sada' AND 'Chiconi';BETWEEN cherche un intervalle, ici dans l'ordre alphabétique (et 'Sada' vient après 'Chiconi') : aucune école ne sort. Pour une liste de valeurs, on utilise IN.

13. [SQL] Un intervalle avec BETWEEN

QCU, une seule réponse · bonne réponse en C

Objectif : Utiliser BETWEEN et savoir qu'il inclut les bornes.

Table : RESERVOIR (id_r, nom, volume), volume en m³.

Quelle requête donne les réservoirs dont le volume est compris entre 500 et 1000 m³, bornes incluses ?

  1. SELECT * FROM RESERVOIR WHERE volume > 500 AND volume < 1000;Presque : les signes stricts excluent les réservoirs de 500 et de 1000 m³. Il faudrait >= et <=, ou BETWEEN.
  2. SELECT * FROM RESERVOIR WHERE volume FROM 500 TO 1000;FROM … TO n'existe pas dans une condition SQL : SQLite signale une erreur de syntaxe.
  3. Juste · SELECT * FROM RESERVOIR WHERE volume BETWEEN 500 AND 1000;Oui : BETWEEN a AND b garde les valeurs de a à b, bornes comprises. C'est l'écriture courte de volume >= 500 AND volume <= 1000.
  4. SELECT * FROM RESERVOIR WHERE volume IN (500, 1000);IN ne garde que les valeurs exactes 500 et 1000, pas celles qui sont entre les deux, comme 750.

14. [SQL] Tester l'absence de valeur : IS NULL

QCU, une seule réponse · bonne réponse en D

Objectif : Tester une valeur absente avec IS NULL, et non avec =.

Table : PARCELLE (id_parcelle, id_proprio).

Quelle requête donne les parcelles agricoles qui n'ont pas encore de propriétaire (valeur absente) ?

  1. SELECT * FROM PARCELLE WHERE id_proprio = NULL;C'est le piège classique : une comparaison avec NULL par = n'est jamais vraie, et la requête ne renvoie rien. On écrit IS NULL.
  2. SELECT * FROM PARCELLE WHERE id_proprio = '';La chaîne vide '' est une valeur (un texte sans caractère), pas l'absence de valeur NULL : ce ne sont pas les mêmes lignes.
  3. SELECT * FROM PARCELLE WHERE id_proprio EMPTY;EMPTY n'est pas un mot-clé SQL : SQLite signale une erreur de syntaxe. L'absence de valeur se teste avec IS NULL.
  4. Juste · SELECT * FROM PARCELLE WHERE id_proprio IS NULL;Oui : IS NULL teste l'absence de valeur. C'est la seule façon fiable de trouver les cases vides au sens de SQL.

15. [SQL] Supprimer les doublons : DISTINCT

QCU, une seule réponse · bonne réponse en C

Objectif : Afficher chaque valeur une seule fois avec DISTINCT.

Table : POISSON (id, espece).

Quelle requête affiche la liste des espèces présentes dans la table, sans doublons ?

  1. SELECT UNIQUE espece FROM POISSON;UNIQUE est une contrainte qu'on pose sur une colonne à la création d'une table. Dans un SELECT, SQLite le refuse : on écrit DISTINCT.
  2. SELECT DIFFERENT espece FROM POISSON;DIFFERENT n'est pas un mot-clé : SQLite croit que c'est une colonne et répond « no such column: DIFFERENT ».
  3. Juste · SELECT DISTINCT espece FROM POISSON;Oui : DISTINCT, placé juste après SELECT, supprime les lignes en double du résultat : « perroquet » n'apparaît qu'une fois.
  4. SELECT espece FROM POISSON ORDER BY espece;Le tri range les doublons côte à côte, mais il les garde : « perroquet » apparaîtrait deux fois.

16. [SQL] Trier dans l'ordre décroissant

QCU, une seule réponse · bonne réponse en B

Objectif : Trier les lignes avec ORDER BY … DESC.

Table : RESERVOIR (id_r, nom, volume).

Quelle requête affiche les réservoirs d'eau du plus grand au plus petit volume ?

  1. SELECT * FROM RESERVOIR ORDER BY volume;Sans précision, le tri est croissant (ASC) : on irait du plus petit au plus grand volume.
  2. Juste · SELECT * FROM RESERVOIR ORDER BY volume DESC;Oui : ORDER BY trie, et DESC (pour descending, « décroissant ») commence par la plus grande valeur.
  3. SELECT * FROM RESERVOIR SORT BY volume DESC;SORT BY n'existe pas en SQL : le tri s'écrit ORDER BY. SQLite signale une erreur de syntaxe.
  4. SELECT * FROM RESERVOIR WHERE volume DESC;DESC précise le sens d'un tri : il ne s'écrit qu'après ORDER BY. Après WHERE, SQLite signale une erreur.

17. [SQL] Trier selon deux critères

QCU, une seule réponse · bonne réponse en A

Objectif : Écrire un tri sur deux colonnes, dans deux sens différents.

Table : VILLAGE (nom, commune, pop).

Quelle fin de requête range les villages par commune (de A à Z), puis, dans une même commune, par population décroissante ?

  1. Juste · ORDER BY commune ASC, pop DESCOui : SQL trie d'abord par commune ; pour deux villages de la même commune, il trie par population, ici décroissante.
  2. ORDER BY commune ASC AND pop DESCLes critères de tri se séparent par une virgule, pas par AND : SQLite signale une erreur de syntaxe.
  3. SORT BY commune, pop DESCLe mot-clé est ORDER BY, pas SORT BY : SQLite signale une erreur de syntaxe.
  4. ORDER BY commune, popLe premier critère est bon, mais sans DESC la population serait triée dans l'ordre croissant.

18. [SQL] Compter les lignes : COUNT

QCU, une seule réponse · bonne réponse en C

Objectif : Compter les lignes d'une table avec COUNT(*).

Table : RECIF (id_r, nom, id_zone).

Quelle requête compte le nombre de récifs enregistrés ?

  1. SELECT SUM(*) FROM RECIF;SUM additionne les valeurs d'une colonne de nombres ; il ne compte pas les lignes, et SQLite refuse SUM(*).
  2. SELECT TOTAL(*) FROM RECIF;TOTAL existe dans SQLite, mais il additionne une colonne, comme SUM : il ne compte pas les lignes, et TOTAL(*) est refusé.
  3. Juste · SELECT COUNT(*) FROM RECIF;Oui : COUNT(*) compte les lignes du résultat. Ici, il y a 3 récifs.
  4. SELECT COUNT(id_r) WHERE RECIF;Il manque FROM : sans lui, SQLite ne sait pas quelle table lire, et cherche une colonne nommée RECIF.

19. [SQL] Additionner une colonne : SUM

QCU, une seule réponse · bonne réponse en D

Objectif : Additionner les valeurs d'une colonne avec SUM.

La table RECOLTE (poids, annee) enregistre les récoltes de vanille, poids en kg.

Quelle requête donne la masse totale de vanille récoltée en 2023 ?

  1. SELECT COUNT(poids) FROM RECOLTE WHERE annee = 2023;COUNT compte les récoltes (ici 2), il n'additionne pas leurs poids.
  2. SELECT ADD(poids) FROM RECOLTE WHERE annee = 2023;ADD n'est pas une fonction d'agrégation : c'est un mot réservé de SQL (il sert à modifier une table), et SQLite signale une erreur de syntaxe. On additionne une colonne avec SUM.
  3. SELECT poids + poids FROM RECOLTE;Ce calcul se fait ligne par ligne : chaque poids est doublé. Il n'y a ni total, ni filtre sur l'année.
  4. Juste · SELECT SUM(poids) FROM RECOLTE WHERE annee = 2023;Oui : WHERE garde les récoltes de 2023, puis SUM additionne leurs poids : 12,5 + 8 = 20,5 kg.

20. [SQL] Calculer une moyenne : AVG

QCU, une seule réponse · bonne réponse en A

Objectif : Calculer une moyenne sur des lignes filtrées.

Table : NAVIRE (nom, tonnage, port).

Quelle requête calcule le tonnage moyen des navires du port de Longoni ?

  1. Juste · SELECT AVG(tonnage) FROM NAVIRE WHERE port = 'Longoni';Oui : WHERE garde les navires de Longoni, puis AVG fait la moyenne de leur tonnage : (300 + 500) / 2 = 400.
  2. SELECT MEAN(tonnage) FROM NAVIRE WHERE port = 'Longoni';MEAN est le mot anglais pour « moyenne », mais ce n'est pas une fonction SQL. La moyenne s'écrit AVG (de average).
  3. SELECT AVG(tonnage) WHERE port = 'Longoni';Il manque FROM NAVIRE : sans lui, SQLite ne sait pas où trouver les colonnes tonnage et port.
  4. SELECT AVG(*) FROM NAVIRE WHERE port = 'Longoni';Une moyenne se calcule sur une colonne de nombres précise ; AVG(*) est refusé par SQLite.
