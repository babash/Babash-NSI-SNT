1. [Coût] Pourquoi compter des opérations

QCU, une seule réponse · bonne réponse en C

Objectif : Expliquer pourquoi on compare des algorithmes par leur nombre d'opérations.

Pourquoi compare-t-on deux algorithmes par leur nombre d'opérations plutôt que par leur temps en secondes ?

  1. Python ne permet pas de mesurer le tempsPython sait mesurer le temps (module time). Le problème est ailleurs : ce temps change d'une machine à l'autre.
  2. Une opération dure toujours plus d'une secondeUn ordinateur fait des millions d'opérations par seconde. On compte les opérations parce que ce nombre ne dépend pas de la machine.
  3. Juste · Le temps dépend de la machine, pas seulement de l'algorithmeOui : le même programme est plus rapide sur un ordinateur récent. Le nombre d'opérations, lui, ne dépend que de l'algorithme et de la taille des données.
  4. Un nombre d'opérations est toujours entierC'est vrai, mais ce n'est pas la raison. On compte les opérations car ce nombre caractérise l'algorithme, quelle que soit la machine.

2. [Coût] Compter les opérations de deux lignes

QCU, une seule réponse · bonne réponse en B

Objectif : Compter les opérations élémentaires avec une convention donnée.

Convention : on compte chaque affectation et chaque opération arithmétique (+, -, *, /) pour 1.

a = 10
b = a * 2 + 5

Combien d'opérations élémentaires ce code effectue-t-il ?

  1. 22, ce sont les deux affectations. Avec la convention de l'énoncé, il faut aussi compter la multiplication et l'addition de la deuxième ligne.
  2. Juste · 4Oui : l'affectation de a (1), puis dans la ligne 2 une multiplication, une addition et une affectation (3). Total : 4.
  3. 1Chaque ligne contient au moins une opération : ici, deux affectations, plus deux calculs dans la ligne 2.
  4. 5Tu as peut-être compté la lecture de a ou le nombre 5. La convention ne compte que les affectations et les opérations + - * / : cela fait 4.

3. [Coût] Compter les tours d'une boucle for

QCU, une seule réponse · bonne réponse en D

Objectif : Compter les exécutions du corps d'une boucle for i in range(n).

for i in range(n):
    print('Bonjour')

Avec n = 100, combien de fois print est-elle exécutée ?

  1. 1 foisLe corps de la boucle est répété à chaque tour, pas une seule fois. range(100) donne 100 valeurs de i, donc 100 tours.
  2. n × n foisn × n, c'est pour deux boucles imbriquées. Ici, une seule boucle : 100 tours.
  3. 101 foisrange(100) s'arrête avant 100 : il donne 0, 1, …, 99. Cela fait 100 valeurs, pas 101.
  4. Juste · 100 foisOui : range(n) donne les valeurs 0 à n - 1, soit n valeurs. Le corps est exécuté une fois pour chacune : 100 fois.

4. [Coût] Deux boucles l'une après l'autre

QCU, une seule réponse · bonne réponse en A

Objectif : Additionner le coût de deux boucles écrites à la suite.

On compte les affectations x = 1 et y = 2.

for i in range(n):
    x = 1
for j in range(n):
    y = 2

Quel est le coût T(n) ?

  1. Juste · T(n) = 2nOui : la première boucle fait n affectations, la seconde aussi. Deux boucles à la suite s'additionnent : n + n = 2n.
  2. T(n) = n²n², c'est quand une boucle est dans l'autre. Ici, la seconde boucle commence après la première : on additionne n + n.
  3. T(n) = n + 2Chaque boucle répète son affectation n fois : on compte n + n, pas n + 2.
  4. T(n) = 22, c'est le nombre de lignes d'affectation écrites. Mais chacune est répétée n fois par sa boucle.

5. [Coût] Une fonction appelée dans une boucle

QCU, une seule réponse · bonne réponse en D

Objectif : Multiplier le coût d'un appel par le nombre de tours.

La fonction f effectue 3 opérations à chaque appel.

for i in range(n):
    f(i)

Quel est le coût de ce code ?

  1. T(n) = 33, c'est le coût d'un seul appel. La boucle appelle f n fois : 3 opérations à chaque fois.
  2. T(n) = n + 3On n'ajoute pas 3 une seule fois : les 3 opérations reviennent à chaque tour. On multiplie : 3 × n.
  3. T(n) = 3ⁿ3ⁿ voudrait dire que le coût triple à chaque tour. Ici, chaque tour coûte toujours 3 : le total est 3n.
  4. Juste · T(n) = 3nOui : n tours, et 3 opérations par tour. Le coût d'un corps de boucle se multiplie par le nombre de tours.

6. [Coût] Deux boucles imbriquées

QCU, une seule réponse · bonne réponse en C

Objectif : Compter les exécutions dans deux boucles imbriquées.

for i in range(n):
    for j in range(n):
        k = i + j

Combien de fois l'addition i + j est-elle effectuée ?

  1. 2n fois2n, ce serait deux boucles l'une après l'autre. Ici, la boucle sur j est dans la boucle sur i : elle repart à zéro à chaque tour de i.
  2. n foisn, c'est le nombre de tours d'une seule boucle. La boucle intérieure se répète entièrement pour chaque valeur de i.
  3. Juste · n × n foisOui : pour chacun des n tours de i, la boucle sur j fait n tours. Total : n × n = n².
  4. n + 1 foisLes boucles imbriquées se multiplient : n tours de i, et n tours de j à chaque fois, soit n² additions.

for i in range(n):
    for j in range(n):

Avec n = 10, combien d'additions sont faites ?

  1. Juste · 100Oui : 10 tours de i, et pour chacun 10 tours de j : 10 × 10 = 100 additions.
  2. 1010 est le nombre de tours d'une seule boucle. Les deux boucles sont imbriquées : 10 × 10.
  3. 2020 = 10 + 10 : c'est le calcul pour deux boucles à la suite. Imbriquées, elles se multiplient.
  4. 10001000 = 10³, c'est le cas de trois boucles imbriquées. Ici, il y en a deux : 10² = 100.

8. [Coût] Une affectation dans chaque boucle imbriquée

QCU, une seule réponse · bonne réponse en B

Objectif : Compter des affectations placées à deux niveaux d'imbrication.

for i in range(n):
    x = 1
    for j in range(n):
        y = 2

Quel est le nombre total d'affectations x = 1 et y = 2 ?

  1. 2nx = 1 est bien exécutée n fois, mais y = 2 est dans la boucle intérieure : elle l'est n fois par tour de i, soit n².
  2. Juste · n + n²Oui : x = 1 est exécutée une fois par tour de i (n fois), y = 2 une fois par tour de j, pour chaque i (n² fois). Total : n + n².
  3. n²n², ce sont les affectations y = 2 seulement. Il faut ajouter les n affectations x = 1 de la boucle extérieure.
  4. 2n²x = 1 n'est pas dans la boucle sur j : elle n'est pas répétée n² fois, mais n fois seulement.

9. [Coût] Calculer T(n) pour une valeur de n

Un algorithme effectue T(n) = 5n + 2 opérations.

Avec n = 1000, combien d'opérations effectue-t-il ?

  1. 10071007 = 1000 + 5 + 2 : tu as additionné 5 au lieu de le multiplier. 5n veut dire 5 × n.
  2. 50005000 est bien 5 × 1000, mais il reste le + 2 : T(1000) = 5002.
  3. Juste · 5002Oui : 5 × 1000 + 2 = 5000 + 2 = 5002. On fait d'abord la multiplication, puis l'addition.
  4. 70007000 = (5 + 2) × 1000 : le 2 n'est pas multiplié par n. On calcule 5 × 1000, puis on ajoute 2.

10. [Coût] Appeler une fonction linéaire dans une boucle

QCU, une seule réponse · bonne réponse en B

Objectif : Reconnaître qu'un appel de coût n dans une boucle de n tours donne n².

Le coût de la fonction somme(liste) est proportionnel à la taille n de la liste. On l'appelle dans une boucle.

for i in range(n):
    somme(ma_liste)

Quel est le coût de ce code ?

  1. Linéaire (en n)Un seul appel est linéaire. Mais il est répété n fois : n appels de coût n, soit n × n.
  2. Juste · Quadratique (en n²)Oui : n tours, et à chaque tour un appel de coût n. Total : n × n = n². Un appel de fonction n'est pas forcément une opération élémentaire.
  3. ConstantLe coût dépend de n deux fois : par le nombre de tours et par le coût de somme. Il ne peut pas être constant.
  4. Cubique (en n³)n³ demanderait trois facteurs n. Ici, il y en a deux : les tours de boucle et le coût de somme.

  3. 1010 est le nombre de tours de la boucle sur i. Pour chacun, la boucle sur j en fait n.

12. [Coût] Accéder à un élément par son indice

QCU, une seule réponse · bonne réponse en D

Objectif : Savoir que lire liste[i] a un coût constant.

Lire la valeur de liste[0] est une opération dont le coût :

  1. est proportionnel à la taille de la listeC'est le coût d'un parcours (chercher une valeur, faire une somme). Un accès par indice va directement à la case.
  2. est quadratiqueUn coût quadratique vient de deux boucles imbriquées. Lire une case par son indice ne demande aucune boucle.
  3. double quand la liste doubleCe serait un coût linéaire. Pour lire liste[0], Python n'a pas besoin de regarder les autres éléments.
  4. Juste · ne dépend pas de la taille de la listeOui : Python va directement à la case demandée, sans parcourir la liste. Le coût est constant, que la liste ait 10 ou 10 millions d'éléments.

13. [Coût] Les tours d'une boucle while qui avance de 2

QCU, une seule réponse · bonne réponse en A

Objectif : Compter les tours d'une boucle while dont le pas est 2.

On suppose que n est un entier pair.

i = 0
while i < n:
    i = i + 2

Combien de tours de boucle sont effectués ?

  1. Juste · n / 2 toursOui : i prend les valeurs 0, 2, 4, …, n - 2, soit n / 2 valeurs. Pour n = 6 : 3 tours. Le coût reste linéaire.
  2. n toursi n'avance pas de 1 mais de 2 à chaque tour : il atteint n deux fois plus vite. Essaie avec n = 6 : i vaut 0, 2, 4, puis 6.
  3. 2n toursAvancer de 2 fait moins de tours, pas plus : il faut n / 2 pas de 2 pour aller de 0 à n.
  4. n² toursIl n'y a qu'une boucle, sans boucle intérieure : le nombre de tours ne peut pas être n².

14. [Coût] Écrire T(n) avec une instruction avant la boucle

Objectif : Écrire le coût exact d'une boucle précédée d'une instruction.

Une opération élémentaire est faite avant une boucle de n tours. Chaque tour de la boucle contient 3 opérations élémentaires.

Quel est le coût exact T(n) ?

  1. Juste · T(n) = 3n + 1Oui : 3 opérations par tour, n tours, donc 3n, plus l'opération faite une seule fois avant la boucle : 3n + 1.
  2. T(n) = n + 3Les 3 opérations reviennent à chaque tour : on les multiplie par n. L'opération d'avant la boucle s'ajoute une fois.
  3. T(n) = 3(n + 1)3(n + 1) = 3n + 3 : cela compterait 3 opérations avant la boucle. Il n'y en a qu'une : 3n + 1.
  4. T(n) = 4nL'opération d'avant la boucle n'est faite qu'une fois, pas à chaque tour : on l'ajoute, on ne la multiplie pas par n.

15. [Coût] Trois boucles imbriquées

Objectif : Compter les tours de trois boucles imbriquées de taille n.

Combien de tours fait le corps de 3 boucles imbriquées, chacune de taille n ?

  1. 3n3n, ce serait trois boucles à la suite. Imbriquées, elles se multiplient : n × n × n.
  2. n²n², c'est pour deux boucles imbriquées. Avec une troisième à l'intérieur, on multiplie encore par n.
  3. 3ⁿ3ⁿ est une croissance exponentielle, bien plus rapide. Trois boucles imbriquées donnent n × n × n = n³.
  4. Juste · n³Oui : n × n × n = n³. Pour n = 100, cela fait déjà un million de tours : ce coût cubique grandit très vite.

Un algorithme a un coût T(n) = 10n. On passe de n = 100 à n = 1000.

Le nombre d'opérations est :

  1. multiplié par 2n est multiplié par 10, pas par 2. Pour un coût linéaire, les opérations sont multipliées comme n : par 10.
  2. multiplié par 100Multiplier par 100 quand n est multiplié par 10, c'est le comportement d'un coût quadratique (10²). Ici, le coût est linéaire.
  3. Juste · multiplié par 10Oui : T(100) = 1000 et T(1000) = 10 000. Un coût linéaire est multiplié par le même facteur que n.

17. [Coût] Un coût quadratique quand n double

QCU, une seule réponse · bonne réponse en B

Objectif : Prévoir l'évolution d'un coût quadratique quand n double.

Un algorithme a un coût T(n) = n². La taille des données double : n devient 2n.

Le nombre d'opérations est :

  1. doubléDoublé, c'est le cas d'un coût linéaire. Ici, (2n)² = 4n² : le coût est multiplié par 4.
  2. Juste · quadrupléOui : (2n)² = 4n². Doubler n multiplie un coût quadratique par 4 : c'est pourquoi ces algorithmes ralentissent vite.
  3. tripléAucun calcul ne donne 3 ici : (2n)² = 2² × n² = 4n².
  4. multiplié par 88 = 2³ correspondrait à un coût cubique (n³). Pour n², c'est 2² = 4.

18. [Coût] Le coût qui grandit le plus vite

Objectif : Comparer des coûts pour de grandes valeurs de n.

Lequel de ces algorithmes devient le plus vite inutilisable quand n augmente ?

  1. T(n) = 1000n1000n est grand pour de petits n, mais il reste linéaire. Dès n = 1000, n² le rattrape, puis le dépasse toujours.
  2. Juste · T(n) = n²Oui : pour n = 1 000 000, n² vaut mille milliards, quand 1000n vaut un milliard. C'est le terme de plus haut degré qui décide.
  3. T(n) = 10n + 50010n + 500 est linéaire : les constantes 10 et 500 comptent peu quand n devient très grand.
  4. T(n) = 5050 est un coût constant : il ne change pas quand n augmente. C'est le meilleur cas possible.

for i in range(n):

        x = 1

Le nombre total d'opérations (tests et affectations) est de l'ordre de :

  1. n²Il n'y a qu'une boucle : le if n'est pas une boucle, il ne répète rien. Le coût reste de l'ordre de n.
  2. 1Le test est refait à chaque tour de boucle : le nombre d'opérations grandit avec n.
  3. Juste · nOui : n tests, plus une affectation un tour sur deux (n / 2). Total : environ 1,5 × n, donc de l'ordre de n.
  4. log(n)Un coût logarithmique vient d'une taille divisée par 2 à chaque étape (dichotomie). Ici, i avance de 1 en 1.

20. [Coût] Prévoir une durée pour un coût quadratique

QCU, une seule réponse · bonne réponse en A

Objectif : Utiliser le facteur de croissance d'un coût quadratique pour prévoir une durée.

Un algorithme met 2 ms pour n = 10. Son coût est quadratique.

Combien de temps mettra-t-il pour n = 100 ?

  1. Juste · 200 msOui : n est multiplié par 10, donc le temps par 10² = 100 : 2 ms × 100 = 200 ms.
  2. 20 ms20 ms, c'est multiplier par 10 comme n : ce serait un coût linéaire. Quadratique, le temps est multiplié par 10² = 100.
  3. 4 ms4 ms, c'est doubler le temps. Mais n est multiplié par 10, et le temps d'un coût quadratique par 10² = 100.
  4. 2 secondes2 s = 2000 ms, soit un facteur 1000 = 10³ : ce serait un coût cubique. Pour n², le facteur est 100.
