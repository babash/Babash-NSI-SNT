1. [Coût] Reconnaître un coût quadratique

QCU, une seule réponse

Objectif : Associer deux boucles imbriquées à un coût en n².

Quelle structure de code a un coût de l'ordre de n² ?

Bonne réponse : B

  1. Distracteur : Une boucle de 1 à nRetour : Une seule boucle de n tours donne un coût linéaire, de l'ordre de n.
  2. Bonne réponse : Une boucle de 1 à n dans une boucle de 1 à nRetour : Oui : imbriquées, les boucles se multiplient : n × n = n². C'est le coût des tris par insertion et par sélection.
  3. Distracteur : Deux boucles de 1 à n, l'une après l'autreRetour : À la suite, les coûts s'additionnent : n + n = 2n, c'est encore linéaire.
  4. Distracteur : Une instruction sans boucleRetour : Sans boucle, le nombre d'opérations ne dépend pas de n : le coût est constant.

2. [Coût] Un bloc if dans une boucle

QCU, une seule réponse

Objectif : Voir que le contenu d'un if de taille fixe ne change pas l'ordre de grandeur.

Dans une boucle de 1 à n, un bloc if contient 10 opérations.

Le coût total est :

Bonne réponse : A

  1. Bonne réponse : proportionnel à nRetour : Oui : au plus 10 opérations par tour, et n tours, soit au plus 10n. Le 10 est un coefficient : le coût reste linéaire.
  2. Distracteur : proportionnel à 10Retour : 10 opérations par tour, mais la boucle fait n tours : le total grandit avec n.
  3. Distracteur : proportionnel à n²Retour : Un if n'est pas une boucle : il ne répète rien. Il n'y a qu'une boucle, donc un coût de l'ordre de n.
  4. Distracteur : constantRetour : Le bloc est dans la boucle : il est exécuté jusqu'à n fois. Le coût dépend donc de n.

3. [Coût] Lire une valeur d'un dictionnaire

QCU, une seule réponse

Objectif : Connaître le coût de l'accès à une valeur d'un dictionnaire par sa clé.

Accéder à une valeur d'un dictionnaire à partir de sa clé, comme d['Sada'], est une opération :

Bonne réponse : A

  1. Bonne réponse : constante (elle ne dépend pas du nombre de clés)Retour : Oui : en moyenne, l'accès par clé ne dépend pas du nombre d'éléments. C'est un grand avantage du dictionnaire sur la recherche dans une liste.
  2. Distracteur : linéaire (elle dépend du nombre de clés)Retour : Python ne parcourt pas les clés une à une : il calcule où se trouve la valeur. Ce n'est pas un parcours.
  3. Distracteur : quadratiqueRetour : Un coût quadratique vient de deux boucles imbriquées. Lire d['Sada'] n'en demande aucune.
  4. Distracteur : variable selon la valeur stockéeRetour : Le coût ne dépend pas de ce qui est rangé : grand nombre ou longue chaîne, l'accès se fait de la même façon.

4. [Coût] Additionner des termes de même degré

QCU, une seule réponse

Objectif : Réduire une expression du coût avant de la simplifier.

Si T(n) = 3n + 5n + 2, alors T(n) est égal à :

Bonne réponse : C

  1. Distracteur : 15n + 2Retour : 3n + 5n s'additionnent : on ajoute les coefficients (3 + 5), on ne les multiplie pas.
  2. Distracteur : 8n²Retour : Additionner deux termes en n donne encore un terme en n : 3n + 5n = 8n, pas 8n².
  3. Bonne réponse : 8n + 2Retour : Oui : 3n + 5n = 8n, et le 2 reste à part. Le coût est linéaire.
  4. Distracteur : 3n + 7Retour : 5n et 2 ne s'additionnent pas : l'un dépend de n, l'autre non. On regroupe 3n + 5n = 8n.

5. [Coût] La règle de simplification

QCU, une seule réponse

Objectif : Énoncer la règle qui donne l'ordre de grandeur d'un coût.

Pour donner l'ordre de grandeur d'un coût T(n), on ne garde que :

Bonne réponse : A

  1. Bonne réponse : le terme de plus haut degré, sans son coefficientRetour : Oui : dans 15n² + 7n + 12, c'est n² qui domine quand n grandit. On écrit O(n²), sans le 15.
  2. Distracteur : la somme de tous les coefficientsRetour : Les coefficients ne disent pas comment le coût grandit avec n. On garde le terme qui grandit le plus vite.
  3. Distracteur : le terme le plus petitRetour : C'est l'inverse : quand n est grand, c'est le terme le plus grand qui l'emporte, les autres deviennent négligeables.
  4. Distracteur : le dernier nombre de l'expressionRetour : L'ordre d'écriture ne compte pas. On cherche le terme qui grandit le plus vite avec n.

6. [Coût] Simplifier un coût quadratique

QCU, une seule réponse

Objectif : Donner la forme simplifiée d'un coût polynomial.

Quelle est la forme simplifiée du coût T(n) = 15n² + 7n + 12 ?

Bonne réponse : C

  1. Distracteur : O(n)Retour : 7n est bien là, mais 15n² grandit beaucoup plus vite. On garde le terme de plus haut degré : n².
  2. Distracteur : O(n³)Retour : Aucun terme en n³ dans l'expression : le plus haut degré est 2.
  3. Bonne réponse : O(n²)Retour : Oui : on garde le terme de plus haut degré, 15n², et on retire son coefficient. Le coût est quadratique.
  4. Distracteur : O(1)Retour : 12 est la partie constante, la plus petite quand n grandit. C'est le terme en n² qui l'emporte.

7. [Coût] Simplifier un coût linéaire

QCU, une seule réponse

Objectif : Voir qu'une grande constante ne change pas l'ordre de grandeur.

Quelle est la forme simplifiée du coût T(n) = 100n + 5000 ?

Bonne réponse : D

  1. Distracteur : O(1)Retour : 5000 est grand, mais il ne dépend pas de n. Le terme 100n, lui, grandit sans limite : le coût est linéaire.
  2. Distracteur : O(n²)Retour : Il n'y a pas de terme en n² dans l'expression : le plus haut degré est 1.
  3. Distracteur : O(100)Retour : 100 est le coefficient de n : on le retire, mais on garde n. On écrit O(n).
  4. Bonne réponse : O(n)Retour : Oui : 100n domine 5000 dès que n est assez grand, et le coefficient 100 disparaît. Le coût est linéaire.

8. [Coût] Le pire des cas

QCU, une seule réponse

Objectif : Expliquer ce que garantit le coût dans le pire des cas.

Que représente le coût « dans le pire des cas » ?

Bonne réponse : A

  1. Bonne réponse : Un maximum que l'algorithme ne dépassera jamaisRetour : Oui : quelles que soient les données de taille n, l'algorithme ne fera pas plus d'opérations. C'est une garantie.
  2. Distracteur : Le temps moyen de toutes les exécutionsRetour : C'est le coût en moyenne, une autre mesure. Le pire des cas prend les données les plus défavorables.
  3. Distracteur : Le cas où l'ordinateur s'éteintRetour : Le pire des cas parle des données, pas d'une panne : ce sont les entrées qui demandent le plus d'opérations.
  4. Distracteur : Le temps le plus court possibleRetour : C'est le meilleur des cas (par exemple, l'élément cherché est le premier). Le pire des cas est le plus long.

9. [Coût] Chercher dans une liste non triée

QCU, une seule réponse

Objectif : Donner le coût de la recherche séquentielle dans le pire des cas.

Pour chercher un élément dans une liste non triée de n éléments, le coût dans le pire des cas est :

Bonne réponse : B

  1. Distracteur : O(1)Retour : O(1) serait le meilleur cas (l'élément est le premier). Dans le pire, il faut regarder toutes les cases.
  2. Bonne réponse : O(n)Retour : Oui : si l'élément est le dernier ou absent, on compare les n éléments. La recherche séquentielle a un coût linéaire.
  3. Distracteur : O(n²)Retour : Une seule boucle suffit : on compare chaque élément une fois à la valeur cherchée. Le coût est linéaire.
  4. Distracteur : O(log n)Retour : O(log n) est le coût de la dichotomie, qui demande une liste triée. Non triée, on doit tout parcourir.

10. [Coût] Le coût de la dichotomie

QCU, une seule réponse

Objectif : Associer la recherche dichotomique à un coût logarithmique.

La recherche dichotomique dans une liste triée (on divise la zone de recherche par 2 à chaque étape) a un coût :

Bonne réponse : D

  1. Distracteur : O(n)Retour : O(n), c'est le parcours de toute la liste. La dichotomie élimine la moitié des éléments à chaque étape : bien moins d'étapes.
  2. Distracteur : O(1)Retour : Le nombre d'étapes augmente avec la taille de la liste, même lentement : le coût n'est pas constant.
  3. Distracteur : O(n²)Retour : La dichotomie n'a qu'une boucle, et elle fait de moins en moins de tours : elle est bien plus rapide que n².
  4. Bonne réponse : O(log n)Retour : Oui : en divisant par 2 à chaque étape, 20 étapes suffisent pour un million d'éléments. C'est un coût logarithmique.

11. [Coût] Classer les familles de coût

QCU, une seule réponse

Objectif : Ranger les coûts usuels du plus faible au plus élevé.

Quel classement va du coût le plus faible au coût le plus élevé, pour n grand ?

Bonne réponse : D

  1. Distracteur : O(n²), O(n), O(log n), O(1)Retour : C'est l'ordre inverse : O(1) ne grandit pas du tout, O(n²) grandit le plus vite.
  2. Distracteur : O(1), O(n), O(log n), O(n²)Retour : log n grandit moins vite que n : pour n = 1 000 000, log₂ n vaut environ 20. O(log n) vient donc avant O(n).
  3. Distracteur : O(log n), O(1), O(n), O(n²)Retour : O(1) ne dépend pas de n : c'est le plus faible. log n, lui, grandit, même lentement.
  4. Bonne réponse : O(1), O(log n), O(n), O(n²)Retour : Oui : constant, logarithmique, linéaire, quadratique. Pour n = 1 000 000 : 1, environ 20, un million, mille milliards.

12. [Coût] Un coût exponentiel

QCU, une seule réponse

Objectif : Expliquer pourquoi un coût en 2ⁿ rend vite un algorithme impraticable.

Pourquoi un algorithme de coût 2ⁿ est-il impraticable dès que n dépasse 50 environ ?

Bonne réponse : C

  1. Distracteur : Python ne sait pas calculer les puissances de 2Retour : Python calcule très bien 2 ** 50. Le problème est le nombre d'opérations que l'algorithme doit faire, pas le calcul de 2ⁿ.
  2. Distracteur : La mémoire vive est pleine dès le départRetour : Le coût compté ici est un nombre d'opérations, donc du temps, pas de la mémoire. C'est le temps qui explose.
  3. Bonne réponse : Le nombre d'opérations devient beaucoup trop grandRetour : Oui : 2⁵⁰ vaut plus d'un million de milliards. À un milliard d'opérations par seconde, il faudrait environ 13 jours, et le double pour n = 51.
  4. Distracteur : Un tel algorithme est interdit par les normesRetour : Aucune norme n'interdit un algorithme. On l'évite parce qu'il est beaucoup trop long dès que n grandit.

13. [Coût] Le coût d'un tri à deux boucles

QCU, une seule réponse

Objectif : Associer un tri à deux boucles imbriquées à un coût quadratique.

Un algorithme de tri contient deux boucles imbriquées, qui vont chacune jusqu'à n. Son coût est de l'ordre de :

Bonne réponse : D

  1. Distracteur : O(n)Retour : O(n), ce serait une seule boucle. Deux boucles imbriquées se multiplient : n × n.
  2. Distracteur : O(log n)Retour : Aucun tri ne peut être aussi rapide : il faut au moins regarder chaque élément une fois.
  3. Distracteur : O(2ⁿ)Retour : 2ⁿ est bien plus rapide à grandir que n². Deux boucles imbriquées de n tours donnent n².
  4. Bonne réponse : O(n²)Retour : Oui : c'est le coût des tris par sélection et par insertion du programme de première, dans le pire des cas.

14. [Coût] Choisir un algorithme pour un milliard de données

QCU, une seule réponse

Objectif : Choisir le coût le plus faible pour un très grand n.

Pour traiter un milliard de données, lequel de ces coûts est préférable ?

Bonne réponse : D

  1. Distracteur : O(n)Retour : Un milliard d'opérations, c'est faisable, mais O(log n) n'en demande qu'une trentaine : il est bien préférable.
  2. Distracteur : O(n²)Retour : n² ferait un milliard de milliards d'opérations : plusieurs dizaines d'années de calcul.
  3. Distracteur : O(n³)Retour : n³ est le plus élevé des quatre : c'est le pire choix pour un grand n.
  4. Bonne réponse : O(log n)Retour : Oui : log₂ d'un milliard vaut environ 30. C'est le coût le plus faible des quatre.

15. [Coût] Simplifier une somme de termes

QCU, une seule réponse

Objectif : Garder le terme dominant entre n² et n log n.

Quelle est la forme simplifiée du coût T(n) = n² + n log n ?

Bonne réponse : C

  1. Distracteur : O(n log n)Retour : n log n grandit moins vite que n², car log n grandit moins vite que n. On garde le terme dominant : n².
  2. Distracteur : O(n³)Retour : On ne multiplie pas les termes : on garde le plus grand. Aucun terme ici n'est en n³.
  3. Bonne réponse : O(n²)Retour : Oui : n log n est négligeable devant n² quand n est grand. On ne garde que n².
  4. Distracteur : O(log n)Retour : log n est le facteur qui grandit le moins vite : on garde au contraire le terme qui grandit le plus vite.

16. [Coût] Ce que dit la règle de simplification

QCU, une seule réponse

Objectif : Appliquer la règle de simplification à des affirmations.

Laquelle de ces affirmations est vraie ?

Bonne réponse : C

  1. Distracteur : O(n²) est plus efficace que O(n)Retour : C'est l'inverse : n² grandit plus vite que n. Un algorithme en O(n) est plus efficace pour n grand.
  2. Distracteur : O(1) signifie que l'algorithme fait 1 seule opérationRetour : O(1) signifie que le nombre d'opérations ne dépend pas de n : il peut en faire 1, 50 ou 1000.
  3. Bonne réponse : O(100n) est identique à O(n)Retour : Oui : on retire les coefficients. 100n et n sont tous les deux linéaires : doubler n double le coût.
  4. Distracteur : O(log n) est moins efficace que O(n)Retour : C'est l'inverse : log n grandit beaucoup moins vite que n. La dichotomie (O(log n)) est plus rapide qu'un parcours (O(n)).

17. [Coût] Une boucle intérieure de taille fixe

QCU, une seule réponse

Objectif : Voir qu'une boucle de taille fixe ne change pas l'ordre de grandeur.

for i in range(n):
    for j in range(5):
        x = 1

Quelle est la forme simplifiée du coût de ce code ?

Bonne réponse : B

  1. Distracteur : O(n²)Retour : Deux boucles imbriquées ne donnent n² que si les deux vont jusqu'à n. Ici, la boucle intérieure fait toujours 5 tours.
  2. Bonne réponse : O(n)Retour : Oui : 5 × n affectations, et on retire le coefficient 5. Le coût est linéaire.
  3. Distracteur : O(1)Retour : La boucle extérieure fait n tours : le coût dépend de n, il n'est pas constant.
  4. Distracteur : O(log n)Retour : Rien n'est divisé par 2 ici : i avance de 1 en 1, et chaque tour fait 5 affectations.

18. [Coût] Un code sans boucle

QCU, une seule réponse

Objectif : Reconnaître un coût constant.

Quel est le coût d'un code qui ne contient aucune boucle, seulement des if et des print ?

Bonne réponse : B

  1. Distracteur : O(n)Retour : Sans boucle (ni appel de fonction qui boucle), aucune instruction n'est répétée : le nombre d'opérations ne dépend pas de n.
  2. Bonne réponse : O(1)Retour : Oui : chaque instruction est exécutée au plus une fois. Le nombre d'opérations est borné : le coût est constant.
  3. Distracteur : O(0)Retour : Le code fait bien des opérations, mais leur nombre ne dépend pas de n. On écrit O(1) pour un coût constant.
  4. Distracteur : Il dépend des donnéesRetour : Les if choisissent quelles lignes s'exécutent, mais il y en a toujours un nombre limité : le coût est constant.

19. [Coût] Nommer le coût n log n

QCU, une seule réponse

Objectif : Nommer la famille de coût n log n.

Un algorithme dont le coût est en O(n log n) est dit :

Bonne réponse : A

  1. Bonne réponse : quasi linéaireRetour : Oui : n log n est à peine plus grand que n (pour un million d'éléments, log₂ n vaut environ 20). On le dit quasi linéaire.
  2. Distracteur : quadratiqueRetour : Quadratique, c'est n². n log n grandit beaucoup moins vite : c'est le coût du tri fusion, vu en terminale.
  3. Distracteur : logarithmiqueRetour : Logarithmique, c'est log n seul. Ici, log n est multiplié par n : c'est un peu plus que linéaire.
  4. Distracteur : constantRetour : Le coût grandit avec n : il ne peut pas être constant.

20. [Coût] Chercher un doublon en comparant tout

QCU, une seule réponse

Objectif : Évaluer le coût d'une comparaison de chaque élément à tous les autres.

Pour chercher un doublon dans une liste de taille n, on compare chaque élément à tous les autres. Dans le pire des cas, le coût est :

Bonne réponse : B

  1. Distracteur : O(n)Retour : Une comparaison par élément ne suffit pas : chaque élément est comparé à tous les autres, soit n comparaisons pour chacun.
  2. Bonne réponse : O(n²)Retour : Oui : pour chacun des n éléments, on fait jusqu'à n comparaisons. Deux boucles imbriquées : n × n.
  3. Distracteur : O(1)Retour : Le nombre de comparaisons dépend de la taille de la liste : il ne peut pas être constant.
  4. Distracteur : O(log n)Retour : Rien ne divise la liste par 2 : on compare toutes les paires d'éléments, ce qui fait de l'ordre de n².
