Corrigé enseignant·e. Cette page donne les bonnes réponses et tous les retours. Elle sert à relire le quiz ; elle ne se donne pas aux élèves. L'aperçu sans réponses : nsi1-ligne-de-commande.html.

1. [Navigation] La commande pwd

QCU, une seule réponse

Objectif : Savoir ce qu'affiche la commande pwd.

pwd

Que fait exactement cette commande ?

Bonne réponse : D

  1. Distracteur : Elle change le mot de passe de l'utilisateurRetour : C'est une confusion fréquente : pour changer de mot de passe, la commande est passwd. pwd veut dire print working directory, « affiche le répertoire de travail ».
  2. Distracteur : Elle affiche le contenu du dossier courantRetour : Pour lister les fichiers et sous-dossiers, la commande est ls (list). pwd affiche seulement le chemin du dossier où tu es.
  3. Distracteur : Elle fait remonter à la racineRetour : Pour changer de répertoire, on utilise cd (change directory), par exemple cd /. pwd ne déplace pas : il affiche.
  4. Bonne réponse : Elle affiche le chemin absolu du répertoire de travailRetour : Oui : pwd (print working directory) affiche où tu te trouves dans l'arborescence, depuis la racine /. Pratique avant un cd ou un rm.

2. [Navigation] Remonter d'un niveau avec cd ..

QCU, une seule réponse

Objectif : Prévoir le répertoire atteint avec un chemin relatif ..

Le répertoire de travail est /home/eleve/sauvegardes. On saisit la commande suivante.

cd ..

Quel est le nouveau répertoire de travail ?

Bonne réponse : A

  1. Bonne réponse : /home/eleveRetour : Oui : .. désigne le répertoire parent. Depuis /home/eleve/sauvegardes, on remonte d'un niveau, dans /home/eleve.
  2. Distracteur : /homeRetour : Ce serait remonter de deux niveaux, avec cd ../.. ; .. ne fait monter que d'un niveau.
  3. Distracteur : /home/eleve/sauvegardesRetour : Le répertoire a changé : un seul point (.) désigne le dossier courant, mais deux points (..) désignent le dossier parent.
  4. Distracteur : / (la racine)Retour : Pour aller directement à la racine, on écrit cd /. Avec .., on ne remonte que d'un niveau.

3. [Arborescence] Reconnaître un chemin absolu

QCU, une seule réponse

Objectif : Distinguer un chemin absolu d'un chemin relatif.

Parmi ces chemins, lequel est un chemin absolu ?

Bonne réponse : B

  1. Distracteur : sauvegardes/note.txtRetour : Ce chemin ne commence pas par / : il est relatif, il part du répertoire de travail.
  2. Bonne réponse : /var/log/sys.logRetour : Oui : un chemin absolu commence toujours par la racine /. Il désigne le même fichier, quel que soit le répertoire de travail.
  3. Distracteur : ../admin/configRetour : .. part du dossier parent du répertoire de travail : c'est un chemin relatif.
  4. Distracteur : sys.logRetour : Un simple nom de fichier est un chemin relatif : le fichier est cherché dans le répertoire de travail.

4. [Fichiers] Afficher les fichiers cachés

QCU, une seule réponse

Objectif : Lister aussi les fichiers dont le nom commence par un point.

Un dossier de configuration au nom qui commence par un point (par exemple .secret) n'apparaît pas avec ls.

Quelle commande l'affiche aussi ?

Bonne réponse : A

  1. Bonne réponse : ls -aRetour : Oui : l'option -a (all, « tout ») liste tous les éléments, y compris les fichiers et dossiers cachés, ceux dont le nom commence par un point.
  2. Distracteur : ls -lRetour : -l (long) affiche les détails : droits, taille, propriétaire. Mais les éléments cachés restent cachés sans -a.
  3. Distracteur : show .secretRetour : show n'est pas une commande standard de Linux : le terminal répondrait « command not found ».
  4. Distracteur : ls -RRetour : -R (récursif) liste aussi le contenu des sous-dossiers, mais pas les éléments cachés, sauf avec -a en plus.

5. [Fichiers] Créer un fichier vide

QCU, une seule réponse

Objectif : Créer un fichier vide sans ouvrir d'éditeur.

Quelle commande crée un fichier texte vide nommé script.sh ?

Bonne réponse : C

  1. Distracteur : mkdir script.shRetour : mkdir (make directory) crée un dossier, pas un fichier : on aurait un dossier nommé script.sh.
  2. Distracteur : cat script.shRetour : cat affiche le contenu d'un fichier qui existe. Ici, il répondrait « No such file or directory » (fichier ou dossier introuvable).
  3. Bonne réponse : touch script.shRetour : Oui : touch crée le fichier vide s'il n'existe pas (et sinon met à jour sa date de modification).
  4. Distracteur : create script.shRetour : create n'est pas une commande de Linux : le terminal répondrait « command not found ».

6. [Fichiers] Copier un fichier dans un dossier

QCU, une seule réponse

Objectif : Écrire une copie dans le bon ordre : source puis destination.

Quelle commande copie le fichier note.txt dans le dossier sauvegardes/ du répertoire de travail ?

Bonne réponse : B

  1. Distracteur : mv note.txt sauvegardes/Retour : mv (move) déplace le fichier : il n'y aurait plus de note.txt à sa place d'origine. Pour garder l'original, on copie avec cp.
  2. Bonne réponse : cp note.txt sauvegardes/Retour : Oui : cp (copy) s'écrit cp source destination. note.txt reste en place, et une copie arrive dans sauvegardes/.
  3. Distracteur : cp sauvegardes/ note.txtRetour : L'ordre est inversé : on demanderait de copier le dossier sauvegardes/ vers note.txt, et cp refuse un dossier sans l'option -r.
  4. Distracteur : copy note.txt sauvegardes/Retour : copy est la commande de Windows (invite de commandes). Sous Linux, la copie s'écrit cp.

7. [Fichiers] Renommer un fichier

QCU, une seule réponse

Objectif : Renommer un fichier avec mv.

Quelle commande renomme ancien.txt en nouveau.txt, dans le même répertoire ?

Bonne réponse : C

  1. Distracteur : rename ancien.txt nouveau.txtRetour : rename existe sur certains systèmes, mais pour renommer beaucoup de fichiers à la fois, avec une autre syntaxe. Pour un seul fichier, on utilise mv.
  2. Distracteur : cp ancien.txt nouveau.txtRetour : cp fait une copie : ancien.txt existerait toujours, à côté de nouveau.txt.
  3. Bonne réponse : mv ancien.txt nouveau.txtRetour : Oui : « déplacer » un fichier vers un autre nom, dans le même dossier, revient à le renommer.
  4. Distracteur : mv nouveau.txt ancien.txtRetour : L'ordre est inversé : la source (le fichier qui existe, ancien.txt) vient d'abord, puis la destination (nouveau.txt).

8. [Fichiers] Supprimer un dossier qui n'est pas vide

QCU, une seule réponse

Objectif : Choisir la commande qui supprime un dossier et son contenu.

Quelle commande supprime définitivement le dossier archives, qui contient déjà plusieurs fichiers ?

Bonne réponse : B

  1. Distracteur : rm archivesRetour : Sans option, rm refuse de supprimer un dossier : « cannot remove 'archives': Is a directory » (c'est un dossier).
  2. Bonne réponse : rm -r archivesRetour : Oui : l'option -r (récursif) supprime le dossier et tout ce qu'il contient. Attention : sous Linux, il n'y a pas de corbeille.
  3. Distracteur : rmdir archivesRetour : rmdir (remove directory) ne supprime que les dossiers vides : ici, il répondrait « Directory not empty ».
  4. Distracteur : del archivesRetour : del est une commande de Windows : sous Linux, le terminal répondrait « command not found ».

9. [Lecture] Afficher le contenu d'un fichier

QCU, une seule réponse

Objectif : Afficher tout le contenu d'un fichier dans le terminal.

Quelle commande affiche tout le contenu du fichier sys.log dans le terminal ?

Bonne réponse : A

  1. Bonne réponse : cat sys.logRetour : Oui : cat (de concatenate, « mettre bout à bout ») affiche le contenu du fichier directement dans le terminal.
  2. Distracteur : read sys.logRetour : read lit ce qu'on tape au clavier et le range dans une variable. Ici, Bash refuse aussitôt le nom : « read: sys.log': not a valid identifier ». Pour afficher un fichier, on utilise cat.
  3. Distracteur : ls sys.logRetour : ls confirme seulement que le fichier existe en affichant son nom, pas son contenu.
  4. Distracteur : echo sys.logRetour : echo affiche le texte qu'on lui donne : il écrirait le mot « sys.log », pas le contenu du fichier.

10. [Recherche] Chercher un texte dans un fichier

QCU, une seule réponse

Objectif : Savoir quelle commande cherche un texte dans un fichier.

Quelle commande recherche un texte dans un fichier ?

Bonne réponse : B

  1. Distracteur : lsRetour : ls liste les fichiers d'un dossier ; il ne regarde pas à l'intérieur des fichiers.
  2. Bonne réponse : grepRetour : Oui : grep motif fichier affiche les lignes du fichier qui contiennent le motif. Par exemple, grep erreur sys.log.
  3. Distracteur : catRetour : cat affiche tout le fichier : on peut y chercher à l'œil, mais c'est grep qui trouve les lignes qui contiennent le texte.
  4. Distracteur : pwdRetour : pwd affiche le répertoire de travail ; il ne cherche rien dans les fichiers.

11. [Aide] Lire le manuel d'une commande

QCU, une seule réponse

Objectif : Savoir obtenir le mode d'emploi détaillé d'une commande.

Quelle commande affiche le fonctionnement détaillé d'une autre commande ?

Bonne réponse : C

  1. Distracteur : helpRetour : help n'explique que les commandes internes de Bash, comme cd. Pour une commande comme chmod, la page de manuel s'ouvre avec man.
  2. Distracteur : sudoRetour : sudo lance une commande avec les droits du super-utilisateur ; il n'explique rien.
  3. Bonne réponse : manRetour : Oui : man (manual, « manuel ») affiche la page de manuel d'une commande : man chmod explique chmod et toutes ses options.
  4. Distracteur : chmodRetour : chmod change les droits d'un fichier. C'est man chmod qui en affiche le mode d'emploi.

12. [Archives] Décompresser une archive zip

QCU, une seule réponse

Objectif : Savoir décompresser un fichier .zip.

Quelle commande décompresse le fichier archive.zip ?

Bonne réponse : D

  1. Distracteur : man archive.zipRetour : man affiche le manuel d'une commande ; avec un nom de fichier, il ne trouverait pas de page de manuel.
  2. Distracteur : chmod archive.zipRetour : chmod change les droits d'un fichier, et il attend des droits avant le nom. Il ne décompresse rien.
  3. Distracteur : sudo archive.zipRetour : sudo lance une commande en super-utilisateur ; archive.zip n'est pas une commande, il n'y a rien à lancer.
  4. Bonne réponse : unzip archive.zipRetour : Oui : unzip (« dézipper ») extrait les fichiers d'une archive .zip dans le répertoire de travail.

13. [Administration] Le rôle de sudo

QCU, une seule réponse

Objectif : Savoir ce que fait sudo.

sudo apt update

Quel est le rôle de sudo au début de cette ligne ?

Bonne réponse : D

  1. Distracteur : Supprimer des fichiersRetour : La suppression se fait avec rm. sudo ne fait rien seul : il donne des droits à la commande qui le suit.
  2. Distracteur : Aller à la racine du systèmeRetour : Pour aller à la racine, on écrit cd /. sudo ne change pas de répertoire.
  3. Distracteur : Changer de mot de passeRetour : On change de mot de passe avec passwd. sudo demande ton mot de passe, mais pour lancer une commande avec plus de droits.
  4. Bonne réponse : Lancer la commande qui suit en tant que super-utilisateurRetour : Oui : sudo (superuser do) lance la commande avec les droits d'un autre utilisateur, par défaut le super-utilisateur (root). Le mot de passe est demandé.

14. [Droits] La valeur de chaque droit

Appariement

Objectif : Associer chaque droit à sa valeur dans la notation octale de chmod.

Dans la notation octale de chmod (comme chmod 754), chaque droit a une valeur.

Associer chaque droit à sa valeur.

ÉlémentAssociation attendue
Lire (r)4
Exécuter (x)1
Écrire (w)2

Retour : r vaut 4, w vaut 2, x vaut 1 : on additionne les droits accordés. rwx = 4 + 2 + 1 = 7, r-x = 4 + 1 = 5, r-- = 4.

15. [Droits] L'ordre des trois groupes de droits

QCU, une seule réponse

Objectif : Savoir dans quel ordre s'écrivent les droits d'un fichier.

Dans -rwxr-x---, dans quel ordre sont écrits les trois groupes de droits ?

Bonne réponse : C

  1. Distracteur : Groupe, propriétaire, autresRetour : Le premier bloc rwx est celui du propriétaire, qui a en général le plus de droits. Le groupe vient ensuite.
  2. Distracteur : Propriétaire, autres, groupeRetour : Le groupe passe avant les autres : on va du plus proche (le propriétaire) au plus éloigné (tous les autres utilisateurs).
  3. Bonne réponse : Propriétaire, groupe, autresRetour : Oui : après le premier caractère (- pour un fichier, d pour un dossier), on lit les droits du propriétaire (u), du groupe (g), puis des autres (o).
  4. Distracteur : Autres, groupe, propriétaireRetour : C'est l'ordre inverse. On lit de gauche à droite : propriétaire (u), groupe (g), autres (o), comme dans chmod u, g, o.

16. [Droits] Lire les droits du groupe

QCU, une seule réponse

Objectif : Lire les droits accordés au groupe dans une écriture -rwxr-xr--.

$ ls -l rapport.sh
-rwxr-xr-- 1 eleve gp1 120 nov. 20 10:00 rapport.sh

Quels droits a le groupe gp1 sur le fichier rapport.sh ?

Bonne réponse : D

  1. Distracteur : L'exécution seulementRetour : Le bloc du groupe est r-x : il contient aussi r, la lecture. Découpe -rwxr-xr-- en rwx, r-x et r--.
  2. Distracteur : La lecture seulementRetour : r-- est le bloc des autres utilisateurs. Le groupe, au milieu, a r-x : lecture et exécution.
  3. Distracteur : La lecture, l'écriture et l'exécutionRetour : rwx, ce sont les droits du propriétaire, le premier bloc. Le groupe a le deuxième bloc, r-x.
  4. Bonne réponse : La lecture et l'exécutionRetour : Oui : après le -, rwx est au propriétaire (eleve), r-x au groupe (gp1), r-- aux autres. Le groupe peut lire et exécuter, pas modifier.

17. [Droits] Donner seulement la lecture à tous

QCU, une seule réponse

Objectif : Choisir la notation de chmod qui fixe exactement les droits voulus.

Quelle commande donne à tous les utilisateurs le droit de lecture, et uniquement ce droit, sur le fichier UnFichier ?

Bonne réponse : A

  1. Bonne réponse : chmod 444 UnFichierRetour : Oui : 4 est la lecture ; 444 donne r-- au propriétaire, au groupe et aux autres, et retire tous les autres droits : r--r--r--.
  2. Distracteur : chmod a+r UnFichierRetour : +r ajoute la lecture, mais garde les droits existants : un fichier en rw-r----- deviendrait rw-r--r--, avec encore l'écriture. Pour fixer exactement les droits, on utilise l'octal.
  3. Distracteur : chmod 777 UnFichierRetour : 7 = 4 + 2 + 1 : 777 donne tous les droits (lecture, écriture, exécution) à tout le monde, bien plus que la lecture.
  4. Distracteur : chmod 111 UnFichierRetour : 1 est la valeur de l'exécution : 111 donne seulement l'exécution, à tous. La lecture vaut 4.
