1. [Photographie] Le photosite du capteur

QCU, une seule réponse · bonne réponse en C

Objectif : Distinguer le photosite du capteur et le pixel de l'image.

Sur le capteur d'un appareil photo, qu'est-ce qu'un photosite ?

  1. Un point de l'image enregistrée, avec sa couleurÇa, c'est un pixel : un élément de l'image enregistrée. Le photosite est sur le capteur, avant le calcul de l'image.
  2. Un point d'encre sur une photo impriméeLe photosite est dans l'appareil photo, pas sur le papier : c'est lui qui capte la lumière.
  3. Juste · Une minuscule cellule qui mesure la lumière reçueOui : le capteur est couvert de photosites. Chacun mesure la quantité de lumière qu'il reçoit ; des algorithmes en tirent ensuite les pixels de l'image.
  4. Un petit fichier qui décrit la photoLes informations sur la photo (date, réglages, lieu) sont les métadonnées EXIF. Un photosite est une cellule du capteur.

2. [Pixels] La définition d'une image

QCU, une seule réponse · bonne réponse en A

Objectif : Calculer la définition d'une image (nombre de pixels).

Une photo du lagon mesure 4 000 pixels de large et 3 000 pixels de haut. Quelle est sa définition ?

  1. Juste · 12 millions de pixelsOui : 4 000 × 3 000 = 12 000 000 pixels, soit 12 mégapixels (12 Mpx).
  2. 7 000 pixelsTu as additionné la largeur et la hauteur. L'image est un tableau : on multiplie, 4 000 × 3 000.
  3. 36 millions de pixelsTu as multiplié aussi par 3, le nombre de couleurs R, V, B. Ce calcul donne la taille en octets, pas le nombre de pixels.
  4. 1,2 million de pixelsVérifie les zéros : 4 000 × 3 000 = 12 000 000, soit 12 millions.

3. [Couleurs] Les lettres R, V, B

QCU, une seule réponse · bonne réponse en C

Objectif : Connaître les trois couleurs du codage RVB.

Que signifient les lettres RVB (RGB en anglais), utilisées pour coder la couleur d'un pixel ?

  1. Résolution, Vitesse, Bande passanteCes mots parlent de qualité d'image et de réseau. RVB désigne trois couleurs de lumière.
  2. Rapport, Volume, BinaireCes mots ne désignent pas des couleurs. Chaque lettre de RVB est une couleur de lumière.
  3. Juste · Rouge, Vert, BleuOui : chaque pixel d'un écran mélange ces trois lumières. En anglais : Red, Green, Blue.
  4. Rotation, Valeur, BrillanceCe ne sont pas des termes du codage des couleurs. RVB : rouge, vert, bleu.

4. [Couleurs] Mélanger le rouge et le bleu

QCU, une seule réponse · bonne réponse en D

Objectif : Trouver la couleur d'un pixel à partir de ses trois composantes.

Un pixel a les composantes R = 255, V = 0, B = 255. Quelle couleur affiche-t-il ?

  1. JauneLe jaune mélange le rouge et le vert : (255, 255, 0). Ici, c'est le vert qui vaut 0.
  2. VertLe vert seul serait (0, 255, 0). Ici, la composante verte vaut 0 : il n'y a pas de vert du tout.
  3. CyanLe cyan mélange le vert et le bleu : (0, 255, 255). Ici, c'est le rouge qui est à fond.
  4. Juste · MagentaOui : rouge à fond et bleu à fond, sans vert. Sur un écran, la lumière rouge et la lumière bleue donnent le magenta (un rose violacé).

5. [Couleurs] Le code du blanc

QCU, une seule réponse · bonne réponse en C

Objectif : Savoir que, sur un écran, toutes les lumières à fond donnent le blanc.

Quel triplet (R, V, B) code le blanc ?

  1. (0, 0, 0)Toutes les lumières éteintes : c'est le noir. Sur un écran, on ajoute de la lumière pour éclaircir.
  2. (1, 1, 1)1 est une lumière presque éteinte : (1, 1, 1) est un noir. Chaque composante va de 0 à 255.
  3. Juste · (255, 255, 255)Oui : rouge, vert et bleu à fond donnent le blanc. Sur un écran, la lumière s'ajoute.
  4. (128, 128, 128)Trois composantes égales donnent bien un gris ; à 128, c'est un gris moyen. Le blanc demande le maximum, 255.

6. [Couleurs] Synthèse additive et soustractive

QCU, une seule réponse · bonne réponse en D

Objectif : Distinguer la synthèse additive (écran) de la synthèse soustractive (encre).

Un écran mélange des lumières (RVB). Une imprimante mélange des encres (CMJN : cyan, magenta, jaune, noir). Quelle phrase est juste ?

  1. Écran : synthèse soustractive ; imprimante : synthèse additiveC'est l'inverse : l'écran part du noir et ajoute des lumières ; l'encre part du papier blanc et absorbe de la lumière.
  2. Écran et imprimante utilisent les mêmes couleurs primairesLes primaires sont différentes : rouge, vert, bleu pour l'écran ; cyan, magenta, jaune pour l'encre.
  3. Écran : couleurs en binaire ; imprimante : en décimalLa façon d'écrire les nombres ne change rien aux couleurs. La différence est physique : ajouter ou retirer de la lumière.
  4. Juste · Écran : synthèse additive ; imprimante : synthèse soustractiveOui : sur l'écran, on part du noir et on ajoute des lumières (tout à fond : blanc). L'encre retire de la lumière au papier blanc.

7. [Couleurs] Pourquoi 255 ?

QCU, une seule réponse · bonne réponse en A

Objectif : Comprendre pourquoi une composante va de 0 à 255.

Chaque composante R, V, B est codée sur un octet. Quel nombre décimal représente l'octet 11111111, la plus grande valeur possible ?

  1. Juste · 255Oui : 2⁸ - 1 = 255. C'est pourquoi chaque composante va de 0 à 255 : 256 valeurs sur un octet.
  2. 128128 est le poids du seul bit de gauche (10000000). Ici, les huit bits sont à 1 : 128 + 64 + … + 1.
  3. 155Huit bits à 1 donnent la plus grande valeur d'un octet : 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255.
  4. 256256 est le nombre de valeurs possibles, de 0 à 255. La plus grande est 255.

8. [Données] Le bit

QCU, une seule réponse · bonne réponse en B

Objectif : Connaître l'unité de base de l'information.

Quelle est la plus petite unité d'information, qui vaut 0 ou 1 ?

  1. L'octetUn octet regroupe 8 bits : ce n'est pas la plus petite unité.
  2. Juste · Le bitOui : un bit (de l'anglais binary digit, « chiffre binaire ») vaut 0 ou 1.
  3. Le hertzLe hertz mesure une fréquence (par exemple la vitesse d'un processeur), pas une quantité d'information.
  4. Le kilooctet (ko)Un kilooctet vaut 1 000 octets : c'est une grande unité.

9. [Données] L'octet

QCU, une seule réponse · bonne réponse en A

Objectif : Connaître la relation entre l'octet et le bit.

Quelle relation lie l'octet et le bit ?

  1. Juste · 1 octet = 8 bitsOui : un octet, c'est 8 bits. Il code 2⁸ = 256 valeurs, de 0 à 255 : exactement une composante R, V ou B.
  2. 1 octet = 4 bits4 bits forment un quartet, la moitié d'un octet.
  3. 1 octet = 10 bitsOn pense souvent à 10 comme en décimal, mais un octet regroupe 8 bits.
  4. 1 bit = 8 octetsC'est l'inverse : le bit est la plus petite unité, et l'octet en contient 8.

10. [Pixels] Un pixel en niveaux de gris

QCU, une seule réponse · bonne réponse en A

Objectif : Calculer la place d'un pixel en niveaux de gris.

Un pixel en niveaux de gris n'a qu'une composante, de 0 (noir) à 255 (blanc). Combien d'octets faut-il pour le coder ?

  1. Juste · 1 octetOui : 256 valeurs, de 0 à 255, tiennent dans un octet (8 bits). Un pixel en couleur RVB en demande 3.
  2. 2 octetsUn octet code déjà 256 valeurs, de 0 à 255 : c'est assez pour une seule composante.
  3. 3 octets3 octets, c'est un pixel en couleur : un pour R, un pour V, un pour B. En gris, il n'y a qu'une composante.
  4. 8 octetsTu confonds peut-être avec les 8 bits d'un octet. Une valeur de 0 à 255 tient dans 1 octet.

11. [Pixels] La taille d'une image sans compression

QCU, une seule réponse · bonne réponse en D

Objectif : Calculer la taille d'une image : définition × octets par pixel.

Une image de 1 000 × 500 pixels est codée en RVB, un octet par composante, sans compression. Quelle est sa taille ?

  1. 500 000 octetsC'est le nombre de pixels. Chaque pixel prend 3 octets (R, V, B) : il faut multiplier par 3.
  2. 3 octetsC'est la taille d'un seul pixel. L'image en a 1 000 × 500 = 500 000.
  3. 12 000 000 octetsTu as multiplié par 8 en plus : c'est le nombre de bits. 1 500 000 octets = 12 000 000 bits.
  4. Juste · 1 500 000 octetsOui : 1 000 × 500 = 500 000 pixels, × 3 octets = 1 500 000 octets, soit 1,5 Mo environ.

12. [Pixels] La profondeur de couleur

QCU, une seule réponse · bonne réponse en B

Objectif : Calculer le nombre de couleurs codées sur 24 bits.

Un pixel RVB est codé sur 24 bits : 8 bits par composante. Combien de couleurs différentes peut-il prendre ?

  1. 768Tu as additionné (256 × 3). Mais chaque valeur de R se combine avec chaque valeur de V et de B : on multiplie, 256 × 256 × 256.
  2. Juste · 16 777 216Oui : 256 × 256 × 256 = 2²⁴ = 16 777 216 couleurs, plus de 16 millions.
  3. 2424 est le nombre de bits. Avec 24 bits, on a 2²⁴ combinaisons possibles.
  4. 765765 = 255 × 3 : c'est la somme des trois valeurs maximales, pas le nombre de couleurs.

13. [Pixels] La résolution

QCU, une seule réponse · bonne réponse en B

Objectif : Comprendre la résolution d'une image imprimée, en pixels par pouce.

Une image est imprimée avec une résolution de 300 ppp (pixels par pouce ; un pouce mesure 2,54 cm). Que veut dire ce nombre ?

  1. L'image contient 300 pixels en toutLe nombre total de pixels, c'est la définition. La résolution les rapporte à une longueur.
  2. Juste · On aligne 300 pixels sur 2,54 cmOui : la résolution compte les pixels par unité de longueur. Plus elle est grande, plus l'image imprimée est fine.
  3. Chaque pixel peut prendre 300 couleursLe nombre de couleurs dépend de la profondeur de couleur (en bits), pas de la résolution.
  4. Le fichier pèse 300 octetsLa taille du fichier dépend de la définition et du codage, pas directement de la résolution.

14. [Traitement] Un pixel dans une grille

QCU, une seule réponse · bonne réponse en C

Objectif : Repérer un pixel par sa ligne et sa colonne, en comptant à partir de 0.

Une image est rangée dans une grille : grille[ligne][colonne], les indices commencent à 0. Quelle instruction colore en bleu pur le pixel de la 3ᵉ ligne et de la 10ᵉ colonne ?

  1. grille[3][10] = (255, 0, 0)Deux erreurs : (255, 0, 0) est le rouge, et les indices 3 et 10 visent la 4ᵉ ligne, 11ᵉ colonne.
  2. grille[3][10] = (0, 0, 255)La couleur est juste, mais les indices commencent à 0 : la 3ᵉ ligne est la ligne 2.
  3. Juste · grille[2][9] = (0, 0, 255)Oui : la 3ᵉ ligne a l'indice 2, la 10ᵉ colonne l'indice 9, et (0, 0, 255) est le bleu pur.
  4. grille[2][9] = (0, 255, 0)La position est juste, mais (0, 255, 0) est le vert : le bleu est la troisième composante.

15. [Traitement] Une boucle qui dessine

QCU, une seule réponse · bonne réponse en D

Objectif : Prévoir ce que dessine une boucle sur une grille de pixels.

Une image carrée de N × N pixels est rangée dans grille[ligne][colonne].

for i in range(N):
    grille[i][i] = (0, 0, 0)

Que dessine ce programme ?

  1. Une ligne horizontale noireUne ligne horizontale garde le même indice de ligne, par exemple grille[5][i]. Ici, la ligne change à chaque tour.
  2. Une colonne noireUne colonne garde le même indice de colonne, par exemple grille[i][5]. Ici, la colonne change aussi.
  3. Le bord de l'image en noirPour le bord, il faudrait noircir la première et la dernière ligne, et la première et la dernière colonne.
  4. Juste · Une diagonale noireOui : la ligne et la colonne valent toutes deux i : (0, 0), (1, 1), (2, 2)… On noircit la diagonale.

16. [Traitement] Le négatif d'un pixel

QCU, une seule réponse · bonne réponse en C

Objectif : Calculer le négatif d'un pixel : 255 moins chaque composante.

# un pixel orange, couleur de mangue
r, v, b = 200, 150, 0
r, v, b = 255 - r, 255 - v, 255 - b
print(r, v, b)

Qu'affiche ce programme ?

  1. -200 -150 0Le programme ne change pas seulement le signe : il calcule 255 moins chaque valeur.
  2. 0 150 200Le négatif n'inverse pas l'ordre des composantes : il calcule 255 - r, 255 - v, 255 - b.
  3. Juste · 55 105 255Oui : 255 - 200 = 55, 255 - 150 = 105, 255 - 0 = 255. L'orange devient un bleu : c'est le négatif.
  4. 55 105 0Attention à la dernière composante : 255 - 0 vaut 255, pas 0.

r, v, b = 90, 180, 30
gris = (r + v + b) // 3
print(gris)

Qu'affiche ce programme ?

  1. 300300 est la somme. Le programme la divise ensuite par 3 : c'est une moyenne.
  2. Juste · 100Oui : (90 + 180 + 30) // 3 = 300 // 3 = 100. Le pixel devient (100, 100, 100), un gris.
  3. 180Le programme ne garde pas la plus grande composante : il fait la moyenne des trois.
  4. 90Le programme ne garde pas la première composante : il calcule la moyenne des trois.

18. [Traitement] Éclaircir sans dépasser 255

QCU, une seule réponse · bonne réponse en B

Objectif : Éclaircir une composante en la gardant entre 0 et 255.

r = 230
r = min(255, r + 50)
print(r)

Qu'affiche ce programme ?

  1. 280230 + 50 = 280, mais min(255, 280) garde la plus petite des deux valeurs : 255. Une composante ne dépasse jamais 255.
  2. Juste · 255Oui : min garde la plus petite valeur entre 255 et 280. La composante reste dans les limites, 0 à 255.
  3. 230La ligne 2 change r : r + 50 donne 280, et min le ramène à 255.
  4. 50min compare 255 et r + 50, soit 280 : il ne renvoie pas 50.

19. [Erreurs] Modifier un pixel rangé dans un tuple

QCU, une seule réponse · bonne réponse en A

Objectif : Lire une TypeError : un tuple ne se modifie pas.

Le programme suivant est exécuté. Python s'arrête sur l'erreur affichée dans la console.

pixel = (255, 0, 0)
pixel[0] = 0

Console :

TypeError: 'tuple' object does not support item assignment

Quelle correction permet d'obtenir un pixel noir ?

  1. Juste · Créer un nouveau triplet : pixel = (0, 0, 0)Oui. Le message dit « un tuple ne permet pas de modifier un élément ». On range un nouveau triplet dans la variable.
  2. Écrire pixel(0) = 0Les parenthèses servent à appeler une fonction : Python affiche une SyntaxError. Le problème est le tuple.
  3. Écrire pixel[0] == 0Il n'y a plus d'erreur, mais == compare sans rien changer : le pixel reste (255, 0, 0).
  4. Écrire pixel[1] = 0On ne peut modifier aucun élément d'un tuple : Python afficherait la même erreur.
