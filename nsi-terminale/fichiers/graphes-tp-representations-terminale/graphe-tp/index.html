Objectif : représenter un même graphe de trois façons en Python : une liste d'arêtes, un dictionnaire d'adjacence, puis une classe.

Je sais :

  • écrire un graphe comme une liste d'arêtes (des tuples) ;
  • lire les voisins d'un sommet dans un dictionnaire d'adjacence ;
  • ajouter une arête dans les deux sens pour un graphe non orienté ;
  • dire quelle représentation est la plus rapide pour trouver des voisins.

1 heure · 3 questions et 2 bonus ★ · sur ordinateur, seul·e ou en binôme

Ce TP te fait manipuler les différentes manières de représenter un graphe en Python : les tuples pour les arêtes, le dictionnaire d'adjacence (des listes de voisins), puis la programmation orientée objet (POO).

On représente toujours le même graphe : sommets A, B, C, D ; arêtes A-B, A-C, B-C, C-D.

1. Liste d'arêtes (tuples)

C'est la méthode la plus simple : on stocke le graphe comme une liste de couples (des tuples).

Mission : complète le code pour ajouter l'arête manquante, C-D.

# Représentation par liste d'arêtes
graph_edges = [
    ('A', 'B'),
    ('A', 'C'),
    ('B', 'C'),
    [[('C', 'D')|('D', 'C')]],
]

def afficher_aretes(graphe):
    for u, v in graphe:
        print(f"Lien entre {u} et {v}")

afficher_aretes(graph_edges)
Lien entre A et B
Lien entre A et C
Lien entre B et C
Lien entre C et D

Chaque arête s'écrit comme les autres : un tuple de deux sommets, entre parenthèses.

    ('C', 'D'),

Dans un graphe non orienté, ('D', 'C') représente la même arête (l'affichage dit alors « Lien entre D et C »).

2. Dictionnaire d'adjacence (listes)

Cette méthode est plus efficace pour savoir rapidement quels sont les voisins d'un sommet. On utilise un dictionnaire : chaque clé est un sommet, et chaque valeur est la liste de ses voisins.

graph_adj = {
    'A': ['B', 'C'],
    'B': ['A', 'C'],
    'C': ['A', 'B', 'D'],
    'D': ['C']
}

graph_adj = {'A': ['B', 'C'], 'B': ['A', 'C'], 'C': ['A', 'B', 'D'], 'D': ['C']}

def compte_voisins(graphe, sommet):
    return len(graphe[sommet])

print(f"Voisins de C : {compte_voisins(graph_adj, 'C')}")

Un seul accès au dictionnaire, puis la longueur de la liste : c'est immédiat, quel que soit le nombre de sommets.

3. L'approche POO (classes)

En POO, on crée une classe Graphe qui regroupe les données et les comportements (ajouter un sommet, ajouter une arête).

Mission : complète la méthode ajouter_arete. N'oublie pas : dans un graphe non orienté, si A est relié à B, alors B est aussi relié à A.

class Graphe:
    def __init__(self):
        self.adjacence = {}

    def ajouter_sommet(self, sommet):
        if sommet not in self.adjacence:
            self.adjacence[sommet] = []

    def ajouter_arete(self, u, v):
        # 1. S'assurer que les sommets existent
        self.ajouter_sommet(u)
        self.ajouter_sommet(v)
        # 2. Ajouter le lien dans les deux sens
        [[self.adjacence[u].append(v)|self.adjacence[v].append(u)]]
        [[self.adjacence[v].append(u)|self.adjacence[u].append(v)]]

    def afficher(self):
        for sommet, voisins in self.adjacence.items():
            print(f"{sommet} -> {', '.join(voisins)}")

# --- Test du TP ---
mon_graphe = Graphe()
mon_graphe.ajouter_arete('A', 'B')
mon_graphe.ajouter_arete('A', 'C')
mon_graphe.ajouter_arete('B', 'C')
mon_graphe.ajouter_arete('C', 'D')
mon_graphe.afficher()
A -> B, C
B -> A, C
C -> A, B, D
D -> C

self.adjacence[u] est la liste des voisins de u ; .append(v) y ajoute v.

Il faut deux lignes : v dans les voisins de u, et u dans les voisins de v.

        self.adjacence[u].append(v)
        self.adjacence[v].append(u)

Le programme affiche alors A -> B, C, B -> A, C, C -> A, B, D et D -> C. Avec une seule ligne, D n'aurait aucun voisin.

Pour aller plus loin

Complexité. Pourquoi la représentation de l'exercice 2 est-elle plus rapide que celle de l'exercice 1 pour savoir si D est voisin de A ?

  • Avec le dictionnaire, on regarde seulement la liste des voisins de A ; avec la liste d'arêtes, il faut parcourir toutes les arêtes.
  • Parce que le dictionnaire contient moins d'arêtes.
  • Parce que les tuples sont plus lents à lire que les listes.
  • Parce que le dictionnaire est trié par ordre alphabétique.

Combien d'éléments faut-il regarder dans chaque cas, si le graphe a des milliers d'arêtes ?

graph_adj['A'] donne directement les voisins de A : on ne regarde que eux. Avec la liste d'arêtes, il faut, dans le pire des cas, examiner chaque arête. Mesuré sur 200 001 arêtes : environ 0,1 s pour la liste, quelques microsecondes pour le dictionnaire.

Complexité. Pourquoi la représentation de l'exercice 2 est-elle plus rapide que celle de l'exercice 1 pour vérifier si D est voisin de A ?

Avec le dictionnaire, on lit directement la liste des voisins de A (graph_adj['A']), qui est courte. Avec la liste d'arêtes, il faut parcourir toutes les arêtes du graphe.

Pondération. Comment modifier les tuples de l'exercice 1 pour ajouter un « poids » (une distance en km) à chaque route ?

  • Ajouter un troisième élément : ('A', 'B', 5).
  • Faire une deuxième liste avec les distances.
  • Écrire ('A5', 'B').
  • C'est impossible avec des tuples.

Un tuple peut contenir plus de deux valeurs.

On écrit des triplets (u, v, poids), par exemple ('A', 'B', 5), et on les lit avec for u, v, poids in graphe:.

Pondération. Comment modifierais-tu les tuples de l'exercice 1 pour ajouter un « poids » (une distance) à chaque route ?

On ajoute un troisième élément à chaque tuple : ('A', 'B', 5), lu avec for u, v, poids in graphe:.

Mémo

Liste d'arêtes : simple, mais il faut tout parcourir. Dictionnaire d'adjacence : les voisins d'un sommet en un accès.

Graphe non orienté : chaque arête s'ajoute dans les deux sens.
