Exercice 2 (4 points) : le tourniquet en Python

Sujet du bac 2023, Polynésie, jour 1 (23-NSIJ1PO1), exercice 2, 4 points. Le sujet d'origine (PDF).

Cet exercice porte sur la gestion des processus et la programmation orientée objet.

On rappelle qu'un processus est l'instance d'un programme en cours d'exécution. Il est identifié par un numéro unique appelé PID. L'ordonnanceur est la composante du système d'exploitation qui gère l'allocation du processeur entre les différents processus. Nous allons nous intéresser à l'algorithme d'ordonnancement du tourniquet dont le fonctionnement est résumé ci-dessous :

  • les processus prêts à être exécutés sont placés dans une file d'attente selon leur ordre d'arrivée ;
  • l'ordonnanceur alloue le processeur à chaque processus de la file d'attente un même nombre de cycles CPU, appelé quantum ;
  • si le processus n'est pas terminé au bout de ce temps, son exécution est suspendue et il est mis à la fin de la file d'attente ;
  • si le processus est terminé, il sort définitivement de la file d'attente.

2. c) La fonction tourniquet ci-dessous implémente l'algorithme décrit dans l'exercice. Elle prend en paramètre une liste d'objets Processus donnés par ordre d'arrivée et un nombre entier positif correspondant au quantum. La fonction renvoie la liste des PID dans l'ordre de leur exécution par le processeur. Recopier et compléter sur la copie le code manquant.

def tourniquet(liste_attente, quantum):
    ordre_execution = []
    while liste_attente != []:
        # On extrait le premier processus
        processus = liste_attente.pop(0)
        processus.change_etat("En cours d'exécution")
        compteur_tourniquet = 0
        while [[not processus.est_termine()|processus.reste_a_faire > 0|processus.reste_a_faire != 0|compteur_tourniquet < quantum]] and [[compteur_tourniquet < quantum|not processus.est_termine()|processus.reste_a_faire > 0|processus.reste_a_faire != 0]]:
            ordre_execution.append([[processus.pid]])
            processus.execute_un_cycle()
            compteur_tourniquet = compteur_tourniquet + 1
        if [[not processus.est_termine()|processus.reste_a_faire > 0|processus.reste_a_faire != 0]]:
            processus.change_etat("Suspendu")
            liste_attente.append(processus)
        else:
            processus.change_etat([["Terminé"]])
    return ordre_execution

La boucle intérieure tourne tant que le processus n'a pas fini et que son quantum n'est pas épuisé.

Après la boucle : s'il n'a pas fini, il retourne au bout de la file ; sinon, il passe à l'état « Terminé ».

            ordre_execution.append(processus.pid)
            ...
        if not processus.est_termine():
            ...
        else:
            processus.change_etat("Terminé")

Suis la figure 1 : à chaque fois qu'un processus est élu, il fait l'instruction suivante de sa colonne. Note qui détient le fichier et le clavier.

Cycle 0 : D acquiert le fichier. Cycle 2 : B acquiert le clavier. Que se passe-t-il au cycle 3 pour D, puis au cycle 5 pour B ?

D acquiert le fichier (cycle 0) et calcule (cycle 1). B acquiert le clavier (cycle 2). Au cycle 3, D demande le clavier, détenu par B : D est bloqué. Au cycle 5, B demande le fichier, détenu par D : B est bloqué. B et D s'attendent mutuellement : chacun détient la ressource dont l'autre a besoin et ne la libérera jamais. C'est un interblocage. Mots attendus : détient, attend, bloqué, attente circulaire.

Mémo

Processus : un programme en cours d'exécution, avec un PID. États : prêt, élu, bloqué. ps les liste, kill en arrête un.

Ordonnancement : par priorité, le plus prioritaire s'exécute (et peut en suspendre un autre) ; par tourniquet, chacun son tour pendant un quantum, puis retour au bout de la file. Fais toujours un tableau : cycle, file, élu.

Interblocage : une attente en cercle. X détient R1 et attend R2, Y détient R2 et attend R1. Pour l'éviter : demander les ressources toujours dans le même ordre.
