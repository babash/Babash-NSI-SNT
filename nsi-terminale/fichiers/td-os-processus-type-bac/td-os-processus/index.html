1. L'arborescence et les droits d'accès

Voici l'arborescence des fichiers d'un serveur. Les flèches vont du répertoire parent vers ses éléments fils. (D) : dossier ; (F) : fichier.

Un utilisateur est connecté en tant qu'eleve. Son répertoire personnel est /home/eleve. Il se trouve dans le dossier nsi.

Donne le chemin absolu du répertoire nsi.

Un chemin absolu part de la racine : il commence par /.

~ est un raccourci du répertoire personnel : le chemin absolu l'écrit en entier, depuis /.

Pars de la racine / et descends l'arbre jusqu'à nsi, en séparant les noms par /.

/home/eleve/devoirs/nsi : on part de la racine, puis home, eleve, devoirs et enfin nsi.

L'utilisateur veut copier le fichier notes.csv (chez prof) dans son dossier projets. Écris la commande, avec uniquement des chemins relatifs.

Ces deux chemins sont absolus (ils commencent par /). La consigne demande des chemins relatifs, à partir de nsi.

Depuis nsi, ../.. mène à /home/eleve. Pour atteindre prof, il faut remonter d'un cran de plus.

cp source destination. Depuis nsi, .. mène à devoirs, ../.. à eleve, ../../.. à home.

cp ../../../prof/notes.csv ../../projets : trois remontées pour arriver dans home, puis prof/notes.csv ; deux remontées pour arriver dans eleve, puis projets.

Tu es toujours dans le dossier nsi. Donne la commande (ou la suite de commandes, sur une ligne) qui crée avec touch un fichier exam1.txt dans le dossier examens.

Cette commande crée exam1.txt là où tu es, dans nsi : il faut donner le chemin du dossier examens.

examens est dans prof, lui-même dans home : depuis nsi, il faut remonter jusqu'à home.

Deux commandes sur une ligne se séparent par ; ou &&.

touch ../../../prof/examens/exam1.txt, ou bien cd ../../../prof/examens puis touch exam1.txt. Le chemin absolu /home/prof/examens/exam1.txt marche aussi.

Tu te déplaces dans l'arborescence, puis tu tapes la commande ci-dessous. Qu'affiche le terminal ?

eleve@serveur:~/devoirs/nsi$ ls ../..

ls .. afficherait le contenu de devoirs. Ici, on remonte de deux crans.

L'invite ~/devoirs/nsi dit où tu es. ../.. remonte de deux crans.

ls affiche le contenu du dossier, pas son nom.

../.. depuis ~/devoirs/nsi, c'est ~, soit /home/eleve. Le terminal affiche son contenu : devoirs projets.

L'administrateur·rice tape ces commandes à partir de /home/eleve. Qu'affiche la dernière ?

$ mkdir archives
$ cd devoirs
$ mv nsi ../archives/
$ ls ../archives

ls affiche le contenu du dossier archives, pas son nom.

mv déplace nsi dans archives, qui était vide.

On crée archives (vide), on entre dans devoirs, on y prend nsi pour le mettre dans ../archives. Le dossier archives contient alors seulement nsi.

L'utilisateur tape ls -l dans le répertoire /home/prof et obtient :

-rwxrw-r-- 1 prof  enseignants  2048 Mar 24 10:00 notes.csv

L'utilisateur eleve (qui n'est pas dans le groupe enseignants) peut-il modifier ce fichier ? Peut-il l'exécuter ?

  • Oui aux deux : le fichier a les droits rwx.
  • Il peut le modifier (w), mais pas l'exécuter.
  • Non aux deux : pour les autres, les droits sont r--, lecture seule.
  • Non : il ne peut même pas le lire.

Après le premier caractère (- : un fichier), les droits vont par trois : propriétaire, groupe, autres.

eleve n'est ni le propriétaire (prof) ni dans le groupe : ce sont les trois derniers caractères.

rwx pour prof, rw- pour le groupe enseignants, r-- pour les autres. eleve fait partie des autres : il peut lire le fichier, mais ni le modifier (pas de w) ni l'exécuter (pas de x).

L'utilisateur eleve (qui n'est pas dans le groupe enseignants) peut-il modifier ce fichier ? Peut-il l'exécuter ? Justifie.

Non aux deux. Les droits se lisent par trois : rwx pour le propriétaire prof, rw- pour le groupe enseignants, r-- pour les autres. eleve fait partie des autres : lecture seule, ni w ni x.

Donne la commande chmod, en notation octale, qui rend ce fichier lisible et modifiable par tout le monde, mais exécutable par personne.

777 donne aussi le droit d'exécution (x = 1) à tout le monde.

C'est juste, mais en notation symbolique. La consigne demande la notation octale (des chiffres).

r = 4, w = 2, x = 1 : on additionne les droits voulus, pour chacun des trois groupes.

Lecture + écriture = 4 + 2 = 6, pour le propriétaire, le groupe et les autres : chmod 666 notes.csv. ls -l affiche alors -rw-rw-rw-.

L'administrateur·rice veut donner la propriété de ce fichier à un autre utilisateur, directeur. Il ou elle tape :

$ sudo chown directeur notes.csv

Quel est le rôle de cette commande, et que signifie le préfixe sudo ?

  • chown fait de directeur le propriétaire du fichier ; sudo lance la commande avec les droits du super-utilisateur (root).
  • La commande donne tous les droits à directeur ; sudo veut dire « super-dossier ».
  • La commande déplace notes.csv chez directeur ; sudo confirme le déplacement.
  • La commande connecte la session en tant que directeur ; sudo demande son mot de passe.

chown : change owner, changer le propriétaire.

Un utilisateur ordinaire ne peut pas donner son fichier à un autre : il faut les droits de l'administrateur.

chown directeur notes.csv fait de directeur le nouveau propriétaire du fichier. Seul le super-utilisateur root peut le faire : sudo (super user do) exécute la commande avec ses droits, après avoir demandé le mot de passe de l'administrateur·rice.

Explique le rôle de cette commande et la signification du préfixe sudo.

chown (change owner) fait de directeur le propriétaire de notes.csv. sudo (super user do) lance la commande avec les droits du super-utilisateur root, seul autorisé à changer le propriétaire d'un fichier.

2. Processus et flux de données

L'administrateur·rice surveille l'activité du serveur avec la commande ps -ef. En voici un extrait :

UID     PID   PPID  C  CMD
root    1     0     0  /sbin/init
root    500   1     0  /usr/sbin/sshd
eleve   1050  500   0  -bash
eleve   1210  1050  99 python3 calcul_pi.py
eleve   1215  1050  0  ps -ef

Quel est le PID du processus parent de python3 ?

1210 est le PID de python3 lui-même. Son parent est dans la colonne PPID.

PPID : Parent Process ID, l'identifiant du processus parent.

Sur la ligne de python3, la colonne PPID vaut 1050 : c'est le shell bash qui l'a lancé.

Quel graphe de parenté (l'arbre des processus) correspond à cet extrait ? Une flèche va du parent vers l'enfant.

  • 1 → 500 → 1050 → 1210 → 1215
  • 1 → 500 → 1050, puis 1050 → 1210 et 1050 → 1215
  • 1 → 500, 1 → 1050, 1 → 1210 et 1 → 1215
  • 1215 → 1050, 1210 → 1050, 1050 → 500 → 1

Pour chaque ligne, trace une flèche de PPID vers PID.

init (PID 1) a lancé sshd, qui a lancé le bash de la connexion ; ce bash a deux enfants, python3 et ps.

Dessine le graphe de parenté (l'arbre des processus) de cet extrait.

Une flèche de chaque PPID vers son PID : 1 → 500 → 1050, puis 1050 → 1210 et 1050 → 1215. init est la racine ; bash a deux enfants, python3 et ps.

Un processus « orphelin » est un processus dont le parent est terminé. Si l'on tue le processus bash (PID 1050), quel processus devient le nouveau parent du processus 1210 ? Donne son PID ou son nom.

sshd est le grand-parent, mais le système ne rattache pas un orphelin à son grand-parent.

Un orphelin est « adopté » par l'ancêtre de tous les processus.

Le processus 1210 est adopté par init, le processus de PID 1, l'ancêtre de tous les processus (sur beaucoup de systèmes Linux récents, il s'appelle systemd).

On considère la commande ps -ef | grep "python3".

Quel est le rôle du symbole | ?

  • Il lance les deux commandes l'une après l'autre, sans lien entre elles.
  • Il enregistre le résultat de ps -ef dans un fichier nommé grep.
  • Il envoie la sortie de ps -ef à l'entrée de grep : c'est un tube.
  • Il lance ps -ef ou bien grep, selon celle qui marche.

Le symbole s'appelle un tube (pipe).

Le tube | branche la sortie de la commande de gauche sur l'entrée de la commande de droite : grep ne lit pas un fichier, mais le résultat de ps -ef, et n'en garde que les lignes qui contiennent python3.

Explique le rôle du symbole |.

Le tube | envoie la sortie de la commande de gauche (ps -ef) à l'entrée de la commande de droite (grep), qui ne garde que les lignes contenant python3.

D'après le tableau, quelles lignes cette commande affiche-t-elle ? Coche toutes celles qui peuvent apparaître.

grep "python3" garde chaque ligne qui contient le texte python3, n'importe où.

Pendant que ps photographie les processus, grep tourne déjà : il fait partie de la liste.

La ligne eleve 1210 1050 99 python3 calcul_pi.py s'affiche. En pratique, une deuxième ligne apparaît aussi : celle de la commande grep python3, lancée en même temps que ps et qui contient le mot cherché (essai réel dans source/verifier.py).

3. Réseaux et connectivité

Pour vérifier la connexion avec un serveur distant, l'utilisateur tape ping -c 3 8.8.8.8. Le terminal affiche :

64 bytes from 8.8.8.8: icmp_seq=1 ttl=115 time=12.4 ms
64 bytes from 8.8.8.8: icmp_seq=2 ttl=115 time=13.1 ms
64 bytes from 8.8.8.8: icmp_seq=3 ttl=115 time=12.8 ms
--- 8.8.8.8 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2003ms

Quel est le rôle de la commande ping ?

  • Télécharger un fichier depuis le serveur.
  • Tester si une machine répond sur le réseau, et mesurer le temps d'aller-retour.
  • Donner l'adresse IP de son propre ordinateur.
  • Afficher la liste des routeurs traversés.

Chaque ligne 64 bytes from… est une réponse du serveur, avec un temps.

ping envoie des paquets de test (ICMP) à une machine et attend ses réponses : il dit si elle est joignable et mesure le temps d'aller-retour. -c 3 : trois paquets.

Quel est le rôle de la commande ping ?

ping envoie des paquets de test à une machine et attend ses réponses : il vérifie qu'elle est joignable et mesure le temps d'aller-retour.

Que peux-tu conclure sur la connexion entre l'ordinateur et le serveur 8.8.8.8 ?

  • Elle fonctionne bien : 3 paquets envoyés, 3 reçus (0 % de perte), en 13 ms environ.
  • Elle ne fonctionne pas : 0 % des paquets sont passés.
  • Elle est très lente : plus de 2 secondes par paquet.
  • Tous les serveurs d'internet sont joignables.

Lis la dernière ligne : envoyés, reçus, perte.

Les 3 paquets envoyés ont reçu une réponse (0 % de perte), avec un temps d'aller-retour d'environ 12 à 13 ms : la connexion avec ce serveur fonctionne, et elle est rapide.

Que peux-tu conclure sur l'état de la connexion entre l'ordinateur et le serveur 8.8.8.8 ?

La connexion fonctionne : 3 paquets envoyés, 3 reçus, 0 % de perte, et un aller-retour rapide (environ 13 ms).

4. Programmation Python et système

Dominique veut automatiser le nettoyage du serveur. Elle dispose d'une liste de processus, représentés par des dictionnaires :

processus_actifs = [
    {"pid": 1210, "nom": "python3",
        "cpu": 99.8, "user": "eleve"},
    {"pid": 1340, "nom": "firefox",
        "cpu": 12.5, "user": "eleve"},
    {"pid": 1450, "nom": "bash",
        "cpu": 0.1, "user": "root"}
]

Écris une fonction trouver_critiques(liste_proc) qui renvoie la liste des PID des processus dont la consommation CPU est supérieure à 80 %. Des tests, cachés, la vérifient quand tu cliques sur « Lancer et vérifier ».

def trouver_critiques(liste_proc):
    ...

On part d'une liste vide, on parcourt liste_proc, et on ajoute le PID quand c'est critique.

Pour un processus p : sa consommation est p["cpu"], son PID p["pid"].

def trouver_critiques(liste_proc):
    critiques = []
    for p in liste_proc:
        if p["cpu"] > 80:
            critiques.append(p["pid"])
    return critiques

Avec la liste de Dominique, la fonction renvoie [1210]. On peut aussi écrire une liste en compréhension : [p["pid"] for p in liste_proc if p["cpu"] > 80].

Dominique veut filtrer les processus par utilisateur. Complète la fonction.

def filtrer_par_user(liste_proc, nom_user):
    resultat = []
    for p in liste_proc:
        if p["user"] == [[nom_user]]:
            resultat.append([[p]])
    return resultat

On compare l'utilisateur de chaque processus au paramètre reçu par la fonction.

On veut garder les processus eux-mêmes (les dictionnaires), pas seulement leur PID.

def filtrer_par_user(liste_proc, nom_user):
    resultat = []
    for p in liste_proc:
        if p["user"] == nom_user:
            resultat.append(p)
    return resultat

filtrer_par_user(processus_actifs, "root") renvoie [{'pid': 1450, 'nom': 'bash', 'cpu': 0.1, 'user': 'root'}].

Mémo

Chemin absolu : depuis / ; relatif : depuis le dossier courant (.. = le parent). Droits : propriétaire, groupe, autres ; r = 4, w = 2, x = 1.

Chaque processus a un PID et un parent (PPID) ; un orphelin est adopté par init (PID 1). Le tube | envoie la sortie d'une commande à la suivante.
