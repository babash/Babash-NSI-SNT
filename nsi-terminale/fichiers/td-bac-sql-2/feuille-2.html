Exercice 2 · Louer du matériel entre membres

Source : Bac NSI, Polynésie, mars 2023, jour 2 (sujet 23-NSIJ2PO1), exercice 2, 4 points. Le sujet d'origine (PDF). Plus proche de l'épreuve : des requêtes à écrire en entier, deux jointures, une suppression.

Cet exercice traite du thème base de données, et principalement du modèle relationnel et du langage SQL.

L'énoncé de cet exercice peut utiliser les mots du langage SQL suivants : SELECT, FROM, WHERE, JOIN ON, INSERT INTO, VALUES, UPDATE, SET, DELETE, COUNT, AND, OR

Un site permet à ses membres de proposer à la location du matériel et de louer du matériel. Ceci permet de mutualiser du matériel entre membres et au propriétaire de rentabiliser cet achat. Le temps d'utilisation du matériel s'en trouve ainsi augmenté et le nombre d'appareils diminué.

Le modèle relationnel est donné par le schéma ci-dessous.

La table Membre contient les informations de chaque utilisateur du site (nom, prénom et code postal). La table Objet décrit le type d'objet à la location ainsi que son tarif de location journalier. La table Reservation répertorie toutes les réservation effectuées par les membres du site avec notamment leur date de début et de fin de location. La table Possede permet de lier les tables Membre et Objet.

1. Dans cette partie, on ne demande pas de requête SQL. En étudiant le contenu des tables ci-dessus :

a) Indiquer quels sont les prénoms et noms du ou des membres du site qui proposent la location d'un appareil à raclette ;

  • Mohamed Ali
  • Fernando Alonso
  • Antoine Dupont
  • Pauline Ferrand
  • Harry Kane

L'appareil à raclette est l'objet 4. Dans Possede, quels membres ont l'objet 4 ?

Dans Possede, l'objet 4 est associé aux membres 1 et 2 : Mohamed Ali et Fernando Alonso. Harry Kane a réservé un appareil à raclette, il ne le propose pas.

1. b) Donner le prénom et le nom du membre qui ne propose pas d'objet à la location.

  • Mohamed Ali
  • Antoine Dupont
  • Pauline Ferrand
  • Harry Kane

Cherche le numéro de membre qui n'apparaît jamais dans la table Possede.

Le membre 5, Harry Kane, n'apparaît pas dans Possede.

2. a) Donner le résultat de la requête suivante :

SELECT nom, prenom FROM Membre WHERE cp = "69003" ;

Écris le résultat sur ta feuille, puis coche les lignes qui y figurent.

  • Ali | Mohamed
  • Alonso | Fernando
  • Dupont | Antoine
  • Ferrand | Pauline
  • Kane | Harry

Deux membres ont le code postal 69003.

2. b) Écrire une requête permettant de connaître le tarif de location d'une scie circulaire.

Le tarif et la description sont dans la même table : pas besoin de jointure.

SELECT tarif FROM Objet WHERE description = 'Scie circulaire';

Résultat calculé par SQLite :

tarif
15

2. c) Écrire une requête permettant de modifier le tarif de location d'un nettoyeur à haute pression pour le passer à 15 € par jour au lieu de 20 € par jour.

Sans WHERE, tous les objets passent à 15 € ! Ajoute la condition qui désigne le nettoyeur.

UPDATE Objet SET … WHERE …; La description s'écrit exactement comme dans la table.

UPDATE Objet SET tarif = 15 WHERE description = 'Nettoyeur haute pression';

ou WHERE id_objet = 1. Attention : la table écrit « Nettoyeur haute pression », sans « à ».

2. d) Écrire une requête SQL permettant d'ajouter Wendie Renard habitant à Villeurbanne (code postal 69100) dans la table Membre, avec un id_membre de 6.

Les valeurs dans l'ordre des colonnes : id_membre, nom, prenom, cp. La ville n'est pas dans la table.

INSERT INTO Membre VALUES (6, 'Renard', 'Wendie', '69100');

Le code postal est du texte dans la table (TEXT) : '69100'.

3. a) Expliquer la limitation importante d'utilisation du service offert par le site si l'on utilisait le couple de clés étrangères (id_objet, id_membre) en tant que clé primaire de la relation Reservation.

Explique sur ta feuille, puis choisis.

  • Un objet ne pourrait être réservé que par un seul membre.
  • Un membre ne pourrait réserver qu'une seule fois un même objet.
  • Un membre ne pourrait réserver qu'un seul objet en tout.
  • Deux réservations ne pourraient pas commencer le même jour.

Regarde les réservations 3 et 4 : même objet, même membre.

Une clé primaire est unique : un même couple (objet, membre) ne pourrait apparaître qu'une fois. Mohamed Ali n'aurait pas pu réserver deux fois la perforatrice (réservations 3 et 4).

3. b) Mohamed Ali décide de ne plus être membre du site. Il faut donc le supprimer de la table Membre à l'aide de la requête :

DELETE FROM Membre
WHERE nom = "Ali" AND prenom = "Mohamed" ;

Expliquer pourquoi cette requête produit une erreur.

Le message de SQLite (vérification des clés étrangères activée) :

Runtime error: FOREIGN KEY constraint failed (19)

Explique sur ta feuille, puis choisis.

  • Il faut écrire les chaînes entre apostrophes.
  • Son id_membre (1) est utilisé comme clé étrangère dans Possede et Reservation : ces lignes feraient référence à un membre qui n'existe plus.
  • Il faut supprimer avec la clé primaire : WHERE id_membre = 1.
  • On ne peut jamais supprimer une ligne d'une table qui a une clé primaire.

FOREIGN KEY constraint failed : « la contrainte de clé étrangère n'est pas respectée ». Où le membre 1 apparaît-il encore ?

Le membre 1 apparaît dans Possede (objets 4 et 6) et dans Reservation (réservations 3 et 4). Le supprimer laisserait des clés étrangères qui ne font référence à rien : le SGBD refuse (contrainte d'intégrité référentielle).

3. c) Proposer une suite de requêtes utilisant le mot clé DELETE, précédant la requête ci-dessus pour supprimer correctement Mohamed Ali, dont l'id_membre est 1, de la base de donnée.

Rappel : la relation Objet décrit le type d'objet à la location. Il n'y a pas d'objet à supprimer dans cette table lors du départ d'un membre.

Écris les requêtes à la suite, sur une ligne, séparées par un point-virgule.

Deux tables font référence au membre 1. Une requête DELETE par table.

Forme : DELETE FROM … WHERE id_membre = 1;

DELETE FROM Possede WHERE id_membre = 1;
DELETE FROM Reservation WHERE id_membre = 1;

Ces deux requêtes, dans un ordre ou dans l'autre. Ensuite, la requête de la question 3. b passe : SQLite supprime Mohamed Ali.

4. Dans cette partie, les requêtes utilisent des jointures entre tables. On supposera donc les numéros id_membre et id_objet non connus.

a) Écrire une requête permettant de compter le nombre de réservations réalisées par Fernando Alonso.

Les réservations sont dans Reservation, le nom dans Membre : jointure sur id_membre.

Pour compter : SELECT COUNT(*) FROM …

SELECT COUNT(*) FROM Reservation
JOIN Membre ON Reservation.id_membre = Membre.id_membre
WHERE Membre.nom = 'Alonso' AND Membre.prenom = 'Fernando';

Résultat calculé par SQLite :

COUNT(*)
3

4. b) Écrire une requête permettant de connaître les noms et prénoms des membres possédant un appareil à raclette.

Sans conditions ON, chaque membre est associé à chaque ligne de Possede : SQLite renvoie tous les membres, plusieurs fois. Chaque JOIN a besoin de son ON.

Trois tables : Membre (le nom), Possede (le lien), Objet (la description). Il faut deux jointures.

Forme : SELECT … FROM Membre JOIN Possede ON … JOIN Objet ON … WHERE …;

SELECT nom, prenom FROM Membre
JOIN Possede ON Membre.id_membre = Possede.id_membre
JOIN Objet ON Possede.id_objet = Objet.id_objet
WHERE description = 'Appareil à raclette';

Résultat calculé par SQLite :

nomprenom
AliMohamed
AlonsoFernando

Mémo

Jointure : FROM A JOIN B ON A.cle_etrangere = B.cle_primaire. Sans ON, chaque ligne de A est associée à chaque ligne de B.

INSERT INTO table VALUES (…); · UPDATE table SET colonne = valeur WHERE …; · DELETE FROM table WHERE …; Sans WHERE, toutes les lignes sont modifiées ou supprimées.

Contraintes : clé primaire déjà prise, UNIQUE constraint failed ; clé étrangère sans ligne correspondante, FOREIGN KEY constraint failed. On ajoute d'abord la ligne référencée ; on supprime d'abord les lignes qui y font référence.
