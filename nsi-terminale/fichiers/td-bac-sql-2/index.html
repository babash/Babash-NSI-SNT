Exercice 1 · Une base de données sur le cinéma

Source : Bac NSI, Métropole, mai 2022, jour 1 (sujet 22-NSIJ1ME1), exercice 2, 4 points. Le sujet d'origine (PDF). Le plus guidé : des requêtes à compléter.

Cet exercice porte sur les bases de données.

On pourra utiliser les mots clés SQL suivants : SELECT, FROM, WHERE, JOIN, ON, INSERT, INTO, VALUES, UPDATE, SET, AND.

Nous allons étudier une base de données traitant du cinéma dont voici le schéma relationnel qui comporte 3 relations :

  • la relation individu (id_ind, nom, prenom, naissance)
  • la relation realisation (id_rea, titre, annee, type)
  • la relation emploi (id_emp, description, #id_ind, #id_rea)

Les clés primaires sont soulignées et les clés étrangères sont précédées d'un #. Ainsi emploi.id_ind est une clé étrangère faisant référence à individu.id_ind.

1. On s'intéresse ici à la récupération de données dans une relation.

a. Écrire ce que renvoie la requête ci-dessous :

SELECT nom, prenom, naissance
FROM individu
WHERE nom = 'Crog';

Sur l'extrait, une seule personne s'appelle Crog. On affiche trois colonnes, dans l'ordre du SELECT.

Sur l'extrait donné, une seule ligne (résultat calculé par SQLite) :

nomprenomnaissance
CrogDaniel07-07-1968

Le sujet ne donne qu'un extrait : dans la table complète, il pourrait y avoir d'autres Crog.

1. b. Fournir une requête SQL permettant de récupérer le titre et la clé primaire de chaque film dont la date de sortie est strictement supérieure à 2020.

La clé primaire de realisation est soulignée dans le schéma. La date de sortie, c'est l'attribut annee.

SELECT titre, id_rea FROM realisation WHERE annee > 2020;

Résultat calculé par SQLite sur l'extrait :

titreid_rea
Mourir pour attendre950

2. Cette question traite de la modification de relations.

a. Dire s'il faut utiliser la requête 1 ou la requête 2 proposées ci-dessous pour modifier la date de naissance de Daniel Crog. Justifier votre réponse en expliquant pourquoi la requête refusée ne pourra pas fonctionner.

Requête 1 :

UPDATE individu
SET naissance = '02-03-1968'
WHERE id_ind = 688 AND nom = 'Crog' AND prenom = 'Daniel';

Requête 2 :

INSERT INTO individu
VALUES (688, 'Crog', 'Daniel', '02-03-1968');

Le message de SQLite pour la requête 2 :

Runtime error: UNIQUE constraint failed: individu.id_ind (19)

Justifie sur ta feuille, puis choisis.

  • La requête 1 : la requête 2 ajoute une ligne avec la clé primaire 688, qui est déjà prise.
  • La requête 2 : elle remplace la ligne de Daniel Crog par une ligne avec la bonne date.
  • La requête 1 : la requête 2 est refusée car il manque la liste des colonnes de individu.
  • Les deux conviennent : elles donnent toutes les deux la bonne date de naissance à Daniel Crog.

UPDATE modifie des lignes qui existent ; INSERT ajoute une ligne. Que vaut la clé primaire de Daniel Crog ?

La requête 1 modifie la ligne existante. La requête 2 essaie d'ajouter une deuxième ligne avec id_ind = 688 : une clé primaire est unique, le SGBD la refuse. Le message de SQLite :

Runtime error: UNIQUE constraint failed: individu.id_ind (19)

2. Cette question traite de la modification de relations.

a. Dire s'il faut utiliser la requête 1 ou la requête 2 proposées ci-dessous pour modifier la date de naissance de Daniel Crog. Justifier votre réponse en expliquant pourquoi la requête refusée ne pourra pas fonctionner.

Requête 1 :

UPDATE individu
SET naissance = '02-03-1968'
WHERE id_ind = 688 AND nom = 'Crog' AND prenom = 'Daniel';

Requête 2 :

INSERT INTO individu
VALUES (688, 'Crog', 'Daniel', '02-03-1968');

Le message de SQLite pour la requête 2 :

Runtime error: UNIQUE constraint failed: individu.id_ind (19)

2. b. Expliquer si la relation individu peut accepter (ou pas) deux individus portant le même nom, le même prénom et la même date de naissance.

Explique sur ta feuille, puis choisis.

  • Non : le SGBD refuse deux lignes identiques sur ces trois attributs.
  • Oui, s'ils ont deux id_ind différents : seule la clé primaire doit être unique.
  • Non, car deux personnes ne peuvent pas avoir le même nom et la même date de naissance.
  • Oui, même avec le même id_ind.

Quel est le seul attribut dont les valeurs doivent toutes être différentes ?

Oui : la clé primaire est id_ind. Deux homonymes nés le même jour sont acceptés, à condition d'avoir deux id_ind différents.

3. Cette question porte sur la notion de clés étrangères.

a. Recopier sur votre copie les demandes ci-dessous, dans leur intégralité, et les compléter correctement pour qu'elles ajoutent dans la relation emploi les rôles de Daniel Crog en tant que James Bond dans le film nommé 'Casino Impérial' puis dans le film 'Ciel tombant'.

INSERT INTO emploi
VALUES (5400, 'Acteur(James Bond)', [[688]], [[105]]);
INSERT INTO emploi
VALUES (5401, 'Acteur(James Bond)', [[688]], [[325]]);

Les deux dernières valeurs sont les clés étrangères, dans l'ordre du schéma : id_ind, puis id_rea.

Cherche l'id_ind de Daniel Crog, puis l'id_rea de chaque film dans les extraits.

INSERT INTO emploi
VALUES (5400, 'Acteur(James Bond)', 688, 105);
INSERT INTO emploi
VALUES (5401, 'Acteur(James Bond)', 688, 325);

688 est Daniel Crog ; 105 est « Casino Imperial » et 325 « Ciel tombant ».

Attention au sujet : la question écrit « Casino Impérial » (avec un é), la table « Casino Imperial ».

3. b. On désire rajouter un nouvel emploi de Daniel Crog en tant que James Bond dans le film 'Docteur Yes'. Expliquer si l'on doit d'abord créer l'enregistrement du film dans la relation realisation ou si l'on doit d'abord créer le rôle dans la relation emploi.

Explique sur ta feuille, puis choisis.

  • D'abord le film dans realisation : id_rea, clé étrangère de emploi, doit désigner un film qui existe.
  • D'abord le rôle dans emploi : le film 'Docteur Yes' sera ajouté ensuite dans realisation.
  • L'ordre n'a pas d'importance : les deux enregistrements sont dans des tables différentes.
  • On ajoute les deux en une seule requête INSERT, qui remplit realisation et emploi à la fois.

Dans emploi, id_rea est une clé étrangère. Que doit-il exister avant ?

D'abord le film dans realisation, puis le rôle dans emploi. Sinon, le SGBD refuse le rôle : sa clé étrangère id_rea ne correspond à aucun film. Par exemple, avec un film 999 qui n'existe pas, SQLite répond :

Runtime error: FOREIGN KEY constraint failed (19)

4. Cette question traite des jointures.

a. Recopier sur votre copie la requête SQL ci-dessous, dans son intégralité, et la compléter de façon à ce qu'elle renvoie le nom de l'acteur, le titre du film et l'année de sortie du film, à partir de tous les enregistrements de la relation emploi pour lesquels la description de l'emploi est 'Acteur(James Bond)'.

SELECT [[individu.nom, realisation.titre, realisation.annee|nom,titre,annee|individu.nom,titre,annee|nom,realisation.titre,realisation.annee]]
FROM emploi
JOIN individu ON [[emploi.id_ind = individu.id_ind|individu.id_ind=emploi.id_ind]]
JOIN realisation ON [[emploi.id_rea = realisation.id_rea|realisation.id_rea=emploi.id_rea]]
WHERE emploi.description = 'Acteur(James Bond)';
Crog | Casino Imperial | 2006
Crog | Ciel tombant | 2012

Après SELECT : trois colonnes, séparées par des virgules. On peut préciser la table : individu.nom.

Après ON : la clé étrangère de emploi = la clé primaire de l'autre table.

SELECT individu.nom, realisation.titre, realisation.annee
FROM emploi
JOIN individu ON emploi.id_ind = individu.id_ind
JOIN realisation ON emploi.id_rea = realisation.id_rea
WHERE emploi.description = 'Acteur(James Bond)';

Avec les deux rôles ajoutés à la question 3. a du sujet, SQLite renvoie :

nomtitreannee
CrogCasino Imperial2006
CrogCiel tombant2012

4. b. Fournir une requête SQL permettant de trouver toutes les descriptions des emplois de Denis Johnson (Denis est son prénom et Johnson est son nom). On veillera à n'afficher que la description des emplois et non les films associés à ces emplois.

La description est dans emploi, le nom et le prénom dans individu : une seule jointure suffit.

Deux conditions dans le WHERE, reliées par AND.

SELECT emploi.description
FROM emploi
JOIN individu ON emploi.id_ind = individu.id_ind
WHERE individu.nom = 'Johnson' AND individu.prenom = 'Denis';

Denis Johnson n'est pas dans l'extrait : sur les tables de l'énoncé, le résultat est vide. La requête a été testée en ajoutant Denis Johnson et un autre Johnson.

4. b. Fournir une requête SQL permettant de trouver toutes les descriptions des emplois de Denis Johnson (Denis est son prénom et Johnson est son nom). On veillera à n'afficher que la description des emplois et non les films associés à ces emplois.

Mémo

Jointure : FROM A JOIN B ON A.cle_etrangere = B.cle_primaire. Sans ON, chaque ligne de A est associée à chaque ligne de B.

INSERT INTO table VALUES (…); · UPDATE table SET colonne = valeur WHERE …; · DELETE FROM table WHERE …; Sans WHERE, toutes les lignes sont modifiées ou supprimées.

Contraintes : clé primaire déjà prise, UNIQUE constraint failed ; clé étrangère sans ligne correspondante, FOREIGN KEY constraint failed. On ajoute d'abord la ligne référencée ; on supprime d'abord les lignes qui y font référence.
