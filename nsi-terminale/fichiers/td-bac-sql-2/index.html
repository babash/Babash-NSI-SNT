SQL type bac 2 : jointures et mises à jour

Objectif : traiter deux vrais exercices de l'épreuve écrite sur les jointures, les modifications d'une base et ses contraintes d'intégrité.

Je sais :

  • écrire une requête avec une ou deux jointures (JOIN … ON) ;
  • écrire un INSERT, un UPDATE ou un DELETE qui modifie seulement les bonnes lignes ;
  • expliquer pourquoi le SGBD refuse une requête (clé primaire déjà prise, clé étrangère) et lire son message d'erreur ;
  • choisir l'ordre des modifications quand des tables sont liées.

1 h 30 à 2 h · 2 exercices du bac (4 points chacun) · 19 questions · seul·e ou en binôme · après le TD type bac 1

Comme à l'épreuve : sans machine d'abord, sur ta feuille ; puis on vérifie ici.

Comment la page corrige tes requêtes : elle ne les exécute pas (pas encore). Elle les compare à des écritures acceptées : majuscules ou minuscules, espaces, point-virgule final, guillemets simples ou doubles, ordre des conditions. Si ta requête est juste mais écrite autrement (avec des alias, par exemple), compare-la avec la correction : elle donne le résultat calculé par SQLite sur les tables de l'énoncé. Les messages d'erreur sont ceux de SQLite.

Exercice 1 · Une base de données sur le cinéma

Source : Bac NSI, Métropole, mai 2022, jour 1 (sujet 22-NSIJ1ME1), exercice 2, 4 points. Le sujet d'origine (PDF). Le plus guidé : des requêtes à compléter.

Cet exercice porte sur les bases de données.

On pourra utiliser les mots clés SQL suivants : SELECT, FROM, WHERE, JOIN, ON, INSERT, INTO, VALUES, UPDATE, SET, AND.

Nous allons étudier une base de données traitant du cinéma dont voici le schéma relationnel qui comporte 3 relations :

  • la relation individu (id_ind, nom, prenom, naissance)
  • la relation realisation (id_rea, titre, annee, type)
  • la relation emploi (id_emp, description, #id_ind, #id_rea)

Les clés primaires sont soulignées et les clés étrangères sont précédées d'un #. Ainsi emploi.id_ind est une clé étrangère faisant référence à individu.id_ind.

1. On s'intéresse ici à la récupération de données dans une relation.

a. Écrire ce que renvoie la requête ci-dessous :

SELECT nom, prenom, naissance
FROM individu
WHERE nom = 'Crog';

Sur l'extrait, une seule personne s'appelle Crog. On affiche trois colonnes, dans l'ordre du SELECT.

Sur l'extrait donné, une seule ligne (résultat calculé par SQLite) :

nomprenomnaissance
CrogDaniel07-07-1968

Le sujet ne donne qu'un extrait : dans la table complète, il pourrait y avoir d'autres Crog.

1. b. Fournir une requête SQL permettant de récupérer le titre et la clé primaire de chaque film dont la date de sortie est strictement supérieure à 2020.

La clé primaire de realisation est soulignée dans le schéma. La date de sortie, c'est l'attribut annee.

SELECT titre, id_rea FROM realisation WHERE annee > 2020;

Résultat calculé par SQLite sur l'extrait :

titreid_rea
Mourir pour attendre950

2. Cette question traite de la modification de relations.

a. Dire s'il faut utiliser la requête 1 ou la requête 2 proposées ci-dessous pour modifier la date de naissance de Daniel Crog. Justifier votre réponse en expliquant pourquoi la requête refusée ne pourra pas fonctionner.

Requête 1 :

UPDATE individu
SET naissance = '02-03-1968'
WHERE id_ind = 688 AND nom = 'Crog' AND prenom = 'Daniel';

Requête 2 :

INSERT INTO individu
VALUES (688, 'Crog', 'Daniel', '02-03-1968');

Justifie sur ta feuille, puis choisis.

  • La requête 1 : la requête 2 ajoute une ligne avec la clé primaire 688, qui est déjà prise.
  • La requête 2 : elle remplace la ligne de Daniel Crog.
  • La requête 1 : la requête 2 est refusée car il manque la liste des colonnes.
  • Les deux conviennent.

UPDATE modifie des lignes qui existent ; INSERT ajoute une ligne. Que vaut la clé primaire de Daniel Crog ?

La requête 1 modifie la ligne existante. La requête 2 essaie d'ajouter une deuxième ligne avec id_ind = 688 : une clé primaire est unique, le SGBD la refuse. Le message de SQLite :

Runtime error: UNIQUE constraint failed: individu.id_ind (19)

2. b. Expliquer si la relation individu peut accepter (ou pas) deux individus portant le même nom, le même prénom et la même date de naissance.

Explique sur ta feuille, puis choisis.

  • Non : le SGBD refuse deux lignes identiques sur ces trois attributs.
  • Oui, s'ils ont deux id_ind différents : seule la clé primaire doit être unique.
  • Non, car deux personnes ne peuvent pas avoir le même nom et la même date de naissance.
  • Oui, même avec le même id_ind.

Quel est le seul attribut dont les valeurs doivent toutes être différentes ?

Oui : la clé primaire est id_ind. Deux homonymes nés le même jour sont acceptés, à condition d'avoir deux id_ind différents.

3. Cette question porte sur la notion de clés étrangères.

a. Recopier sur votre copie les demandes ci-dessous, dans leur intégralité, et les compléter correctement pour qu'elles ajoutent dans la relation emploi les rôles de Daniel Crog en tant que James Bond dans le film nommé 'Casino Impérial' puis dans le film 'Ciel tombant'.

INSERT INTO emploi
VALUES (5400, 'Acteur(James Bond)', [[688]], [[105]]);
INSERT INTO emploi
VALUES (5401, 'Acteur(James Bond)', [[688]], [[325]]);

Les deux dernières valeurs sont les clés étrangères, dans l'ordre du schéma : id_ind, puis id_rea.

Cherche l'id_ind de Daniel Crog, puis l'id_rea de chaque film dans les extraits.

INSERT INTO emploi
VALUES (5400, 'Acteur(James Bond)', 688, 105);
INSERT INTO emploi
VALUES (5401, 'Acteur(James Bond)', 688, 325);

688 est Daniel Crog ; 105 est « Casino Imperial » et 325 « Ciel tombant ».

Attention au sujet : la question écrit « Casino Impérial » (avec un é), la table « Casino Imperial ».

3. b. On désire rajouter un nouvel emploi de Daniel Crog en tant que James Bond dans le film 'Docteur Yes'. Expliquer si l'on doit d'abord créer l'enregistrement du film dans la relation realisation ou si l'on doit d'abord créer le rôle dans la relation emploi.

Explique sur ta feuille, puis choisis.

  • D'abord le film dans realisation : la clé étrangère id_rea de emploi doit faire référence à un film qui existe.
  • D'abord le rôle dans emploi : le film sera ajouté ensuite.
  • L'ordre n'a pas d'importance.
  • On ajoute les deux en une seule requête INSERT.

Dans emploi, id_rea est une clé étrangère. Que doit-il exister avant ?

D'abord le film dans realisation, puis le rôle dans emploi. Sinon, le SGBD refuse le rôle : sa clé étrangère id_rea ne correspond à aucun film. Par exemple, avec un film 999 qui n'existe pas, SQLite répond :

Runtime error: FOREIGN KEY constraint failed (19)

4. Cette question traite des jointures.

a. Recopier sur votre copie la requête SQL ci-dessous, dans son intégralité, et la compléter de façon à ce qu'elle renvoie le nom de l'acteur, le titre du film et l'année de sortie du film, à partir de tous les enregistrements de la relation emploi pour lesquels la description de l'emploi est 'Acteur(James Bond)'.

SELECT [[individu.nom, realisation.titre, realisation.annee|nom,titre,annee|individu.nom,titre,annee|nom,realisation.titre,realisation.annee]]
FROM emploi
JOIN individu ON [[emploi.id_ind = individu.id_ind|individu.id_ind=emploi.id_ind]]
JOIN realisation ON [[emploi.id_rea = realisation.id_rea|realisation.id_rea=emploi.id_rea]]
WHERE emploi.description = 'Acteur(James Bond)';

Après SELECT : trois colonnes, séparées par des virgules. On peut préciser la table : individu.nom.

Après ON : la clé étrangère de emploi = la clé primaire de l'autre table.

SELECT individu.nom, realisation.titre, realisation.annee
FROM emploi
JOIN individu ON emploi.id_ind = individu.id_ind
JOIN realisation ON emploi.id_rea = realisation.id_rea
WHERE emploi.description = 'Acteur(James Bond)';

Avec les deux rôles ajoutés à la question 3. a, SQLite renvoie :

nomtitreannee
CrogCasino Imperial2006
CrogCiel tombant2012

4. b. Fournir une requête SQL permettant de trouver toutes les descriptions des emplois de Denis Johnson (Denis est son prénom et Johnson est son nom). On veillera à n'afficher que la description des emplois et non les films associés à ces emplois.

La description est dans emploi, le nom et le prénom dans individu : une seule jointure suffit.

Deux conditions dans le WHERE, reliées par AND.

SELECT emploi.description
FROM emploi
JOIN individu ON emploi.id_ind = individu.id_ind
WHERE individu.nom = 'Johnson' AND individu.prenom = 'Denis';

Denis Johnson n'est pas dans l'extrait : sur les tables de l'énoncé, le résultat est vide. La requête a été testée en ajoutant Denis Johnson et un autre Johnson.

Exercice 2 · Louer du matériel entre membres

Source : Bac NSI, Polynésie, mars 2023, jour 2 (sujet 23-NSIJ2PO1), exercice 2, 4 points. Le sujet d'origine (PDF). Plus proche de l'épreuve : des requêtes à écrire en entier, deux jointures, une suppression.

Cet exercice traite du thème base de données, et principalement du modèle relationnel et du langage SQL.

L'énoncé de cet exercice peut utiliser les mots du langage SQL suivants : SELECT, FROM, WHERE, JOIN ON, INSERT INTO, VALUES, UPDATE, SET, DELETE, COUNT, AND, OR

Un site permet à ses membres de proposer à la location du matériel et de louer du matériel. Ceci permet de mutualiser du matériel entre membres et au propriétaire de rentabiliser cet achat. Le temps d'utilisation du matériel s'en trouve ainsi augmenté et le nombre d'appareils diminué.

Le modèle relationnel est donné par le schéma ci-dessous.

La table Membre contient les informations de chaque utilisateur du site (nom, prénom et code postal). La table Objet décrit le type d'objet à la location ainsi que son tarif de location journalier. La table Reservation répertorie toutes les réservation effectuées par les membres du site avec notamment leur date de début et de fin de location. La table Possede permet de lier les tables Membre et Objet.

1. Dans cette partie, on ne demande pas de requête SQL. En étudiant le contenu des tables ci-dessus :

a) Indiquer quels sont les prénoms et noms du ou des membres du site qui proposent la location d'un appareil à raclette ;

  • Mohamed Ali
  • Fernando Alonso
  • Antoine Dupont
  • Pauline Ferrand
  • Harry Kane

L'appareil à raclette est l'objet 4. Dans Possede, quels membres ont l'objet 4 ?

Dans Possede, l'objet 4 est associé aux membres 1 et 2 : Mohamed Ali et Fernando Alonso. Harry Kane a réservé un appareil à raclette, il ne le propose pas.

1. b) Donner le prénom et le nom du membre qui ne propose pas d'objet à la location.

  • Mohamed Ali
  • Antoine Dupont
  • Pauline Ferrand
  • Harry Kane

Cherche le numéro de membre qui n'apparaît jamais dans la table Possede.

Le membre 5, Harry Kane, n'apparaît pas dans Possede.

2. a) Donner le résultat de la requête suivante :

SELECT nom, prenom FROM Membre WHERE cp = "69003" ;

Écris le résultat sur ta feuille, puis coche les lignes qui y figurent.

  • Ali | Mohamed

2. b) Écrire une requête permettant de connaître le tarif de location d'une scie circulaire.

Le tarif et la description sont dans la même table : pas besoin de jointure.

SELECT tarif FROM Objet WHERE description = 'Scie circulaire';

2. c) Écrire une requête permettant de modifier le tarif de location d'un nettoyeur à haute pression pour le passer à 15 € par jour au lieu de 20 € par jour.

Sans WHERE, tous les objets passent à 15 € ! Ajoute la condition qui désigne le nettoyeur.

UPDATE Objet SET … WHERE …; La description s'écrit exactement comme dans la table.

UPDATE Objet SET tarif = 15 WHERE description = 'Nettoyeur haute pression';

ou WHERE id_objet = 1. Attention : la table écrit « Nettoyeur haute pression », sans « à ».

2. d) Écrire une requête SQL permettant d'ajouter Wendie Renard habitant à Villeurbanne (code postal 69100) dans la table Membre, avec un id_membre de 6.

Les valeurs dans l'ordre des colonnes : id_membre, nom, prenom, cp. La ville n'est pas dans la table.

INSERT INTO Membre VALUES (6, 'Renard', 'Wendie', '69100');

Le code postal est du texte dans la table (TEXT) : '69100'.

3. a) Expliquer la limitation importante d'utilisation du service offert par le site si l'on utilisait le couple de clés étrangères (id_objet, id_membre) en tant que clé primaire de la relation Reservation.

Explique sur ta feuille, puis choisis.

  • Un objet ne pourrait être réservé que par un seul membre.
  • Un membre ne pourrait réserver qu'une seule fois un même objet.
  • Un membre ne pourrait réserver qu'un seul objet en tout.
  • Deux réservations ne pourraient pas commencer le même jour.

Regarde les réservations 3 et 4 : même objet, même membre.

Une clé primaire est unique : un même couple (objet, membre) ne pourrait apparaître qu'une fois. Mohamed Ali n'aurait pas pu réserver deux fois la perforatrice (réservations 3 et 4).

3. b) Mohamed Ali décide de ne plus être membre du site. Il faut donc le supprimer de la table Membre à l'aide de la requête :

DELETE FROM Membre
WHERE nom = "Ali" AND prenom = "Mohamed" ;

Expliquer pourquoi cette requête produit une erreur.

Le message de SQLite (vérification des clés étrangères activée) :

Runtime error: FOREIGN KEY constraint failed (19)

Explique sur ta feuille, puis choisis.

  • Il faut écrire les chaînes entre apostrophes.
  • Son id_membre (1) est utilisé comme clé étrangère dans Possede et Reservation : ces lignes feraient référence à un membre qui n'existe plus.
  • Il faut supprimer avec la clé primaire : WHERE id_membre = 1.
  • On ne peut jamais supprimer une ligne d'une table qui a une clé primaire.

FOREIGN KEY constraint failed : « la contrainte de clé étrangère n'est pas respectée ». Où le membre 1 apparaît-il encore ?

Le membre 1 apparaît dans Possede (objets 4 et 6) et dans Reservation (réservations 3 et 4). Le supprimer laisserait des clés étrangères qui ne font référence à rien : le SGBD refuse (contrainte d'intégrité référentielle).

3. c) Proposer une suite de requêtes utilisant le mot clé DELETE, précédant la requête ci-dessus pour supprimer correctement Mohamed Ali, dont l'id_membre est 1, de la base de donnée.

Rappel : la relation Objet décrit le type d'objet à la location. Il n'y a pas d'objet à supprimer dans cette table lors du départ d'un membre.

Écris les requêtes à la suite, sur une ligne, séparées par un point-virgule.

Deux tables font référence au membre 1. Une requête DELETE par table.

Forme : DELETE FROM … WHERE id_membre = 1;

DELETE FROM Possede WHERE id_membre = 1;
DELETE FROM Reservation WHERE id_membre = 1;

Ces deux requêtes, dans un ordre ou dans l'autre. Ensuite, la requête de la question 3. b passe : SQLite supprime Mohamed Ali.

4. Dans cette partie, les requêtes utilisent des jointures entre tables. On supposera donc les numéros id_membre et id_objet non connus.

a) Écrire une requête permettant de compter le nombre de réservations réalisées par Fernando Alonso.

Les réservations sont dans Reservation, le nom dans Membre : jointure sur id_membre.

Pour compter : SELECT COUNT(*) FROM …

SELECT COUNT(*) FROM Reservation
JOIN Membre ON Reservation.id_membre = Membre.id_membre
WHERE Membre.nom = 'Alonso' AND Membre.prenom = 'Fernando';

Résultat calculé par SQLite :

COUNT(*)
3

4. b) Écrire une requête permettant de connaître les noms et prénoms des membres possédant un appareil à raclette.

Sans conditions ON, chaque membre est associé à chaque ligne de Possede : SQLite renvoie tous les membres, plusieurs fois. Chaque JOIN a besoin de son ON.

Trois tables : Membre (le nom), Possede (le lien), Objet (la description). Il faut deux jointures.

Forme : SELECT … FROM Membre JOIN Possede ON … JOIN Objet ON … WHERE …;

SELECT nom, prenom FROM Membre
JOIN Possede ON Membre.id_membre = Possede.id_membre
JOIN Objet ON Possede.id_objet = Objet.id_objet
WHERE description = 'Appareil à raclette';

Résultat calculé par SQLite :

nomprenom
AliMohamed
AlonsoFernando

Mémo

Jointure : FROM A JOIN B ON A.cle_etrangere = B.cle_primaire. Sans ON, chaque ligne de A est associée à chaque ligne de B.

INSERT INTO table VALUES (…); · UPDATE table SET colonne = valeur WHERE …; · DELETE FROM table WHERE …; Sans WHERE, toutes les lignes sont modifiées ou supprimées.

Contraintes : clé primaire déjà prise, UNIQUE constraint failed ; clé étrangère sans ligne correspondante, FOREIGN KEY constraint failed. On ajoute d'abord la ligne référencée ; on supprime d'abord les lignes qui y font référence.
