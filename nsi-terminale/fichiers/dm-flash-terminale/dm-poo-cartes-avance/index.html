Un jeu de cartes

DM flash, niveau avancé

Cours-quiz

Nom et prénom :Classe :

Objectif : faire travailler deux classes ensemble : un paquet qui contient des objets cartes.

Je sais :

  • reconnaître les attributs et les méthodes de deux classes ;
  • prévoir ce qu'affiche un programme, erreur comprise ;
  • remplir une liste d'objets avec deux boucles imbriquées ;
  • expliquer pourquoi == ne compare pas deux objets attribut par attribut.

50 minutes · 9 questions et 1 bonus ★ · devoir maison

Un jeu classique de 52 cartes a quatre couleurs : trèfle (noir), carreau (rouge), cœur (rouge) et pique (noir). Chaque couleur a treize cartes : As, 2, 3, 4, 5, 6, 7, 8, 9, 10, Valet, Dame, Roi.

Les couleurs s'appellent aussi des enseignes. Dans le jeu de cartes, le mot « couleur » n'a donc pas le même sens que dans la vie courante (où l'on dirait qu'il n'y a que deux couleurs : le rouge et le noir).

On s'intéresse au code suivant, enregistré dans le fichier cartes.py.

class Carte:

    def __init__(self, c, v):
        """Initialise couleur (entre 1 et 4) et valeur (entre 1 et 13)."""
        self.couleur = c
        self.valeur = v

    def get_nom(self):
        """Renvoie le nom de la carte : As, 2, ... 10, Valet, Dame, Roi."""
        if self.valeur > 1 and self.valeur < 11:
            return str(self.valeur)
        elif self.valeur == 11:
            return "Valet"
        elif self.valeur == 12:
            return "Dame"
        elif self.valeur == 13:
            return "Roi"
        else:
            return "As"

    def get_couleur(self):
        """Renvoie la couleur (parmi pique, coeur, carreau, trefle)."""
        return ['pique', 'coeur', 'carreau', 'trefle'][self.couleur - 1]

class Paquet:

    def __init__(self):
        self.contenu = []

    def remplir(self):

        for couleur in range(1, ...):

                ...

    def get_carte_at(self, pos):
        """Renvoie la carte qui se trouve à la position donnée."""
        if 0 <= pos < ...:
            return ...

    def nb_cartes(self):
        return len(self.contenu)

Dans la boucle, on crée une carte et on l'ajoute à la liste : self.contenu.append(Carte(…, …)).

    def __init__(self):

4 × 13 = 52 tours : un objet Carte par tour. Les cartes sont rangées couleur par couleur : la carte de couleur c et de valeur v est à la position (c − 1) × 13 + (v − 1).

Sans le if, self.contenu[52] provoquerait une erreur IndexError. Quand la condition est fausse, la méthode arrive à sa fin sans return : elle renvoie None. len(self.contenu) est juste aussi.

3. Chercher une carte dans le paquet

Les méthodes étant complétées comme aux questions 6 et 7, on écrit ce programme sous les classes :

carte1 = Carte(2, 2)
paquet = Paquet()
paquet.remplir()
for i in range(1, len(paquet.nb_cartes)+1):
    current = paquet.get_carte_at(i)
    if current.couleur == carte1.couleur and current.valeur == carte1.valeur:
        print("Trouvé en position {i}")

Qu'affiche ce programme ?

  • Rien : il s'arrête aussitôt sur une erreur TypeError.
  • Trouvé en position 14, une seule fois, sans erreur
  • Trouvé en position {i}, avec les accolades
  • Rien, sans erreur : la carte n'est jamais trouvée dans le paquet.

paquet.nb_cartes, sans parenthèses, n'appelle pas la méthode : c'est la méthode elle-même.

Peut-on calculer la longueur (len) d'une méthode ?

Sans parenthèses, paquet.nb_cartes est la méthode, pas le nombre de cartes. Python s'arrête à la ligne du for :

TypeError: object of type 'method' has no len()

Et ce n'est pas la seule erreur : voir la question bonus.

Qu'affiche ce programme ?

    def __init__(self, c, v):
        self.couleur = c
        self.valeur = v

class Paquet:
    def __init__(self):
        self.contenu = []

    def remplir(self):

            for valeur in range(1, 14):
                self.contenu.append(Carte(couleur, valeur))

        if 0 <= pos < self.nb_cartes():
            return self.contenu[pos]

    def nb_cartes(self):

carte1 = Carte(2, 2)
paquet = Paquet()
paquet.remplir()
for i in range(paquet.nb_cartes()):
    current = paquet.get_carte_at(i)
    if current.couleur == carte1.couleur and current.valeur == carte1.valeur:
        print(f"Trouvé en position {i}")

Trois corrections : paquet.nb_cartes() sans len, les positions de 0 à 51 (range(paquet.nb_cartes())), et le f devant la chaîne. Le 2 de la couleur 2 est en position (2 − 1) × 13 + (2 − 1) = 14.

Pourquoi ne peut-on pas comparer directement current et carte1 avec current == carte1 ?

  • Pour deux objets Carte (sans méthode __eq__), == vérifie si c'est le même objet : deux cartes créées à part ne sont pas égales.
  • Python s'arrête sur une erreur : on ne peut pas comparer deux objets d'une classe que l'on a écrite soi-même.
  • On peut : comme pour deux tuples, == compare tout seul la couleur et la valeur des deux cartes, attribut par attribut.
  • Parce que current est une chaîne de caractères (le nom de la carte, comme "Dame"), pas un objet Carte.

carte1 a été créée par Carte(2, 2) ; la carte du paquet, par un autre appel à Carte(2, 2) dans remplir. Est-ce le même objet ?

Carte(2, 2) == Carte(2, 2) vaut False : ce sont deux objets distincts en mémoire, et la classe ne dit pas comment comparer deux cartes. On compare donc les attributs, un par un, comme dans le programme.

Pourquoi ne peut-on pas comparer directement current et carte1 ?

Mémo

Un objet peut en contenir d'autres : self.contenu est une liste d'objets Carte, remplie avec self.contenu.append(Carte(c, v)).

Une méthode s'appelle avec ses parenthèses : paquet.nb_cartes(). Deux objets Carte distincts ne sont pas ==, même avec les mêmes attributs : la classe n'a pas de méthode __eq__.
