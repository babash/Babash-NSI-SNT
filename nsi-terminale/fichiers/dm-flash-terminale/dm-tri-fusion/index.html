1. La fusion

Maki Tire-Vite, le cow-boy du lagon, doit trier une grande file de Lagonnet par taille. Pour aller plus vite, il utilise le tri fusion : il sépare la file en deux, demande à ses adjoint·e·s de trier chaque moitié, puis il fusionne les deux moitiés triées pour n'en former qu'une seule.

def fusion(gauche, droite):
    resultat = []
    i = j = 0
    # On compare les premiers de chaque file et on prend le plus petit
    while i < len(gauche) and j < len(droite):
        if gauche[i] < droite[j]:
            resultat.append(gauche[i])
            i += 1
        else:
            resultat.append(droite[j])
            j += 1
    # On ajoute les restes des files
    resultat.extend(gauche[i:])
    resultat.extend(droite[j:])
    return resultat

def tri_fusion(tab):
    if len(tab) <= 1:
        return tab
    milieu = len(tab) // 2
    gauche = tri_fusion(tab[:milieu])
    droite = tri_fusion(tab[milieu:])
    return fusion(gauche, droite)

Maki a déjà deux groupes triés : gauche = [0.9, 1.5] (Petit-Îlot et Grande-Barge) et droite = [1.2, 2.1] (Moyen-Maki et Mont-Choungui). Complète les étapes de la fonction fusion.

# On compare 0.9 et 1.2. Le plus petit, ajouté au résultat :
etape_1 = [[0.9]]
# On compare 1.5 et 1.2. Le plus petit, ajouté au résultat :
etape_2 = [[1.2]]
# On compare 1.5 et 2.1. Le plus petit, ajouté au résultat :
etape_3 = [[1.5]]
# Il ne reste que 2.1 : on l'ajoute à la fin. Résultat final :
resultat = [[[0.9, 1.2, 1.5, 2.1]|0.9, 1.2, 1.5, 2.1]]

À chaque comparaison, le plus petit des deux passe dans le résultat, et on avance dans sa liste seulement.

Après la troisième comparaison, gauche est épuisée : la boucle s'arrête, et extend ajoute ce qui reste de droite.

etape_1 = 0.9
etape_2 = 1.2
etape_3 = 1.5
resultat = [0.9, 1.2, 1.5, 2.1]

Trois comparaisons suffisent : on ne compare jamais deux éléments d'une même liste, puisqu'elles sont déjà triées.

Ce cadre est la fusion de [2.1] et de [1.2].

fusion([2.1], [1.2]) donne [1.2, 2.1] : 1.2 est plus petit que 2.1, il passe devant. Puis fusion([0.9, 1.5], [1.2, 2.1]) donne le tableau trié [0.9, 1.2, 1.5, 2.1], comme à la question 1.

3. Pourquoi c'est rapide

Contrairement au tri par insertion, le tri fusion coupe toujours le tableau en deux, que les Lagonnet soient déjà rangés ou non.

Le temps de calcul du tri fusion change-t-il beaucoup si le tableau est déjà trié ?

  • Oui, il devient beaucoup plus rapide : il n'a presque rien à faire.
  • Oui, il devient beaucoup plus lent, car il découpe pour rien.
  • Non : il découpe et fusionne de la même façon dans tous les cas.
  • Il ne fait rien : il voit tout de suite que le tableau est déjà trié.

Le découpage dépend-il des valeurs, ou seulement de la longueur du tableau ?

Le découpage ne dépend que de la longueur. Mesuré sur 1000 nombres : environ 4900 comparaisons si le tableau est déjà trié, 5000 s'il est à l'envers. Presque pareil.

Le tri fusion coupe toujours le tableau en deux, que les Lagonnet soient déjà rangés ou non. Le temps de calcul change-t-il beaucoup si le tableau est déjà trié ?

Avec 1000 Lagonnet, le tri fusion est en général beaucoup plus rapide que le tri par insertion : sa complexité est en n log(n). Pourquoi « couper en deux » aide-t-il l'ordinateur ?

  • Les deux moitiés sont triées en même temps, par deux processeurs, ce qui divise le temps par deux.
  • Couper en deux élimine à chaque fois la moitié des éléments, comme dans une recherche dichotomique.
  • Une fois le tableau coupé en morceaux de 1 élément, il n'y a plus aucune comparaison à faire.
  • On coupe environ 10 fois en deux jusqu'à 1 élément ; chaque niveau fusionne les 1000 éléments une fois.

Combien de fois faut-il diviser 1000 par 2 pour arriver à 1 ?

1000 → 500 → 250 → … → 1 : environ 10 niveaux (le logarithme en base 2 de 1000 vaut environ 10). À chaque niveau, les fusions passent une fois sur les 1000 éléments : environ 1000 × 10 opérations. Le tri par insertion, dans le pire cas, fait 1000 × 1000 / 2 comparaisons (499 500, mesuré), contre environ 5000 pour le tri fusion.

Dans tri_fusion, à quoi sert la ligne if len(tab) <= 1: return tab ? (Indice : peut-on couper en deux un Lagonnet tout seul ?)

  • Elle donne le cas de base : 0 ou 1 élément, la liste est déjà triée ; les appels s'arrêtent.
  • Elle évite une erreur quand la liste est vide, et ne sert à rien d'autre.
  • Elle vérifie que la liste est déjà triée avant de la découper en deux moitiés.
  • Elle trie directement les petites listes de deux éléments, sans avoir à les découper.

Que se passerait-il sans cette ligne, avec tab = [2.1] ? tab[:0] est vide et tab[0:] vaut encore [2.1].

C'est le cas de base. Sans lui, tri_fusion([2.1]) rappellerait tri_fusion([2.1]) sans fin : Python s'arrêterait avec une RecursionError.

Dans tri_fusion, à quoi sert la ligne if len(tab) <= 1: return tab ? (Indice : peut-on couper en deux un Lagonnet tout seul ?)

Mémo

Diviser pour régner : couper le problème en deux, résoudre chaque moitié par un appel récursif, combiner les résultats (ici, la fusion).

Tri fusion : environ n log(n) opérations, dans tous les cas ; tri par insertion : jusqu'à n × n / 2.
