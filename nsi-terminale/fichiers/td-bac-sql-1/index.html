Exercice 1 · Les morceaux préférés d'un musicien

Source : Bac NSI, Métropole, mai 2022, jour 2 (sujet 22-NSIJ2ME1), exercice 4, 4 points. Le sujet d'origine (PDF). C'est l'exercice le plus guidé : commence par lui.

Cet exercice porte sur les bases de données relationnelles et le langage SQL.

L'énoncé de cet exercice utilise les mots clefs du langage SQL suivants : SELECT, FROM, WHERE, JOIN ON, UPDATE, SET, INSERT INTO VALUES, COUNT, ORDER BY.

  • La clause ORDER BY suivie d'un attribut permet de trier les résultats par ordre croissant de l'attribut ;
  • COUNT(*) renvoie le nombre de lignes d'une requête ;

Un musicien souhaite créer une base de données relationnelle contenant ses morceaux et interprètes préférés. Pour cela il utilise le langage SQL. Il crée une table morceaux qui contient entre autres les titres des morceaux et leur année de sortie :

morceaux

1Like a Rolling Stone19651
2Respect19672
3Imagine19703
4Hey Jude19684
5Smells Like Teen Spirit19915
6I Want To hold Your Hand19634

Il crée la table interpretes qui contient les interprètes et leur pays d'origine :

interpretes

2Aretha FranklinÉtats-Unis
3John LennonAngleterre
4The BeatlesAngleterre
5NirvanaÉtats-Unis

id_morceau de la table morceaux et id_interprete de la table interpretes sont des clés primaires.

L'attribut id_interprete de la table morceaux fait directement référence à la clé primaire de la table interpretes.

1. a. Écrire le résultat de la requête suivante :

SELECT titre FROM morceaux WHERE id_interprete = 4;

Écris le résultat sur ta feuille, puis coche les titres qui y figurent.

  • Like a Rolling Stone
  • Hey Jude
  • Imagine
  • I Want To hold Your Hand
  • Respect
  • The Beatles

La condition garde les lignes de morceaux dont la dernière colonne vaut 4.

On garde les lignes où id_interprete vaut 4 (The Beatles), et on n'affiche que la colonne titre :

titre
Hey Jude
I Want To hold Your Hand

1. b. Écrire une requête permettant d'afficher les noms des interprètes originaires d'Angleterre.

Sans apostrophes, Angleterre est lu comme un nom de colonne. SQLite répond : no such column: Angleterre. Une chaîne de caractères s'écrit entre apostrophes : 'Angleterre'.

Quelle table contient le pays ? On affiche quelle colonne ?

Forme : SELECT … FROM interpretes WHERE pays = '…';

SELECT nom FROM interpretes WHERE pays = 'Angleterre';

Résultat calculé par SQLite :

nom
John Lennon
The Beatles

1. c. Écrire le résultat de la requête suivante :

SELECT titre, annee FROM morceaux ORDER BY annee;

Écris le tableau sur ta feuille. Ici, remets les lignes du résultat dans l'ordre (titre | annee).

  1. I Want To hold Your Hand | 1963
  2. Like a Rolling Stone | 1965
  3. Respect | 1967
  4. Hey Jude | 1968
  5. Imagine | 1970
  6. Smells Like Teen Spirit | 1991

Deux colonnes, six lignes, de 1963 à 1991 :

Relis les rappels de l'énoncé : une fonction compte les lignes.

SELECT COUNT(*) FROM morceaux;

Résultat calculé par SQLite :

1. e. Écrire une requête affichant les titres des morceaux par ordre alphabétique.

Trier sur quelle colonne ? ORDER BY trie par ordre croissant : pour du texte, c'est l'ordre alphabétique.

SELECT titre FROM morceaux ORDER BY titre;

ASC (croissant) peut être ajouté : c'est l'ordre par défaut. Résultat calculé par SQLite :

titre
Hey Jude
I Want To hold Your Hand
Imagine
Like a Rolling Stone
Respect
Smells Like Teen Spirit

2. a. Citer, en justifiant, la clé étrangère de la table morceaux.

Justifie sur ta feuille, puis choisis la bonne réponse.

  • id_morceau, car elle identifie chaque morceau.
  • id_interprete, car elle fait référence à la clé primaire de la table interpretes.
  • titre, car deux morceaux n'ont jamais le même titre.
  • Il n'y en a pas : chaque table a seulement une clé primaire.

Une clé étrangère est un attribut qui fait référence à la clé primaire d'une autre table.

id_interprete est la clé étrangère de morceaux : ses valeurs doivent exister dans la colonne id_interprete (clé primaire) de la table interpretes. Elle relie chaque morceau à son interprète.

2. b. Écrire un schéma relationnel des tables interpretes et morceaux.

Écris-le sur ta feuille (clé primaire soulignée, clé étrangère précédée de #), puis choisis celui qui correspond.

  • interpretes(id_interprete, nom, pays) et morceaux(id_morceau, titre, annee, #id_interprete)
  • interpretes(#id_interprete, nom, pays) et morceaux(id_morceau, titre, annee, id_interprete)
  • interpretes(id_interprete, nom, pays) et morceaux(id_morceau, titre, annee, id_interprete)
  • interpretes(id_interprete) et morceaux(id_morceau, #id_interprete)

Le schéma d'une relation : son nom, puis tous ses attributs entre parenthèses. On souligne la clé primaire, on met # devant une clé étrangère.

interpretes(id_interprete, nom, pays)
morceaux(id_morceau, titre, annee, #id_interprete)

On peut aussi donner les domaines : id_interprete INT, nom VARCHAR…

2. c. Expliquer pourquoi la requête suivante produit une erreur :

INSERT INTO interpretes VALUES (1, 'Trust', 'France');

Explique sur ta feuille, puis choisis la bonne explication.

  • Il manque la liste des colonnes après le nom de la table.
  • 'France' n'est pas un pays autorisé.
  • La clé primaire id_interprete vaut déjà 1 (Bob Dylan) : deux lignes ne peuvent pas avoir la même clé primaire.
  • Trust n'a aucun morceau dans la table morceaux.

Regarde la première valeur, et compare-la avec la table interpretes.

La valeur 1 de id_interprete est déjà prise par Bob Dylan. Une clé primaire est unique : le SGBD refuse l'insertion (contrainte d'intégrité de relation). Le message de SQLite :

Runtime error: UNIQUE constraint failed: interpretes.id_interprete (19)

3. a. Une erreur de saisie a été faite. Écrire une requête SQL permettant de changer l'année du titre « Imagine » en 1971.

Sans WHERE, tous les morceaux passent en 1971 ! Ajoute la condition qui désigne « Imagine ».

Pour modifier une ligne : UPDATE table SET colonne = valeur WHERE condition;

La condition peut porter sur le titre ou sur la clé primaire (id_morceau = 3).

UPDATE morceaux SET annee = 1971 WHERE titre = 'Imagine';

ou WHERE id_morceau = 3 : c'est plus sûr, car la clé primaire désigne une seule ligne. SQLite modifie bien une seule ligne : (3, Imagine, 1971, 3).

3. b. Écrire une requête SQL permettant d'ajouter l'interprète « The Who » venant d'Angleterre à la table interpretes. On lui donnera un id_interprete égal à 6.

Forme : INSERT INTO table VALUES (valeur1, valeur2, …); dans l'ordre des colonnes de la table.

INSERT INTO interpretes VALUES (6, 'The Who', 'Angleterre');

On peut aussi nommer les colonnes : INSERT INTO interpretes (id_interprete, nom, pays) VALUES (6, 'The Who', 'Angleterre');

3. c. Écrire une requête SQL permettant d'ajouter le titre « My Generation » de « The Who » à la table morceaux. Ce titre est sorti en 1965 et on lui donnera un id_morceau de 7 ainsi que l'id_interprete qui conviendra.

L'id_interprete qui convient est celui de The Who, ajouté à la question précédente.

INSERT INTO morceaux VALUES (7, 'My Generation', 1965, 6);

L'ordre compte : il faut d'abord ajouter The Who (question 3. b), sinon la clé étrangère 6 ne fait référence à aucun interprète.

4. Écrire une requête permettant de lister les titres des interprètes venant des États-Unis.

Ta requête est bien construite, mais la table écrit 'États-Unis', avec un É : avec 'Etats-Unis', SQLite ne trouve aucune ligne.

Sans condition ON, chaque morceau est associé à chaque interprète des États-Unis : SQLite renvoie 18 lignes, chaque titre trois fois, Imagine et Hey Jude compris. La jointure doit relier la clé étrangère à la clé primaire.

Le titre est dans morceaux, le pays dans interpretes : il faut une jointure.

Forme : SELECT … FROM morceaux JOIN interpretes ON morceaux.id_interprete = interpretes.id_interprete WHERE …;

SELECT titre FROM morceaux
JOIN interpretes ON morceaux.id_interprete = interpretes.id_interprete
WHERE pays = 'États-Unis';

Résultat calculé par SQLite :

titre
Like a Rolling Stone
Respect
Smells Like Teen Spirit

Mémo

Clé primaire : identifie chaque ligne (valeurs toutes différentes). Clé étrangère : fait référence à la clé primaire d'une autre table. Schéma : morceaux(id_morceau, titre, annee, #id_interprete).

SELECT colonnes FROM table WHERE condition ORDER BY colonne; · DISTINCT retire les doublons · COUNT(*), MIN, MAX.

Une chaîne ou une date s'écrit entre apostrophes : 'Angleterre', '2021-11-08'.
