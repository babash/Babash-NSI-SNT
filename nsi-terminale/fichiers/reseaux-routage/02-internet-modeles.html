Internet — Architecture mondiale et modèles (1/4)

NSI — Terminale

1. Internet ≠ Web

Internet est le réseau mondial qui interconnecte des milliards de machines via une infrastructure physique (câbles, routeurs, satellites).
Le Web (World Wide Web) n'est que l'un des services offerts par Internet : un ensemble de pages liées entre elles via le protocole HTTP. D'autres services existent : courriel (SMTP/IMAP), transfert de fichiers (FTP, SSH), messagerie instantanée, streaming, etc.

2. Infrastructure physique mondiale

Contrairement à l'impression d'« immatérialité », Internet repose sur une infrastructure très concrète :

  • Près de 99 % du trafic intercontinental circule par câbles sous-marins en fibre optique, et non par satellite.
  • Des centres de données (datacenters) hébergent les serveurs et les contenus.
  • Des opérateurs (Tier 1, Tier 2…) interconnectent leurs réseaux dans des points d'échange (IXP).
Exemple — Mayotte : l'île est raccordée à l'Internet mondial par deux câbles sous-marins : LION2, vers Madagascar, Maurice et le Kenya, et FLY-LION3, vers les Comores, où il rejoint le câble EASSy. La présence de plusieurs câbles permet une redondance : si l'un est coupé (chalutier, séisme), les paquets sont réacheminés sur un autre. C'est la résilience du maillage physique.

3. Modèle Client-Serveur

Une machine (le client) émet une requête vers une machine spécialisée (le serveur) qui héberge une ressource et renvoie une réponse.

  • Rôles asymétriques et figés.
  • Le serveur est toujours actif et attend les requêtes.
  • Exemples : Web (HTTP), mail, DNS, jeux en ligne.
  • Limite : si le serveur tombe en panne, le service s'arrête.

4. Modèle Pair-à-Pair (P2P)

Chaque machine (pair) joue simultanément le rôle de client et de serveur. Les données sont distribuées à travers le réseau.

  • Rôles symétriques.
  • Pas de point central : résilience élevée.
  • Mieux adapté au partage de gros fichiers.
  • Exemples : BitTorrent, certains protocoles de blockchain, IPFS.

6. Le protocole IP : acheminer les paquets

IP (Internet Protocol) est responsable de l'acheminement des paquets d'un émetteur à un destinataire, à travers un ou plusieurs réseaux interconnectés par des routeurs.

  • Chaque paquet IP comporte un en-tête avec l'IP source et l'IP destination.
  • IP est non fiable : pas de garantie de livraison, ni d'ordre, ni d'absence de doublons.
  • IP fonctionne par commutation de paquets : le message est découpé en paquets indépendants pouvant emprunter des routes différentes.

7. Le protocole TCP : assurer la fiabilité

Pour pallier les défauts d'IP, on lui adjoint TCP (Transmission Control Protocol), qui fiabilise les échanges.

Principaux mécanismes de TCP :
  • Connexion préalable : poignée de main en 3 étapes (SYN → SYN-ACK → ACK) pour ouvrir une session entre client et serveur.
  • Découpage et numérotation : les données sont découpées en segments numérotés.
  • Accusés de réception (ACK) : chaque segment reçu est confirmé. Sans ACK dans un délai imparti, le segment est retransmis.
  • Réordonnancement : à la réception, TCP remet les segments dans l'ordre, même s'ils sont arrivés mélangés.
  • Détection d'erreurs par somme de contrôle (checksum).
TCP vs UDP : à côté de TCP existe UDP, plus rapide mais non fiable (pas d'accusé de réception). UDP est utilisé pour les usages temps réel où une perte ponctuelle est acceptable : streaming vidéo, jeux en ligne, voix sur IP.

8. Le DNS : annuaire d'Internet

Le DNS (Domain Name System) est un service distribué qui traduit un nom de domaine intelligible (wikipedia.org) en une adresse IP utilisable par les machines (208.80.154.224).
