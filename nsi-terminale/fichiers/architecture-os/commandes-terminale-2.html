À retenir

  • Un processus est un programme en cours d'exécution ; le système lui donne un numéro, son PID.
  • Chaque processus est créé par un autre, son parent : son PPID est le PID du parent. Le processus 1 est lancé par le noyau au démarrage.
  • ps -ef liste les processus ; top les montre en temps réel.
  • kill PID demande à un processus de s'arrêter ; kill -9 PID l'arrête tout de suite, sans lui laisser le temps de sauvegarder.
  • Le joker * remplace n'importe quelle suite de caractères : *.py, ce sont tous les fichiers du répertoire courant qui finissent par .py.
  • Le tube | envoie ce qu'affiche la commande de gauche à la commande de droite : ps -ef | grep cron ne garde que les lignes qui contiennent cron.

1. Les processus

eleve lance un calcul des marées en arrière-plan (le & rend la main tout de suite), puis demande la liste des processus avec quelques colonnes : PID, PPID, utilisateur·rice, part du processeur, part de la mémoire, commande. En voici un extrait :

eleve@lycee:~$ python3 marees.py &
eleve@lycee:~$ ps -eo pid,ppid,user,%cpu,%mem,args
  PID  PPID USER      %CPU %MEM COMMAND
    1     0 root       0.0  0.1 /sbin/init
   98     1 root       0.0  0.3 /usr/sbin/cron
  120     1 eleve      0.1  1.2 -bash
  450   120 eleve    145.2 85.0 python3 marees.py
  451   120 eleve      0.0  0.1 ps -eo pid,ppid,user,%cpu,%mem,args

Exemple : la ligne de cron a pour PPID 1 : cron a été créé par le processus 1, /sbin/init.

À ton tour : quel est le processus parent de python3 marees.py ? Donne son nom ou son PID.

Le PPID de 450 est 120 : c'est bash, le terminal depuis lequel eleve a lancé le calcul.

Erreur fréquente : /sbin/init : le processus 1 est le parent de bash : c'est le « grand-parent » de 450. Lis le PPID de la ligne 450.

Erreur fréquente : 450 : 450 est le PID du calcul lui-même ; son parent est dans la colonne PPID.

À ton tour : donne les PID de tous les processus créés par bash (PID 120).

450 et 451 : ce sont les deux lignes dont le PPID vaut 120.

Erreur fréquente : 450 : il y en a un autre : regarde toutes les lignes dont le PPID vaut 120.

Erreur fréquente : 1 98 : ce sont les processus créés par le processus 1 (leur PPID vaut 1).

Quel est le rôle du processus 1 (/sbin/init, souvent appelé systemd) ?

  • L'ancêtre de tous les processus : il lance les services
  • Le premier programme ouvert par l'utilisateur·rice
  • Il mesure la consommation du processeur
  • Un enfant de bash, qui l'a lancé

Le processus 1 (init, souvent systemd) est lancé par le noyau au démarrage : c'est l'ancêtre de tous les processus. Il démarre et surveille les services.

« Le premier programme ouvert par l'utilisateur·rice » : non. Le processus 1 est lancé par le noyau, au démarrage, avant toute connexion.

« Il mesure la consommation du processeur » : non. Il consomme 0.0 % : il ne mesure rien, il organise.

« Un enfant de bash, qui l'a lancé » : non. Son PPID est 0 : il n'a pas de processus parent, c'est le noyau qui le lance.

Quel est le rôle du processus 1 (/sbin/init, souvent appelé systemd) ?

Le processus 1 (init, souvent systemd) est lancé par le noyau au démarrage : c'est l'ancêtre de tous les processus. Il démarre et surveille les services.

Pourquoi la commande ps apparaît-elle dans sa propre liste ?

  • C'est un processus elle aussi, lancé par bash
  • C'est une erreur d'affichage de la commande ps
  • Elle reste lancée en permanence, comme cron
  • Elle a été lancée par le processus 1, au démarrage

Pendant qu'elle construit la liste, ps est un programme en cours d'exécution : un processus, créé par bash (PPID 120). Elle s'arrête juste après.

« C'est une erreur d'affichage de la commande ps » : non. Ce n'est pas une erreur : pendant qu'elle s'exécute, ps est un processus comme les autres.

« Elle reste lancée en permanence, comme cron » : non. ps s'arrête dès que la liste est affichée : elle n'apparaît que dans sa propre liste.

« Elle a été lancée par le processus 1, au démarrage » : non. Son PPID est 120 : elle a été lancée par bash.

Le processus 450 utilise 145.2 % du processeur. Comment est-ce possible ?

  • Il utilise plusieurs cœurs à la fois
  • C'est une erreur d'affichage de la commande
  • Il compte aussi la mémoire vive utilisée
  • Il fait tourner le processeur plus vite

Ici, 100 % correspond à un cœur entier. 145.2 % : le calcul utilise plusieurs cœurs du processeur en même temps.

« C'est une erreur d'affichage de la commande » : non. Ce n'est pas une erreur : ps compte en pourcentage d'un cœur.

« Il compte aussi la mémoire vive utilisée » : non. La mémoire est dans la colonne %MEM : %CPU parle du processeur.

« Il fait tourner le processeur plus vite » : non. Un processeur ne dépasse pas sa vitesse : c'est le nombre de cœurs qui compte.

Le processus 450 occupe 85 % de la mémoire vive. Si elle est pleine, quel mécanisme prend le relais ?

  • La zone d'échange (swap) sur le disque
  • La mémoire cache, à l'intérieur du processeur
  • La mémoire morte (ROM) de la carte mère
  • La corbeille, que le système vide alors

La zone d'échange, le swap : une partie du disque sert de mémoire, plus lente que la RAM.

« La mémoire cache, à l'intérieur du processeur » : non. Le cache est une toute petite mémoire du processeur, pas une réserve quand la RAM est pleine.

« La mémoire morte (ROM) de la carte mère » : non. La mémoire morte ne s'écrit pas pendant l'exécution des programmes.

« La corbeille, que le système vide alors » : non. Le système n'efface pas les fichiers pour libérer la mémoire.

2. Le joker et le tube

Exemple : dans nsi, ls *.py affiche tp1.py : tous les fichiers qui finissent par .py.

À ton tour : que fait rm *.tmp ?

  • Supprimer les fichiers .tmp du répertoire courant
  • Supprimer le fichier nommé exactement *.tmp
  • Lister les fichiers temporaires du répertoire
  • Supprimer les fichiers .tmp de tout le disque

*.tmp désigne tous les fichiers du répertoire courant qui finissent par .tmp : rm les supprime tous, sans corbeille.

« Supprimer le fichier nommé exactement *.tmp » : non. Le * est un joker : il ne fait pas partie d'un nom de fichier.

« Lister les fichiers temporaires du répertoire » : non. rm supprime : il ne liste rien.

« Supprimer les fichiers .tmp de tout le disque » : non. Sans -r, rm ne descend pas dans les sous-dossiers : seulement le répertoire courant.

Exemple : cat tp1.py | grep barge : cat envoie tout le fichier dans le tube, et grep n'en garde que les lignes qui contiennent barge.

À ton tour : que fait history | grep cp ?

  • Afficher les commandes tapées contenant cp
  • Copier l'historique dans un fichier nommé grep
  • Afficher toutes les commandes déjà tapées
  • Relancer la dernière commande cp tapée

history envoie la liste des commandes déjà tapées dans le tube ; grep cp n'en garde que les lignes qui contiennent cp.

« Copier l'historique dans un fichier nommé grep » : non. Copier, ce serait la commande cp : ici, cp est le motif cherché par grep.

« Afficher toutes les commandes déjà tapées » : non. grep fait un tri : seules restent les lignes qui contiennent cp.

« Relancer la dernière commande cp tapée » : non. Rien n'est relancé : la commande affiche seulement des lignes.

À ton tour : complète la commande pour n'afficher, dans la liste des processus, que les lignes qui contiennent marees.

ps -ef | grep marees : ps -ef envoie la liste dans le tube, grep garde les lignes qui contiennent marees. (La ligne du grep lui-même apparaît souvent aussi : il contient le mot cherché.)

Erreur fréquente : grep marees ps : après un tube, grep lit ce qui arrive de la gauche : on ne lui donne pas de fichier.

Erreur fréquente : find marees : find cherche des fichiers sur le disque, pas des lignes.
