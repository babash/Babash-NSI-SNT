1. Navigation et déplacements

L'arborescence : / (la racine) contient home, qui contient nsi, qui contient trois dossiers : TP1, Projets et Images. Le fichier web.html est dans Projets. Pour chaque situation, la commande pwd dit où tu es.

Tu es dans /home/nsi/TP1. Va dans le dossier Projets, avec un chemin relatif.

Projets n'est pas dans TP1 : il faut d'abord remonter au dossier parent.

Ce chemin est absolu (il commence par /). On demande un chemin relatif.

Projets et TP1 sont dans le même dossier, nsi : on remonte avec ...

cd ../Projets : .. remonte dans nsi, puis on descend dans Projets.

Tu es dans /home/nsi/Projets. Va dans /home/nsi, avec un chemin absolu.

C'est juste, mais .. est un chemin relatif. On demande un chemin absolu, qui part de /.

Un chemin absolu commence par /.

cd /home/nsi : le chemin part de la racine. (cd .. marche aussi, mais c'est un chemin relatif.)

Tu es dans /home/nsi/TP1. Liste le contenu du dossier Images.

Images n'est pas dans TP1 : il faut remonter d'un cran.

ls, puis le chemin du dossier à lister.

ls ../Images (ou, en absolu, ls /home/nsi/Images).

Tu es dans /home/nsi/Projets. Copie web.html dans le dossier TP1.

mv déplace le fichier : il disparaîtrait de Projets. On veut une copie.

cp source destination ; TP1 est à côté de Projets.

cp web.html ../TP1/ : la source est dans le dossier courant, la destination est TP1, à côté.

Tu es dans /home/nsi. Crée un dossier Archives dans TP1.

Ce dossier serait créé dans nsi, pas dans TP1.

touch crée un fichier ; pour un dossier, c'est mkdir.

mkdir, puis le chemin du nouveau dossier.

mkdir TP1/Archives : chemin relatif, depuis nsi.

2. Gestion des processus

Voici un extrait de la commande top (l'activité du système) :

PID  PPID  USER  %CPU   %MEM   COMMAND
1    0     root  0.0    0.1    systemd
120  1     nsi   0.1    1.2    bash
450  120   nsi   145.2  85.0   python3 calcul_fou.py

Quel est le rôle du processus de PID 1 (systemd) au démarrage du système ?

  • C'est l'ancêtre de tous les processus : il initialise le système et lance les services.
  • C'est le premier programme ouvert par l'utilisateur.
  • Il mesure la consommation du processeur.
  • C'est un enfant de bash.

Regarde son PPID (0), et qui a pour parent le PID 1.

systemd (le processus init) est lancé par le noyau au démarrage : c'est l'ancêtre de tous les processus. Il initialise le système, lance et surveille les services.

Quel est le rôle du processus de PID 1 (systemd) au démarrage du système ?

C'est le processus « ancêtre » (init) : il initialise le système et gère tous les autres services.

Le processus 450 affiche 145.2 % de CPU. Comment peut-on dépasser 100 % ?

  • Il utilise plusieurs cœurs du processeur en même temps : 100 % correspond à un cœur.
  • C'est une erreur d'affichage de top.
  • Il utilise aussi la mémoire vive.
  • Il fait tourner le processeur plus vite que prévu.

Un processeur moderne a plusieurs cœurs.

Pour top, 100 % correspond à un cœur entier. 145,2 % : le processus utilise plusieurs cœurs en même temps (il est multi-tâche, en plusieurs fils d'exécution).

Le processus 450 affiche 145.2 % de CPU. Comment est-il possible de dépasser les 100 % ?

Il utilise plusieurs cœurs du processeur en même temps : 100 % correspond à un seul cœur.

Si la mémoire vive (RAM) est pleine, quel mécanisme du système prend le relais pour éviter le plantage ?

  • La mémoire cache du processeur.
  • L'espace d'échange (le swap) : une partie du disque sert de mémoire.
  • La mémoire morte (ROM).
  • La corbeille, qui libère de la place.

Le système range temporairement des données sur le disque, plus lent mais plus grand.

La partition (ou le fichier) d'échange, le swap : une mémoire virtuelle sur le disque, plus lente que la RAM.

Si la mémoire vive (RAM) est pleine, quel mécanisme du système prend le relais pour éviter le plantage ?

L'espace d'échange, le swap : une mémoire virtuelle sur le disque.

Quel est le processus parent du processus 450 ? Donne son nom ou son PID.

systemd est le parent de bash (le grand-parent de 450). Lis le PPID de la ligne 450.

La colonne PPID donne le PID du parent.

Le PPID de 450 est 120 : c'est bash, le shell depuis lequel le script a été lancé.

Écris la commande qui force l'arrêt immédiat du script calcul_fou.py.

kill seul demande gentiment l'arrêt : le processus peut refuser. Pour forcer, ajoute le signal 9.

kill attend un numéro de processus (PID), pas un nom de fichier.

kill attend le PID du processus. Pour un arrêt forcé : le signal -9.

kill -9 450 : le signal SIGKILL arrête le processus tout de suite, sans lui laisser le temps de sauvegarder.

3. Droits et permissions

Le résultat de ls -l :

-rwxrw-r-- 1 nsi profs 420 mars 16 20:00 script.sh

Quels sont les droits du groupe profs sur ce fichier ?

  • Lecture, écriture et exécution (rwx).
  • Lecture et écriture (rw-).
  • Lecture seulement (r--).
  • Aucun droit.

Après le premier caractère, les droits vont par trois : propriétaire, groupe, autres.

- (un fichier), rwx (propriétaire nsi), rw- (groupe profs), r-- (autres). Le groupe peut lire et écrire, mais pas exécuter.

Écris la commande, en octal, qui donne tous les droits à tout le monde sur script.sh.

666 donne lecture et écriture, sans l'exécution : il manque x = 1.

Tous les droits : r + w + x = 4 + 2 + 1, pour chacun des trois.

chmod 777 script.sh : 7 = 4 + 2 + 1 = rwx, pour le propriétaire, le groupe et les autres.

Écris la commande, en mode relatif, qui ajoute le droit d'exécution aux autres (Others).

+x seul l'ajoute à tout le monde. Précise pour qui : o pour les autres.

g désigne le groupe. Les autres, c'est o.

Qui (u, g ou o), puis +, puis le droit.

chmod o+x script.sh : o (others), + (ajouter), x (exécution). Les droits deviennent -rwxrw-r-x.

Que fait la commande chmod 640 secret.txt ?

  • Propriétaire : rw- ; groupe : r-- ; autres : ---.
  • Propriétaire : rwx ; groupe : r-- ; autres : ---.
  • Propriétaire : --- ; groupe : r-- ; autres : rw-.
  • Propriétaire : rw- ; groupe : rw- ; autres : r--.

6 = 4 + 2, 4 = 4, 0 = rien.

6 = rw- pour le propriétaire, 4 = r-- pour le groupe, 0 = --- pour les autres : le fichier n'est lisible que par son propriétaire et son groupe.

4. Commandes combinées

Explique ce que cherchent à faire ces utilisateur·rices. Indice : | transmet le résultat de la commande de gauche à la commande de droite.

Que fait rm *.tmp ?

  • Elle supprime le fichier nommé *.tmp.
  • Elle supprime tous les fichiers du répertoire courant dont le nom finit par .tmp.
  • Elle liste les fichiers temporaires.
  • Elle supprime tous les fichiers .tmp de l'ordinateur.

* remplace n'importe quelle suite de caractères.

*.tmp désigne tous les fichiers du répertoire courant qui finissent par .tmp : rm les supprime tous, sans corbeille.

Explique avec tes mots ce que fait rm *.tmp.

Elle supprime tous les fichiers du répertoire courant dont le nom finit par .tmp.

Que fait cat notes.txt | grep "NSI" ?

  • Elle affiche tout le fichier notes.txt.
  • Elle écrit « NSI » dans notes.txt.
  • Elle lit notes.txt et n'affiche que les lignes qui contiennent « NSI ».
  • Elle compte les mots « NSI » de notes.txt.

cat envoie le contenu du fichier ; grep filtre les lignes.

cat envoie le contenu de notes.txt dans le tube | ; grep "NSI" ne garde que les lignes qui contiennent NSI.

Explique avec tes mots ce que fait cat notes.txt | grep "NSI".

Elle lit le fichier notes.txt et n'affiche que les lignes qui contiennent le mot NSI.

Mémo

kill -9 PID force l'arrêt d'un processus. Droits : r = 4, w = 2, x = 1, dans l'ordre propriétaire, groupe, autres ; chmod o+x ajoute un droit.

* : n'importe quelle suite de caractères. | : la sortie de gauche devient l'entrée de droite.
