Commandes Linux (terminale)

Les numéros sont les mêmes sur papier et à l'écran. En ligne, la page dit si c'est juste ; après un essai faux prévu, elle pose une question (ci-dessous, « la page demande ») ; la correction vient après deux essais.

Feuille 1 : Rappels de première

1. Les commandes de base

1. Que fait ls [dossier] ? Exemple : ls · ls ..

ls (list) liste le contenu du répertoire courant, ou du dossier indiqué : ls .. liste le parent.

« Afficher le contenu d'un fichier » : non. Afficher un fichier, c'est cat.

« Afficher le chemin du dossier » : non. Afficher le chemin, c'est pwd.

« Effacer l'écran du terminal » : non. ls n'efface rien : il affiche une liste de noms.

2. Que fait cd [chemin] ? Exemple : cd projets

cd (change directory) change de répertoire courant : on se déplace dans l'arborescence.

« Créer le dossier indiqué, vide » : non. Créer un dossier, c'est mkdir.

« Copier le dossier indiqué » : non. Copier, c'est cp.

« Lister le contenu du dossier indiqué » : non. Lister, c'est ls.

3. Que fait cat [fichier] ? Exemple : cat tp1.py

cat affiche tout le contenu d'un fichier dans le terminal.

« Afficher le nom des fichiers du dossier » : non. Les noms, c'est ls.

« Chercher un mot à l'intérieur d'un fichier » : non. Chercher un mot, c'est grep.

« Créer un fichier, puis l'ouvrir » : non. Créer un fichier vide, c'est touch ; cat n'ouvre aucun éditeur.

4. Que fait man [commande] ? Exemple : man ls

man affiche le manuel d'une commande (on en sort avec la touche q).

« Exécuter une commande en tant que root » : non. C'est sudo.

« Afficher l'utilisateur·rice connecté·e » : non. C'est whoami.

« Interrompre une commande bloquée » : non. C'est la touche Ctrl+C.

5. Que fait mkdir [dossier] ? Exemple : mkdir archives

mkdir (make directory) crée un dossier.

« Créer un fichier vide » : non. Un fichier vide, c'est touch.

« Supprimer un dossier » : non. Supprimer un dossier vide, c'est rmdir.

« Aller dans un dossier » : non. Se déplacer, c'est cd.

6. Que fait cp [source] [destination] ? Exemple : cp notes.csv projets/

cp (copy) copie la source vers la destination : l'original reste à sa place.

« Déplacer, sans garder l'original » : non. Si l'original disparaît, c'est mv.

« Renommer le fichier indiqué » : non. Renommer, c'est mv.

« Comparer les deux fichiers » : non. cp ne compare rien : il fabrique une copie.

7. Que fait mv [source] [destination] ? Exemple : mv nsi ../archives/

mv (move) déplace ou renomme : l'original quitte sa place.

« Copier, en gardant l'original » : non. Garder l'original, c'est cp.

« Supprimer un fichier » : non. C'est rm.

« Créer la destination » : non. Créer un dossier, c'est mkdir.

8. Que fait rm [fichier] ? Exemple : rm brouillon.txt

rm (remove) supprime un fichier, définitivement.

« Mettre un fichier à la corbeille » : non. Il n'y a pas de corbeille dans le terminal : le fichier est perdu.

« Vider un fichier, sans le supprimer » : non. rm ne garde rien : le fichier disparaît.

« Renommer un fichier » : non. C'est mv.

9. Que fait rm -r [dossier] ? Exemple : rm -r archives

rm -r (récursif) supprime un dossier et tout ce qu'il contient, sans corbeille.

« Supprimer un dossier, s'il est vide » : non. Un dossier vide seulement, c'est rmdir.

« Renommer un dossier et son contenu » : non. Renommer, c'est mv.

« Vider un dossier, en le gardant » : non. rm -r supprime aussi le dossier lui-même.

15. Quelle est l'arborescence sous /home/eleve après ces commandes ?

Le dossier nsi (avec tp1.py) est passé de devoirs à archives :

eleve/
|-- archives/
|   `-- nsi/
|       `-- tp1.py
|-- devoirs/
`-- projets/

« devoirs/ contient archives/, qui contient nsi/ ; projets/ » : non. mkdir archives est tapé depuis /home/eleve, avant cd devoirs : archives est créé à côté de devoirs.

« archives/ contient nsi/ ; devoirs/ contient nsi/ ; projets/ » : non. mv déplace : nsi n'est plus dans devoirs (garder l'original, c'est cp).

« archives/ est vide ; devoirs/ contient nsi/ ; projets/ » : non. Depuis devoirs, ../archives désigne /home/eleve/archives : le déplacement a bien eu lieu.

16. À ton tour : après ces commandes, on tape la commande ci-dessous depuis /home/eleve. Pourquoi ce refus ?

rmdir ne supprime qu'un dossier vide : archives contient nsi (et tp1.py), d'où « Directory not empty ».

« eleve n'a pas le droit de supprimer archives » : non. archives est à eleve, dans son dossier : le message parle d'un dossier « pas vide ».

« Il faut écrire rmdir archives/ » : non. Le / final ne change rien : le message dit pourquoi le dossier reste.

« rmdir ne supprime que les fichiers » : non. rmdir supprime des dossiers, mais seulement s'ils sont vides.

3. Les droits

18. À ton tour : quels droits le groupe info a-t-il sur notes.csv ?

- (un fichier), rw- (le propriétaire, prof), r-- (le groupe, info), --- (les autres) : le groupe peut lire le fichier, pas le modifier.

« Lire et écrire (rw-) » : non. rw- sont les droits du propriétaire, prof : les trois premières lettres après le tiret.

« Aucun droit (---) » : non. --- sont les droits des autres : les trois dernières lettres.

« Lire et exécuter (r-x) » : non. Il n'y a aucun x dans -rw-r----- : personne ne peut l'exécuter.

19. À ton tour : tu es dans nsi. En octal, rends tp1.py lisible et modifiable par son propriétaire (toi), sans aucun droit ni pour le groupe ni pour les autres.

chmod 600 tp1.py : 6 = 4 + 2 (rw-) pour le propriétaire, 0 (---) pour le groupe et pour les autres.

Acceptées en ligne : 8 écritures, dont chmod 600 ./tp1.py, chmod 600 /home/eleve/devoirs/nsi/tp1.py, chmod 600 ~/devoirs/nsi/tp1.py, chmod 0600 tp1.py.

Après chmod 006 tp1.py (et 7 autres), la page demande : « Dans quel ordre se lisent les trois chiffres ? »

Après chmod 644 tp1.py (et 19 autres), la page demande : « Le groupe et les autres doivent-ils garder un droit ? »

Après chmod 600 (et 1 autres), la page demande : « Qu'écrit-on après chmod : les droits, puis quoi ? »

Après chmod u=rw,go= tp1.py (et 11 autres), la page demande : « C'est du symbolique : on demande l'octal, avec des chiffres. »

20. À ton tour : en symbolique, ajoute le droit d'exécution au propriétaire de tp1.py (tu es dans nsi), sans changer les autres droits.

chmod u+x tp1.py : u (user, le propriétaire), + (ajouter), x (exécution).

Acceptées en ligne : 4 écritures, dont chmod u+x ./tp1.py, chmod u+x /home/eleve/devoirs/nsi/tp1.py, chmod u+x ~/devoirs/nsi/tp1.py.

Après chmod +x tp1.py (et 11 autres), la page demande : « À qui ton +x donne-t-il le droit ? Avec quelle lettre désigne-t-on le seul propriétaire ? »

Après chmod x+u tp1.py (et 11 autres), la page demande : « Dans quel ordre écrit-on : qui, le signe, le droit ? »

Après chmod 700 tp1.py (et 15 autres), la page demande : « C'est de l'octal, et il change aussi d'autres droits : on demande le symbolique. »

Après chmod U+x tp1.py (et 7 autres), la page demande : « Les majuscules comptent : comment s'écrivent u et x ? »

Feuille 2 : Les processus

1. Les commandes

22. Que fait ps -ef ? Exemple : ps -ef

ps (process status) liste les processus ; ps -ef les montre tous, avec leur PID et leur PPID.

« Lister les fichiers du dossier » : non. C'est ls.

« Arrêter les processus en cours » : non. Arrêter un processus, c'est kill : ps affiche seulement.

« Afficher la place libre du disque » : non. ps parle des processus, pas du disque.

23. Que fait kill [PID] ? Exemple : kill 450

kill envoie un signal au processus dont on donne le PID, pour qu'il s'arrête ; kill -9 le force.

« Supprimer le fichier numéro 450 » : non. 450 est un PID : le numéro d'un processus.

« Éteindre l'ordinateur tout de suite » : non. kill vise un seul processus, celui du PID.

« Afficher les infos du processus » : non. Afficher les processus, c'est ps.

24. Que fait le tube | ? Exemple : ps -ef | grep cron

Le tube | envoie ce qu'affiche la commande de gauche à la commande de droite : ici, grep cron ne garde que les lignes de ps -ef qui contiennent cron.

« Lancer les deux commandes ensemble » : non. Elles ne sont pas indépendantes : celle de droite lit ce qu'affiche celle de gauche.

« Enregistrer la sortie dans un fichier » : non. Enregistrer dans un fichier, c'est >.

« Lancer la droite si la gauche réussit » : non. C'est &&.

25. Que fait ping [machine] ? Exemple : ping 8.8.8.8

ping envoie de petits paquets à une machine et attend leur retour : il dit si elle répond, et en combien de millisecondes.

« Afficher ses propres adresses IP » : non. C'est ip addr.

« Envoyer un message à la machine » : non. ping n'envoie aucun message lisible : un petit paquet, qui revient.

« Télécharger un fichier de la machine » : non. ping ne transfère aucun fichier.

28. À ton tour : quel est l'arbre des processus de l'extrait ?

On relie chaque ligne à son PPID : 98 et 105 à 1 ; 118 à 105 ; 120 à 118 ; 450 et 451 à 120.

1 (init)
|-- 98 (cron)
`-- 105 (sshd)
    `-- 118 (sshd: eleve)
        `-- 120 (-bash)
            |-- 450 (python3)
            `-- 451 (ps -ef)

Les autres arbres relient un processus à un ancêtre (118 et 120 à 1, ou à 105), ou font de ps -ef un enfant du calcul (son PPID est 120).

29. Pourquoi la commande ps -ef apparaît-elle dans sa propre liste ?

Pendant qu'elle construit la liste, ps -ef est un programme en cours d'exécution : un processus, créé par -bash (PPID 120). Elle s'arrête juste après.

« C'est une erreur d'affichage de la commande » : non. Pendant qu'elle s'exécute, ps est un processus comme les autres.

« Elle reste lancée en permanence, comme cron » : non. ps s'arrête dès que la liste est affichée.

« Elle a été lancée par le processus 1, au démarrage » : non. Son PPID est 120 : elle a été lancée par -bash.
