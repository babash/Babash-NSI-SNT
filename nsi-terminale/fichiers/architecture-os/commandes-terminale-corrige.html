Corrigé de l'enseignant·e · Tle NSI · Systèmes d'exploitation

Commandes Linux (terminale)

Les numéros sont ceux des feuilles papier. En ligne, chaque question se corrige toute seule : la page dit si c'est juste, puis propose la correction après deux essais. Ce corrigé est fait par un script à partir des feuilles (source/faire-corrige.py) : il ne peut pas en diverger.

Feuille 1 : Rappels et outils

1. Rappels : se déplacer, copier, créer

Question 1. Depuis /home/eleve/devoirs, va dans projets (chemin relatif).

cd ../projets : .. remonte dans eleve, puis on descend dans projets.

Erreur fréquente : cd projets ou cd projets/ : projets n'est pas dans devoirs : il faut d'abord remonter au parent.

Erreur fréquente : cd /home/eleve/projets ou cd ~/projets : ce chemin part de la racine (ou de ~) : on demande un chemin relatif, qui part de devoirs.

Acceptées en ligne : cd ../projets · cd ../projets/ · cd ./../projets

Question 2. Depuis /home/eleve/projets, va dans /home/eleve (chemin absolu).

cd /home/eleve : le chemin part de la racine. (cd .. et cd ~ y mènent aussi, mais ce ne sont pas des chemins absolus écrits en entier.)

Erreur fréquente : cd .. ou cd ../ : c'est juste, mais .. est un chemin relatif. On demande un chemin absolu, qui part de /.

Erreur fréquente : cd ~ ou cd : c'est juste, mais ~ est un raccourci : écris le chemin absolu en entier.

Acceptées en ligne : cd /home/eleve · cd /home/eleve/

Question 3. Depuis /home/eleve/devoirs, liste le contenu de photos.

ls ../photos (ou, en chemin absolu, ls /home/eleve/photos) : la commande affiche lagon.png.

Erreur fréquente : ls photos ou ls photos/ : photos n'est pas dans devoirs : il faut remonter d'un cran.

Erreur fréquente : cd ../photos : cette commande te déplace, sans rien afficher. Pour voir le contenu, c'est une autre commande.

Acceptées en ligne : ls ../photos · ls ../photos/ · ls /home/eleve/photos · ls /home/eleve/photos/ · ls ~/photos · ls ~/photos/

Question 4. Depuis /home/eleve/projets, copie site.html dans devoirs.

cp site.html ../devoirs/ : la source est dans le répertoire courant ; la destination, devoirs, est à côté de projets.

Erreur fréquente : mv site.html ../devoirs/ ou mv site.html ../devoirs : mv déplace : site.html disparaîtrait de projets. On veut une copie.

Erreur fréquente : cp site.html devoirs : devoirs n'est pas dans projets : cette commande crée, dans projets, une copie nommée devoirs.

Acceptées en ligne : cp site.html ../devoirs/ · cp site.html ../devoirs · cp site.html ../devoirs/site.html · cp site.html /home/eleve/devoirs/ · cp site.html /home/eleve/devoirs · cp site.html ~/devoirs/ · cp site.html ~/devoirs

Question 5. Depuis /home/eleve, crée un dossier archives dans devoirs.

mkdir devoirs/archives : chemin relatif, depuis eleve.

Erreur fréquente : mkdir archives : ce dossier serait créé dans eleve, pas dans devoirs.

Erreur fréquente : touch devoirs/archives : touch crée un fichier ; pour un dossier, c'est mkdir.

Acceptées en ligne : mkdir devoirs/archives · mkdir devoirs/archives/ · mkdir ./devoirs/archives · mkdir /home/eleve/devoirs/archives · mkdir ~/devoirs/archives

2. Rappels : la bonne commande

Question 6. Quelle commande affiche tout le contenu d'un fichier ?

cat (more et less le montrent aussi, page par page).

Erreur fréquente : ls : ls affiche le nom des fichiers, pas ce qu'ils contiennent.

Acceptées en ligne : cat · more · less

Question 7. Quelle commande supprime un dossier vide ?

rmdir : il refuse un dossier qui n'est pas vide, c'est le plus sûr.

Erreur fréquente : rm : rm seul refuse de supprimer un dossier (« Is a directory »).

Erreur fréquente : rm -r : rm -r marche, mais il efface aussi tout ce que contient le dossier : pour un dossier vide, rmdir est plus sûr.

Question 8. Quelle commande affiche les lignes d'un fichier qui contiennent un mot ?

grep : grep print tp1.py.

Erreur fréquente : find : find cherche des fichiers par leur nom, pas dans leur contenu.

Erreur fréquente : cat : cat affiche tout le fichier, sans trier les lignes.

Question 9. Quelle commande affiche le manuel d'une commande ?

man : man ls (on en sort avec la touche q).

Erreur fréquente : help : help donne une aide courte sur quelques commandes du shell ; le manuel complet, c'est man.

3. Rappels : les droits

Question 10. À ton tour : quels droits le groupe nsi a-t-il sur tp1.py ?

- (un fichier), rwx (propriétaire eleve), rw- (groupe nsi), r-- (autres) : le groupe peut lire et écrire, pas exécuter.

« Lire, écrire et exécuter (rwx) » : non. rwx sont les droits du propriétaire, eleve : les trois premiers après le tiret.

« Lire seulement (r--) » : non. r-- sont les droits des autres : les trois derniers.

« Lire et exécuter (r-x) » : non. le groupe n'a pas x : sa troisième lettre est un tiret.

Question 11. À ton tour : tu es dans nsi. En octal, donne tous les droits à tout le monde sur tp1.py.

chmod 777 tp1.py : 7 = 4 + 2 + 1 = rwx, pour le propriétaire, le groupe et les autres.

Erreur fréquente : chmod 666 tp1.py : 666 donne lire et écrire, sans exécuter : il manque x = 1.

Erreur fréquente : chmod a+rwx tp1.py ou chmod ugo+rwx tp1.py : c'est juste, mais en symbolique. On demande l'octal.

Acceptées en ligne : chmod 777 tp1.py · chmod 0777 tp1.py · chmod 777 ./tp1.py

Question 12. À ton tour : en symbolique, ajoute le droit d'exécution aux autres (others) sur tp1.py.

chmod o+x tp1.py : o (les autres), + (ajouter), x (exécuter). Les droits deviennent -rwxrw-r-x.

Erreur fréquente : chmod +x tp1.py ou chmod a+x tp1.py : sans lettre (ou avec a), le droit est ajouté à tout le monde. Les autres, c'est o.

Erreur fréquente : chmod g+x tp1.py : g désigne le groupe. Les autres, c'est o.

Acceptées en ligne : chmod o+x tp1.py · chmod o+x ./tp1.py

4. Nouveau : observer la machine

Question 13. Complète la colonne « Ce qu'elle fait ». La première ligne est faite : c'est l'exemple.

history : afficher les commandes déjà tapées.

ps (process status) : lister les processus en cours d'exécution.

top : afficher les processus en temps réel, ceux qui consomment le plus en haut.

kill : envoyer un signal à un processus, pour l'arrêter.

df -h (disk free) : afficher la place libre sur les disques, en Go et Mo.

ip addr : afficher les adresses IP de la machine et ses cartes réseau.

ping : tester si une autre machine répond sur le réseau.

Feuille 2 : Processus et tubes

1. Les processus

Question 14. À ton tour : quel est le processus parent de python3 marees.py ? Donne son nom ou son PID.

Le PPID de 450 est 120 : c'est bash, le terminal depuis lequel eleve a lancé le calcul.

Erreur fréquente : /sbin/init ou 1 ou init : le processus 1 est le parent de bash : c'est le « grand-parent » de 450. Lis le PPID de la ligne 450.

Erreur fréquente : 450 : 450 est le PID du calcul lui-même ; son parent est dans la colonne PPID.

Acceptées en ligne : bash · -bash · 120 · bash (120) · 120 (bash) · -bash (120) · bash, 120 · le processus bash · bash, pid 120 · pid 120

Question 15. À ton tour : donne les PID de tous les processus créés par bash (PID 120).

450 et 451 : ce sont les deux lignes dont le PPID vaut 120.

Erreur fréquente : 450 : il y en a un autre : regarde toutes les lignes dont le PPID vaut 120.

Erreur fréquente : 1 98 ou 98 : ce sont les processus créés par le processus 1 (leur PPID vaut 1).

Acceptées en ligne : 450 451 · 450 et 451 · 450, 451 · 450,451 · 451 450 · 451 et 450 · 451, 450 · 450 ; 451

Question 16. Quel est le rôle du processus 1 (/sbin/init, souvent appelé systemd) ?

Le processus 1 (init, souvent systemd) est lancé par le noyau au démarrage : c'est l'ancêtre de tous les processus. Il démarre et surveille les services.

« Le premier programme ouvert par l'utilisateur·rice » : non. Le processus 1 est lancé par le noyau, au démarrage, avant toute connexion.

« Il mesure la consommation du processeur » : non. Il consomme 0.0 % : il ne mesure rien, il organise.

« Un enfant de bash, qui l'a lancé » : non. Son PPID est 0 : il n'a pas de processus parent, c'est le noyau qui le lance.

Question 17. Pourquoi la commande ps apparaît-elle dans sa propre liste ?

Pendant qu'elle construit la liste, ps est un programme en cours d'exécution : un processus, créé par bash (PPID 120). Elle s'arrête juste après.

« C'est une erreur d'affichage de la commande ps » : non. Ce n'est pas une erreur : pendant qu'elle s'exécute, ps est un processus comme les autres.

« Elle reste lancée en permanence, comme cron » : non. ps s'arrête dès que la liste est affichée : elle n'apparaît que dans sa propre liste.

« Elle a été lancée par le processus 1, au démarrage » : non. Son PPID est 120 : elle a été lancée par bash.

Question 18. Le processus 450 utilise 145.2 % du processeur. Comment est-ce possible ?

Ici, 100 % correspond à un cœur entier. 145.2 % : le calcul utilise plusieurs cœurs du processeur en même temps.

« C'est une erreur d'affichage de la commande » : non. Ce n'est pas une erreur : ps compte en pourcentage d'un cœur.

« Il compte aussi la mémoire vive utilisée » : non. La mémoire est dans la colonne %MEM : %CPU parle du processeur.

« Il fait tourner le processeur plus vite » : non. Un processeur ne dépasse pas sa vitesse : c'est le nombre de cœurs qui compte.

Question 19. Le processus 450 occupe 85 % de la mémoire vive. Si elle est pleine, quel mécanisme prend le relais ?

La zone d'échange, le swap : une partie du disque sert de mémoire, plus lente que la RAM.

« La mémoire cache, à l'intérieur du processeur » : non. Le cache est une toute petite mémoire du processeur, pas une réserve quand la RAM est pleine.

« La mémoire morte (ROM) de la carte mère » : non. La mémoire morte ne s'écrit pas pendant l'exécution des programmes.

« La corbeille, que le système vide alors » : non. Le système n'efface pas les fichiers pour libérer la mémoire.

Question 20. À ton tour : écris la commande qui force l'arrêt immédiat du calcul python3 marees.py.

kill -9 450 : le signal 9 (SIGKILL) arrête le processus 450 tout de suite.

Erreur fréquente : kill 450 : kill seul demande l'arrêt : un processus bloqué peut ne pas répondre. Pour forcer, ajoute le signal 9.

Erreur fréquente : kill -9 marees.py ou kill -9 python3 : kill attend un numéro de processus (PID), pas un nom.

Erreur fréquente : kill -9 120 : 120, c'est bash, le terminal : tu le fermerais. Le calcul a le PID 450.

Acceptées en ligne : kill -9 450 · kill -KILL 450 · kill -SIGKILL 450 · kill -s KILL 450 · kill -s 9 450 · kill -s SIGKILL 450 · sudo kill -9 450

2. Le joker et le tube

Question 21. À ton tour : explique ce que fait rm *.tmp.

*.tmp désigne tous les fichiers du répertoire courant qui finissent par .tmp : rm les supprime tous, sans corbeille.

« Supprimer le fichier nommé exactement *.tmp » : non. Le * est un joker : il ne fait pas partie d'un nom de fichier.

« Lister les fichiers temporaires du répertoire » : non. rm supprime : il ne liste rien.

« Supprimer les fichiers .tmp de tout le disque » : non. Sans -r, rm ne descend pas dans les sous-dossiers : seulement le répertoire courant.

Question 22. À ton tour : explique ce que fait history | grep cp.

history envoie la liste des commandes déjà tapées dans le tube ; grep cp n'en garde que les lignes qui contiennent cp.

« Copier l'historique dans un fichier nommé grep » : non. Copier, ce serait la commande cp : ici, cp est le motif cherché par grep.

« Afficher toutes les commandes déjà tapées » : non. grep fait un tri : seules restent les lignes qui contiennent cp.

« Relancer la dernière commande cp tapée » : non. Rien n'est relancé : la commande affiche seulement des lignes.

Question 23. À ton tour : complète la commande pour n'afficher, dans la liste des processus, que les lignes qui contiennent marees.

ps -ef | grep marees : ps -ef envoie la liste dans le tube, grep garde les lignes qui contiennent marees. (La ligne du grep lui-même apparaît souvent aussi : il contient le mot cherché.)

Erreur fréquente : grep marees ps : après un tube, grep lit ce qui arrive de la gauche : on ne lui donne pas de fichier.

Erreur fréquente : find marees ou find -name marees : find cherche des fichiers sur le disque, pas des lignes.

Acceptées en ligne : grep marees · grep "marees" · grep 'marees' · grep marees.py · grep "marees.py"
