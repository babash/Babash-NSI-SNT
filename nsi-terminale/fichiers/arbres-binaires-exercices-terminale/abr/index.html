2. Dessinons

On étudie l'arbre suivant :

arbre = [8, [3, [1, None, None], [6, [4, None, None], [7, None, None]]],
         [10, None, [14, [13, None, None], None]]]

Pour dessiner cet arbre, donne la racine, puis les deux enfants de chaque nœud (écris None s'il n'y a pas d'enfant).

racine = [[8]]
enfants_de_8 = ([[3]], [[10]])
enfants_de_3 = ([[1]], [[6]])
enfants_de_6 = ([[4]], [[7]])
enfants_de_10 = ([[None|none|aucun|rien]], [[14]])
enfants_de_14 = ([[13]], [[None|none|aucun|rien]])

La première valeur d'une liste est le nœud ; la deuxième est le sous-arbre gauche ; la troisième, le sous-arbre droit.

Dans [10, None, [14, …]], le sous-arbre gauche de 10 est None : 10 n'a qu'un enfant, à droite.

10 n'a pas d'enfant gauche, et 14 n'a pas d'enfant droit.

Cet arbre est-il un arbre binaire de recherche ?

  • Oui : pour chaque nœud, les valeurs à sa gauche sont plus petites, celles à sa droite plus grandes.
  • Oui : chaque nœud a au plus deux enfants, donc c'est un arbre binaire de recherche.
  • Non : 10 n'a qu'un enfant, alors qu'un nœud d'ABR doit en avoir deux.
  • Non : l'arbre n'est pas équilibré, une de ses branches est bien plus longue que l'autre.
  • Non : 13 est mal placé : il devrait se trouver à droite de 14, pas à sa gauche.

Pour chaque nœud, regarde tout son sous-arbre gauche (valeurs plus petites ?) et tout son sous-arbre droit (valeurs plus grandes ?).

Oui. À gauche de 8 : 1, 3, 4, 6, 7 (tous plus petits) ; à droite : 10, 13, 14 (tous plus grands). On vérifie de même pour 3, 6, 10 et 14.

Applique le parcours infixe à cet arbre : écris les valeurs dans l'ordre de visite, séparées par des virgules.

C'est le parcours préfixe (le nœud avant ses sous-arbres). En infixe, le nœud vient entre ses deux sous-arbres.

C'est le parcours suffixe (le nœud après ses sous-arbres). En infixe, le nœud vient entre ses deux sous-arbres.

Infixe : sous-arbre gauche, puis le nœud, puis sous-arbre droit. On commence donc par la feuille la plus à gauche.

1, 3, 4, 6, 7, 8, 10, 13, 14.

Que remarques-tu sur le résultat du parcours infixe ?

  • Les valeurs sont dans l'ordre croissant.
  • La racine est toujours en premier.
  • Les valeurs sont rangées niveau par niveau.
  • Il manque les feuilles.

Compare chaque valeur à la suivante.

Dans un ABR, le parcours infixe donne toujours les valeurs dans l'ordre croissant : tout le sous-arbre gauche (plus petit), puis le nœud, puis tout le sous-arbre droit (plus grand).

Que remarques-tu sur le résultat du parcours infixe ?

Les valeurs sont dans l'ordre croissant : c'est toujours le cas pour le parcours infixe d'un ABR.

3. À la recherche du logarithme

Complète la fonction qui insère element dans un arbre binaire de recherche. Si element est déjà dans l'arbre, la fonction s'arrête sans rien changer.

def insertionABRnr(arbre, element):
    arbre_suivant = arbre
    while arbre_suivant is not None:
        arbre = [[arbre_suivant]]
        if [[arbre[0] > element|element < arbre[0] ]]:
            arbre_suivant = arbre[1]
        elif [[arbre[0] < element|element > arbre[0] ]]:
            arbre_suivant = arbre[2]
        else:
            return
    if arbre[0] > element:
        arbre[1] = [ [[element, None, None]] ]
        print(element, 'ajouté à gauche de', arbre[0])
    if arbre[0] < element:
        arbre[2] = [ [[element, None, None]] ]
        print(element, 'ajouté à droite de', arbre[0])

Dans la boucle, on descend : arbre devient le nœud qu'on visite. On va à gauche si l'élément est plus petit que la valeur du nœud, à droite s'il est plus grand.

Après la boucle, arbre est le dernier nœud visité : on y accroche une nouvelle feuille, [element, None, None].

def insertionABRnr(arbre, element):
    arbre_suivant = arbre
    while arbre_suivant is not None:
        arbre = arbre_suivant
        if arbre[0] > element:
            arbre_suivant = arbre[1]
        elif arbre[0] < element:
            arbre_suivant = arbre[2]
        else:
            return
    if arbre[0] > element:
        arbre[1] = [element, None, None]
        print(element, 'ajouté à gauche de', arbre[0])
    if arbre[0] < element:
        arbre[2] = [element, None, None]
        print(element, 'ajouté à droite de', arbre[0])

Essai sur l'arbre de la partie 2 : insérer 5 affiche 5 ajouté à droite de 4 ; insérer 12 affiche 12 ajouté à gauche de 13. Si element est déjà dans l'arbre, le else arrête la fonction : sans lui, arbre_suivant ne changerait plus et la boucle ne s'arrêterait jamais.

La fonction insertionABRnr est-elle récursive ?

  • Non : elle descend avec une boucle while, sans s'appeler elle-même.
  • Oui : elle travaille sur un arbre, qui est une structure récursive.
  • Oui : elle répète des instructions tant que la place n'est pas trouvée.
  • Non : elle modifie la liste arbre, ce qu'une fonction récursive ne fait pas.

Une fonction récursive s'appelle elle-même. Cherche insertionABRnr( dans son corps.

Non (d'où « nr », non récursive) : elle utilise une boucle. Le nombre de tours est la hauteur de l'arbre : de l'ordre du logarithme en base 2 de n pour un arbre bien équilibré de n nœuds, d'où le titre de la partie.

Complète la fonction récursive qui renvoie True si element est dans l'arbre binaire de recherche, False sinon.

def rechercheABR(arbre, element):
    if arbre is None:
        [[return False]]
    else:
        if arbre[0] == element:
            return True
        if [[element < arbre[0]|arbre[0] > element]]:
            return [[rechercheABR(arbre[1], element)]]
        if [[element > arbre[0]|arbre[0] < element]]:

print(rechercheABR([8, [3, None, None], [10, None, None]], 10))
True

Un arbre vide ne contient rien. Si l'élément est plus petit que la racine, il ne peut être que dans le sous-arbre gauche.

L'appel récursif porte sur un sous-arbre : arbre[1] (gauche) ou arbre[2] (droit).

def rechercheABR(arbre, element):
    if arbre is None:
        return False
    else:
        if arbre[0] == element:
            return True
        if element < arbre[0]:
            return rechercheABR(arbre[1], element)
        if element > arbre[0]:
            return rechercheABR(arbre[2], element)

À chaque appel, on descend d'un niveau et on écarte tout un sous-arbre : on ne visite qu'un chemin, pas tout l'arbre.

Mémo

ABR : pour chaque nœud, plus petit à gauche, plus grand à droite. Le parcours infixe donne les valeurs triées.

Insérer ou chercher : on descend un seul chemin, à gauche ou à droite ; le coût est la hauteur de l'arbre.
