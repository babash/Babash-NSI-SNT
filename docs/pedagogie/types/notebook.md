# Le notebook (TP)

*La pratique sur machine, dans Capytale. Retour aux [types de ressources](../types-de-ressources.md).*

**En bref.** Un notebook mêle du texte et des cellules de code que l'élève exécute. C'est la forme des TP de l'auteur : il les distribue par Capytale, la plateforme de l'académie, accessible par l'ENT. Beaucoup se corrigent seuls. Chaque notebook du site se lit aussi en ligne, sans compte.

## À quoi ça sert

- **Pratiquer sur machine**, après le TD : exécuter, modifier, voir le résultat.
- **Recevoir un retour immédiat** : dans les notebooks auto-évalués, chaque réponse est vérifiée, avec plusieurs essais.
- **Libérer du temps de correction**, qui va au retour oral en classe.
- **Rien à installer** : tout se passe dans le navigateur.

## Comment s'en servir en classe

1. **Lis d'abord la page de lecture** du notebook sur le site : elle l'affiche sans compte et sans l'exécuter.
2. **Télécharge le fichier `.ipynb`** et importe-le dans Capytale (ou dans Basthon, sans compte).
3. **Joins les fichiers indiqués** sur la fiche : un module Python de validation, des images, des données. Sans eux, l'auto-évaluation ne marche pas.
4. **Distribue l'activité** à ta classe par Capytale ; sur Pronote, le TP est un lien vers Capytale.
5. **En binôme** sur un clavier si la salle l'impose : l'un·e tape, l'autre guide.
6. **Pour un contrôle**, retire d'abord les corrections présentes dans le notebook : la fiche te dit où elles sont.

## Les règles fondamentales

| La règle | Pourquoi |
|---|---|
| **Trois éléments par notebook** : le fichier `.ipynb`, une page de lecture, les fichiers à joindre | On peut lire avant d'importer, et tout est là pour que ça marche |
| **Les sorties sont vidées, et aucune donnée d'élève n'est dans le fichier** | Le dépôt est public |
| **Une première réussite rapide, des paliers courts** ; des indices repliés sous les questions | [Règles universelles](../regles-universelles.md#31-45-minutes-au-plus-une-réussite-dès-les-premières-minutes) |
| **La correction automatique quand c'est possible**, avec plusieurs essais | [Règles universelles](../regles-universelles.md#35-la-correction-automatique-chaque-fois-que-cest-possible) |
| **Tout le code est exécuté avant publication** | [Vérifié](../regles-universelles.md#41-vérifié--le-code-exécuté-les-faits-contrôlés-les-liens-testés) |
| **Chaque notebook garde sa licence et ses crédits**, écrits au pied de sa page et sur sa fiche | Plusieurs viennent de collègues, parfois sous une licence non commerciale |
| **La fiche dit ce que la plateforme demande** : un compte ENT pour Capytale | Le travail des élèves y est géré par Capytale, pas par ce site |

## Les exemples du site

- **[Faire des erreurs, c'est cool ! L'apprenti saboteur](https://babash.github.io/Babash-NSI-SNT/bibliotheque/?r=nsi-faire-des-erreurs)** (première) : pour chaque message d'erreur affiché, l'élève écrit le code le plus court qui le provoque. Il s'utilise avec la fiche « Déboguer en Python ».
- **[TP de programmation objet : le Pokédex](https://babash.github.io/Babash-NSI-SNT/bibliotheque/?r=tp-poo-pokedex)** (terminale) : lire une classe, créer des objets, écrire des méthodes. Une version auto-évaluée pour Capytale l'accompagne.
- **[Contrôle blanc auto-corrigé : les types construits](https://babash.github.io/Babash-NSI-SNT/bibliotheque/?r=nsi-types-construits-controle)** (première) : seize questions validées une à une, avec la note affichée.

Le site réunit 21 activités Capytale, de l'auteur et de collègues. Leur rangement dans le dépôt est décrit dans [L'organisation du dépôt](../../ORGANISATION.md#les-activités-capytale).

## Où on en est

Les notebooks sont tous dans la bibliothèque ; les rubriques du site n'en montrent encore que quelques-uns. Ceux qui s'ouvrent seulement par un lien Capytale demandent une connexion à l'ENT.
