Commandes Linux (première)

Les numéros sont les mêmes sur papier et à l'écran. En ligne, la page dit si c'est juste ; après un essai faux prévu, elle pose une question (ci-dessous, « la page demande ») ; la correction vient après deux essais.

Feuille 1 : Le terminal et l'arborescence

1. Navigation dans l'arborescence

1. Que fait pwd ? Exemple : pwd → /home/eleve/devoirs/nsi

pwd (print working directory) affiche le chemin absolu du répertoire courant.

« Changer de répertoire courant » : non. Changer de répertoire, c'est cd : pwd dit seulement où l'on est.

« Lister le contenu du répertoire » : non. Lister, c'est ls : pwd affiche un seul chemin.

« Afficher le mot de passe » : non. pwd veut dire print working directory, « affiche le répertoire de travail ».

2. Que fait ls [dossier] ? Exemple : ls · ls ..

ls (list) liste le contenu du répertoire courant, ou du dossier indiqué : ls .. liste le parent.

« Afficher le contenu d'un fichier » : non. Afficher un fichier, c'est cat.

« Afficher le chemin du dossier » : non. Afficher le chemin, c'est pwd.

« Effacer l'écran du terminal » : non. ls n'efface rien : il affiche une liste de noms.

3. Que fait cd [chemin] ? Exemple : cd projets

cd (change directory) change de répertoire courant : on se déplace dans l'arborescence.

« Créer le dossier indiqué, vide » : non. Créer un dossier, c'est mkdir.

« Copier le dossier indiqué » : non. Copier, c'est cp.

« Lister le contenu du dossier indiqué » : non. Lister, c'est ls.

4. Que fait cd .. ? Exemple : cd ../..

cd .. remonte d'un niveau, vers le dossier parent ; cd ../.. remonte de deux.

« Revenir au dossier personnel » : non. Le dossier personnel, c'est cd ~.

« Aller à la racine du système » : non. La racine, c'est cd /.

« Rester dans le dossier courant » : non. Un seul point, ., c'est le dossier courant ; deux points, le parent.

5. Que fait cd ~ ? Exemple : cd ~

cd ~ ramène dans le dossier personnel (ici /home/eleve), d'où que l'on soit.

« Aller à la racine du système » : non. La racine, c'est /.

« Remonter au dossier parent » : non. Le parent, c'est ...

« Rester dans le dossier courant » : non. Le dossier courant, c'est ..

2. Lecture de fichiers

6. Que fait cat [fichier] ? Exemple : cat tp1.py

cat affiche tout le contenu d'un fichier dans le terminal.

« Afficher le nom des fichiers du dossier » : non. Les noms, c'est ls.

« Chercher un mot à l'intérieur d'un fichier » : non. Chercher un mot, c'est grep.

« Créer un fichier, puis l'ouvrir » : non. Créer un fichier vide, c'est touch ; cat n'ouvre aucun éditeur.

7. Que fait grep [motif] [fichier] ? Exemple : grep print tp1.py

grep affiche les lignes du fichier qui contiennent le motif (le mot cherché).

« Afficher tout le fichier, ligne à ligne » : non. Tout afficher, c'est cat : grep trie les lignes.

« Remplacer le motif dans le fichier » : non. grep ne modifie jamais le fichier : il affiche.

« Chercher un fichier par son nom » : non. grep cherche dans le contenu d'un fichier, pas dans les noms.

8. Que fait man [commande] ? Exemple : man ls

man affiche le manuel d'une commande (on en sort avec la touche q).

« Exécuter une commande en tant que root » : non. C'est sudo.

« Afficher l'utilisateur·rice connecté·e » : non. C'est whoami.

« Interrompre une commande bloquée » : non. C'est la touche Ctrl+C.

3. Création et manipulation de fichiers

9. Que fait touch [fichier] ? Exemple : touch exam1.txt

touch crée un fichier vide (s'il existe déjà, il change seulement sa date).

« Créer un dossier vide » : non. Un dossier, c'est mkdir.

« Ouvrir un fichier pour l'écrire » : non. touch n'ouvre aucun éditeur : il crée le fichier, vide.

« Afficher le contenu d'un fichier » : non. C'est cat.

10. Que fait mkdir [dossier] ? Exemple : mkdir archives

mkdir (make directory) crée un dossier.

« Créer un fichier vide » : non. Un fichier vide, c'est touch.

« Supprimer un dossier » : non. Supprimer un dossier vide, c'est rmdir.

« Aller dans un dossier » : non. Se déplacer, c'est cd.

11. Que fait cp [source] [destination] ? Exemple : cp notes.csv projets/

cp (copy) copie la source vers la destination : l'original reste à sa place.

« Déplacer, sans garder l'original » : non. Si l'original disparaît, c'est mv.

« Renommer le fichier indiqué » : non. Renommer, c'est mv.

« Comparer les deux fichiers » : non. cp ne compare rien : il fabrique une copie.

12. Que fait mv [source] [destination] ? Exemple : mv nsi ../archives/

mv (move) déplace ou renomme : l'original quitte sa place.

« Copier, en gardant l'original » : non. Garder l'original, c'est cp.

« Supprimer un fichier » : non. C'est rm.

« Créer la destination » : non. Créer un dossier, c'est mkdir.

13. Que fait rm [fichier] ? Exemple : rm brouillon.txt

rm (remove) supprime un fichier, définitivement.

« Mettre un fichier à la corbeille » : non. Il n'y a pas de corbeille dans le terminal : le fichier est perdu.

« Vider un fichier, sans le supprimer » : non. rm ne garde rien : le fichier disparaît.

« Renommer un fichier » : non. C'est mv.

14. Que fait rmdir [dossier] ? Exemple : rmdir archives

rmdir (remove directory) supprime un dossier vide ; il refuse un dossier qui n'est pas vide.

« Supprimer un dossier et son contenu » : non. rmdir refuse un dossier qui n'est pas vide (c'est rm -r).

« Créer un dossier vide » : non. C'est mkdir.

« Vider un dossier, en le gardant » : non. rmdir supprime le dossier lui-même, s'il est vide.

20. Quelle est l'arborescence sous /home/eleve après ces commandes ?

Le dossier nsi (avec tp1.py) est passé de devoirs à archives :

eleve/
|-- archives/
|   `-- nsi/
|       `-- tp1.py
|-- devoirs/
`-- projets/

« devoirs/ contient archives/, qui contient nsi/ ; projets/ » : non. mkdir archives est tapé depuis /home/eleve, avant cd devoirs : archives est créé à côté de devoirs.

« archives/ contient nsi/ ; devoirs/ contient nsi/ ; projets/ » : non. mv déplace : nsi n'est plus dans devoirs (garder l'original, c'est cp).

« archives/ est vide ; devoirs/ contient nsi/ ; projets/ » : non. Depuis devoirs, ../archives désigne /home/eleve/archives : le déplacement a bien eu lieu.

Feuille 2 : Chercher, les droits

1. Les commandes des droits

21. Que fait ls -l [dossier] ? Exemple : ls -l /home/prof

ls -l (long) liste avec, pour chaque fichier, ses droits, son propriétaire, son groupe, sa taille et sa date.

« Lister aussi les fichiers cachés » : non. Les fichiers cachés, c'est ls -a.

« Lister les fichiers les plus récents » : non. -l ne trie pas : il donne les détails (long).

« Lister en une ligne, sans détail » : non. C'est le contraire : -l donne une ligne détaillée par fichier.

22. Que fait chmod [droits] [fichier] ? Exemple : chmod 640 notes.csv

chmod (change mode) change les droits d'un fichier ou d'un dossier.

« Changer le propriétaire d'un fichier » : non. C'est chown.

« Changer le nom d'un fichier » : non. C'est mv.

« Afficher les droits d'un fichier » : non. Les afficher, c'est ls -l.

23. Que fait chown [utilisateur] [fichier] ? Exemple : chown prof tp1.py

chown (change owner) change le propriétaire d'un fichier ; c'est réservé à root.

« Changer les droits d'un fichier » : non. C'est chmod.

« Changer le nom d'un fichier » : non. C'est mv.

« Afficher le propriétaire du fichier » : non. L'afficher, c'est ls -l.

24. Que fait sudo [commande] ? Exemple : sudo chown eleve notes.csv

sudo exécute la commande qui le suit avec les droits de root, l'administrateur·rice.

« Afficher le manuel d'une commande » : non. C'est man.

« Changer le propriétaire d'un fichier » : non. C'est chown, la commande de l'exemple : sudo lui donne les droits.

« Arrêter l'ordinateur en tant que root » : non. sudo n'arrête rien : il lance la commande qui le suit.

3. Les droits

27. À ton tour : quels droits le groupe info a-t-il sur notes.csv ?

- (un fichier), rw- (le propriétaire, prof), r-- (le groupe, info), --- (les autres) : le groupe peut lire le fichier, pas le modifier.

« Lire et écrire (rw-) » : non. rw- sont les droits du propriétaire, prof : les trois premières lettres après le tiret.

« Aucun droit (---) » : non. --- sont les droits des autres : les trois dernières lettres.

« Lire et exécuter (r-x) » : non. Il n'y a aucun x dans -rw-r----- : personne ne peut l'exécuter.

28. eleve est dans le groupe info. Pourquoi peut-il copier notes.csv ?

Pour copier, il suffit de lire l'original : le groupe info a le droit r. Il ne pourrait pas le modifier (pas de w).

« eleve est le propriétaire de notes.csv » : non. Le propriétaire est prof : le nom écrit juste après le nombre de liens.

« cp ne regarde jamais les droits d'un fichier » : non. Les droits comptent toujours : sans r, cp répondrait « Permission denied ».

« Le groupe a le droit d'écrire dans le fichier » : non. Le groupe n'a pas w. Et copier ne demande pas d'écrire dans l'original.

31. Dans /home/prof, prof tape la commande ci-dessous. Il est pourtant le propriétaire de notes.csv : pourquoi ce refus ?

Donner un fichier à quelqu'un d'autre est réservé à root, l'administrateur·rice : le système le protège. prof doit passer par sudo.

« chown s'écrit avec sudo devant, toujours » : non. La plupart des commandes se lancent sans sudo : c'est l'opération qui demande les droits de root.

« Il faut d'abord écrire le nom du fichier » : non. L'ordre de la commande est juste : d'abord le nouveau propriétaire, puis le fichier.

« Le groupe info n'a pas le droit w » : non. Les droits rwx ne suffisent pas : même le propriétaire ne peut pas donner son fichier.
