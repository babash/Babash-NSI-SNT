1. Le code de César

Depuis l'Antiquité, les chefs d'État et les armées cherchent à protéger leurs secrets. La cryptographie (du grec kruptos, « caché », et graphein, « écrire ») est née de ce besoin.

Jules César utilisait une substitution mono-alphabétique : chaque lettre du message est remplacée par la lettre située un certain nombre de rangs plus loin dans l'alphabet. Avec un décalage de 3, A devient D. Révolutionnaire à son époque, ce système a une faiblesse majeure : la structure du message ne change pas. Si E est la lettre la plus fréquente de la langue, la lettre qui le remplace sera, elle aussi, la plus fréquente du message codé.

Cette fonction décale les lettres d'un message pour le rendre illisible. Complète, pour chaque composant, son nom dans le code, son type et son rôle. Les rôles possibles : Texte à cacher, Valeur du décalage, Référence des 26 lettres, Stocke le résultat, Message chiffré final.

def crypter_cesar(message, cle):
    alphabet = "abcdefghijklmnopqrstuvwxyz"
    message_code = ""
    for lettre in message:
        indice = alphabet.find(lettre)
        nouvel_indice = (indice + cle) % 26
        message_code = message_code + alphabet[nouvel_indice]
    return message_code

À quoi sert l'opérateur % 26 dans la fonction crypter_cesar ?

  • À revenir au début de l'alphabet après z
  • À couper le message en paquets de 26
  • À choisir la clé au hasard
  • À mettre les lettres en minuscules

Calcule l'indice de « z » décalé de 3 : 25 + 3 = 28. Existe-t-il une lettre d'indice 28 ?

% 26 donne le reste de la division par 26 : 28 % 26 = 2, l'indice de « c ». Les indices restent entre 0 et 25 et l'alphabet « tourne » : après z, on revient à a.

2. Mission : décrypter

Pour lire un message intercepté, il faut la fonction inverse : elle retrouve le message d'origine à partir du message codé et de la clé. Complète-la. Je définis la fonction avec ses deux entrées, j'initialise un résultat vide, je parcours le message lettre par lettre, je trouve l'indice de chaque lettre, je lui retire la clé, j'ajoute la nouvelle lettre au résultat et je renvoie le résultat à la fin.

def [[decrypter_cesar]](message_code, [[cle]]):
    alphabet = "abcdefghijklmnopqrstuvwxyz"
    message = [[""|'']]
    [[for]] lettre in message_code:
        indice = alphabet.[[find]](lettre)
        nouvel_indice = (indice [[-]] cle) % 26
        message = message + alphabet[nouvel_indice]
    [[return]] message

print(decrypter_cesar("rsmb", 4))
noix

Pour retrouver la lettre d'origine, on fait le décalage dans l'autre sens.

Un résultat vide, c'est la chaîne vide "". La méthode qui trouve l'indice d'une lettre est la même que dans crypter_cesar.

def decrypter_cesar(message_code, cle):
    alphabet = "abcdefghijklmnopqrstuvwxyz"
    message = ""
    for lettre in message_code:
        indice = alphabet.find(lettre)
        nouvel_indice = (indice - cle) % 26
        message = message + alphabet[nouvel_indice]
    return message

decrypter_cesar("rsmb", 4) renvoie "noix". Pour « b » : 1 − 4 = −3, et −3 % 26 = 23 en Python, la lettre « x ».

Quelle est la seule différence entre decrypter_cesar et crypter_cesar ? Écris la ligne de code qui change.

Cherche la ligne qui calcule le nouvel indice.

Seul le calcul du nouvel indice change : nouvel_indice = (indice - cle) % 26. On retire la clé au lieu de l'ajouter (les noms des variables peuvent aussi changer, mais cela ne change pas l'algorithme).

3. Les attaques

L'attaque par force brute consiste à tester toutes les clés possibles.

Avec un alphabet de 26 lettres, combien y a-t-il de clés de décalage différentes ?

Un décalage de 26 donne le même résultat qu'un décalage de 0 (grâce à % 26).

Il y a 26 décalages différents (de 0 à 25), dont 25 qui changent vraiment le message (le décalage 0 ne cache rien). Une clé de 27 revient à une clé de 1.

Pourquoi cela rend-il le code de César fragile face à un ordinateur ?

  • Il essaie les 26 clés en un instant
  • Il connaît déjà toutes les clés secrètes
  • Il devine la clé du premier coup
  • La clé est écrite dans le message codé

Combien de temps faut-il pour essayer 26 clés à la main ? Et pour un ordinateur, qui fait des millions d'opérations par seconde ?

Il n'y a que 26 clés : un ordinateur les teste toutes en une fraction de seconde, puis on lit le seul résultat qui a du sens.

Pourquoi cela rend-il le code de César fragile face à un ordinateur ?

L'attaque par fréquence. En français, E est la lettre la plus fréquente (environ 15 %). Les fréquences : E 14,7 % ; A 7,6 % ; I 7,5 % ; S 7,1 % ; N 7,1 % ; R 6,7 % ; T 7,2 % ; O 5,8 % ; L 5,4 % ; U 6,3 % ; les autres lettres moins de 1 %. On intercepte : "oh vhfuhw hvw hq wrl". La lettre la plus fréquente est le h.

Si le h (indice 7) est un E (indice 4), quel est le décalage utilisé ?

On cherche le décalage du chiffrement : de E (4) vers h (7). C'est 7 − 4.

Le chiffrement a fait passer l'indice de 4 à 7.

7 − 4 = 3 : le décalage utilisé est 3.

Utiliser un mot connu (un crib) : on sait que le premier mot "oh" est "le". Cela confirme-t-il ton décalage ?

  • Oui : o → l et h → e reculent tous les deux de 3
  • Non : o → l recule de 4
  • Non : les deux lettres ont deux décalages différents
  • On ne peut pas le savoir

Indices : l = 11, o = 14, e = 4, h = 7.

o (14) → l (11) : 3 ; h (7) → e (4) : 3. Le décalage 3 est confirmé.

Mémo

César : une seule clé de décalage, donc 26 clés seulement, et une même lettre est toujours codée de la même façon. % 26 fait tourner l'alphabet. Décrypter : retirer la clé au lieu de l'ajouter.
