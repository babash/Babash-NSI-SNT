Nom et prénom :Classe :

Objectif : convertir un entier entre les bases 2, 10 et 16.

Je sais :

  • passer du binaire au décimal avec les puissances de 2 ;
  • passer du décimal au binaire et à l'hexadécimal ;
  • passer du binaire à l'hexadécimal par paquets de 4 bits ;
  • passer de l'hexadécimal au décimal et au binaire.

30 minutes · 3 questions et 1 bonus ★ · seul·e ou en binôme

Tu es ingénieur·e en informatique et tu travailles sur un ancien système qui stocke et traite l'information dans trois bases différentes. Pour que le système fonctionne, chaque donnée doit être bien interprétée. Ta mission : convertir les données brutes dans le format demandé.

Comment lire les lignes de code ? En Python, 0b annonce un nombre écrit en binaire et 0x un nombre écrit en hexadécimal. assert vérifie qu'une égalité est vraie : si tes conversions sont justes, Python n'affiche rien. Tu peux donc vérifier chez toi en recopiant la ligne dans Python.

1. Les registres binaires

Les registres du processeur affichent des valeurs en binaire. Complète chaque ligne avec la valeur décimale, puis la valeur hexadécimale.

# binaire == décimal == hexadécimal
assert 0b10101010 == [[170]] == 0x[[AA|aa|Aa|aA]]
assert 0b11100101 == [[229]] == 0x[[E5|e5]]
assert 0b11010000 == [[208]] == 0x[[D0|d0]]

De droite à gauche, les bits valent 1, 2, 4, 8, 16, 32, 64 et 128. Additionne les valeurs des bits à 1.

Pour l'hexadécimal, coupe l'octet en deux paquets de 4 bits : chaque paquet donne un chiffre de 0 à F (1010 = 10 = A).

10101010 = 128 + 32 + 8 + 2 = 170 ; paquets 1010 1010 = A A, donc AA.

11100101 = 128 + 64 + 32 + 4 + 1 = 229 ; paquets 1110 0101 = E 5, donc E5.

11010000 = 128 + 64 + 16 = 208 ; paquets 1101 0000 = D 0, donc D0.

2. Les adresses mémoire décimales

Tu dois régler des sauts dans la mémoire avec des adresses en binaire et en hexadécimal, mais les adresses sont données en décimal. Complète chaque ligne (en binaire, sur 8 bits ou sans les zéros de gauche).

# décimal == binaire == hexadécimal
assert 120 == 0b[[01111000|1111000]] == 0x[[78]]
assert 255 == 0b[[11111111]] == 0x[[FF|ff|Ff|fF]]
assert 16 == 0b[[00010000|10000]] == 0x[[10]]

Pour le binaire, cherche la plus grande puissance de 2 qui tient dans le nombre, retire-la, puis recommence (ou divise par 2 et note les restes).

Pour l'hexadécimal, divise par 16 : le quotient donne le premier chiffre et le reste le second (120 = 16 × 7 + 8).

120 = 64 + 32 + 16 + 8, donc 01111000 ; 120 = 16 × 7 + 8, donc 78.

255 = 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1, donc 11111111 ; 255 = 16 × 15 + 15, donc FF.

16 = 24, donc 00010000 ; 16 = 16 × 1 + 0, donc 10 (attention : « 10 » en hexadécimal vaut seize).

3. Les codes d'opération hexadécimaux

Les codes d'opération de la machine (les opcodes) sont souvent écrits en hexadécimal. Pour vérifier qu'ils sont valides, convertis-les en décimal, puis en binaire.

# hexadécimal == décimal == binaire
assert 0xA5 == [[165]] == 0b[[10100101]]
assert 0x3F == [[63]] == 0b[[00111111|111111]]
assert 0xC0 == [[192]] == 0b[[11000000]]

Rappel : A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.

En décimal : premier chiffre × 16 + second chiffre. En binaire : chaque chiffre hexadécimal donne un paquet de 4 bits (A = 1010, 5 = 0101).

A5 = 10 × 16 + 5 = 165 ; A = 1010 et 5 = 0101, donc 10100101.

3F = 3 × 16 + 15 = 63 ; 3 = 0011 et F = 1111, donc 00111111.

C0 = 12 × 16 + 0 = 192 ; C = 1100 et 0 = 0000, donc 11000000.

Bonus : l'erreur de parité

Un paquet de données arrive avec l'octet 11010011. Quelle est sa valeur décimale ? Et sa valeur hexadécimale ?

assert 0b11010011 == [[211]] == 0x[[D3|d3]]

Même méthode qu'à la question 1 : additionne les puissances de 2, puis coupe en deux paquets de 4 bits.

128 + 64 + 16 + 2 + 1 = 211 ; paquets 1101 0011 = D 3, donc D3.

Mémo

Binaire vers décimal : on additionne les puissances de 2 des bits à 1. Binaire et hexadécimal : un chiffre hexadécimal = un paquet de 4 bits. Décimal vers hexadécimal : on divise par 16 (quotient, puis reste).
