Données : pourquoi vaut-il mieux stocker les coordonnées GPS dans des tuples plutôt que dans des listes ?

  • Parce qu'un tuple se lit plus facilement et plus vite qu'une liste.
  • Parce qu'un tuple est immuable : une coordonnée ne peut pas être modifiée par erreur.
  • Parce qu'une liste ne peut pas contenir deux nombres à virgule.
  • Parce qu'une liste range ses éléments dans le désordre : la latitude et la longitude s'échangent.

Une ville ne bouge pas : ses coordonnées sont fixes. Le tuple, immuable, protège ces données contre une modification par erreur.

Distance : complète la fonction dist, qui calcule la distance (euclidienne) entre deux villes v1 et v2.

def dist(v1, v2, donnees):
    dx = [[donnees[v2][0] - donnees[v1][0] |donnees[v1][0] - donnees[v2][0] ]]
    dy = [[donnees[v2][1] - donnees[v1][1] |donnees[v1][1] - donnees[v2][1] ]]
    return (dx**2 + dy**2)**0.5
villes = {"Chirongui": (-12.932, 45.148), "Tsimkoura": (-12.912, 45.131)}
print(round(dist("Chirongui", "Tsimkoura", villes), 3))

dx est la différence des latitudes (indice 0), dy celle des longitudes (indice 1).

La latitude de v2 s'écrit donnees[v2][0].

dx = donnees[v2][0] - donnees[v1][0]
dy = donnees[v2][1] - donnees[v1][1]

Le sens de la soustraction ne compte pas : on élève au carré. Entre Chirongui et Tsimkoura, la distance vaut environ 0.026.

3. Le mur de la complexité

On compte les ordres de visite possibles des villes : c'est le nombre de « trajets différents ».

Combien de trajets différents existe-t-il pour 3 villes ?

Avec les villes A, B et C : ABC, ACB, BAC… Écris-les tous.

3 choix pour la 1re ville, 2 pour la 2e, 1 pour la dernière : 3 × 2 × 1 = 6.

Et pour 4 villes ?

4 choix pour la première ville, puis il reste 3 villes : 4 × …

4 × 3 × 2 × 1 = 24.

Et pour 5 villes ?

5 × 4 × 3 × 2 × 1 = 120.

Quelle opération mathématique, notée n!, généralise ce calcul pour n villes ?

La factorielle : n! = n × (n − 1) × … × 2 × 1.

Calcule le nombre de trajets pour 10 villes.

10! = 10 × 9 × 8 × … × 1. Tu peux partir de 5! = 120.

10! = 3 628 800 (plus de 3,6 millions).

En Python : from math import factorial, puis factorial(20).

20! = 2 432 902 008 176 640 000, environ 2,4 × 10^18 (2,4 milliards de milliards).

Un processeur moderne teste 10^9 trajets par seconde. Combien de temps lui faut-il pour 50 villes (3 × 10^64 trajets) ?

  • Environ une heure, avec un processeur aussi rapide
  • Environ 55 secondes, car 64 − 9 = 55
  • Environ 3 × 10^55 s, soit près de 10^48 ans
  • Environ 3 × 10^73 secondes, soit 10^66 ans

Temps = nombre de trajets / trajets par seconde. Pour diviser des puissances de 10, on soustrait les exposants.

Une année dure environ 3,2 × 10^7 secondes.

3 × 10^64 / 10^9 = 3 × 10^55 s. Divisé par 3,2 × 10^7 s par an : environ 9,5 × 10^47 ans. L'Univers a « seulement » 1,4 × 10^10 ans.

Conclusion : peut-on trouver la solution parfaite par « force brute » (en testant toutes les solutions) ? Quel est l'intérêt d'une méthode gloutonne ?

  • Oui, toujours : il suffit d'un ordinateur assez rapide et d'un peu de patience, même pour des centaines de villes.
  • Non, pas pour beaucoup de villes : le glouton donne vite une solution, souvent bonne mais pas toujours la meilleure.
  • Non, mais le glouton teste lui aussi toutes les solutions, simplement dans un meilleur ordre, donc bien plus vite.
  • Non, et le glouton, lui, trouve toujours la meilleure solution en un instant, car il va à la ville la plus proche.

La force brute est impossible dès quelques dizaines de villes (explosion factorielle). Le glouton répond en un instant, avec une solution acceptable, pas forcément optimale.

4. Analyse d'une tournée (cycle)

Départ de Chirongui, pour visiter Tsimkoura, Poroani et Choungui, puis revenir. Les distances, arrondies :

  • d(Chirongui, Tsimkoura) = 0.026 ; d(Chirongui, Poroani) = 0.043 ; d(Chirongui, Choungui) = 0.031 ;
  • d(Tsimkoura, Poroani) = 0.021 ; d(Tsimkoura, Choungui) = 0.045 ; d(Poroani, Choungui) = 0.066.

Calcule la longueur du trajet Chirongui → Tsimkoura → Poroani → Choungui → Chirongui.

N'oublie pas le retour à Chirongui (0.031) : c'est un cycle.

Additionne les 4 distances : n'oublie pas le retour au départ.

0.026 + 0.021 + 0.066 + 0.031 = 0.144.

Solution gloutonne : en partant de Chirongui, on va toujours à la ville non visitée la plus proche (d'abord : Tsimkoura ou Poroani ?). Quel est le trajet glouton complet ?

  • Chirongui → Choungui → Tsimkoura → Poroani → Chirongui
  • Chirongui → Tsimkoura → Poroani → Choungui → Chirongui
  • Chirongui → Tsimkoura → Choungui → Poroani → Chirongui
  • Chirongui → Poroani → Tsimkoura → Choungui → Chirongui

Depuis Chirongui, la plus proche est Tsimkoura (0.026, contre 0.043 pour Poroani et 0.031 pour Choungui).

Depuis Tsimkoura, compare d(Tsimkoura, Poroani) et d(Tsimkoura, Choungui).

Chirongui → Tsimkoura (0.026) → Poroani (0.021) → Choungui (seule restante) → Chirongui : c'est le trajet de la question précédente, 0.144.

Solution gloutonne : en partant de Chirongui, quelle est la ville la plus proche entre Tsimkoura et Poroani ? Donne le trajet glouton complet.

Défi : lequel de ces cycles est plus court que le trajet glouton ?

  • Chirongui → Tsimkoura → Choungui → Poroani → Chirongui
  • Chirongui → Choungui → Poroani → Tsimkoura → Chirongui
  • Chirongui → Poroani → Tsimkoura → Choungui → Chirongui
  • Chirongui → Poroani → Choungui → Tsimkoura → Chirongui

Calcule la longueur de chaque cycle avec les six distances, puis compare avec 0.144.

0.043 + 0.021 + 0.045 + 0.031 = 0.140 < 0.144. En allant d'abord à la ville la plus proche, le glouton s'est obligé à finir par le long trajet Poroani → Choungui (0.066).

Défi : trouve un trajet (un cycle) plus court que le trajet glouton pour ces 4 villes.

Conclusion : la méthode gloutonne donne-t-elle toujours la meilleure solution possible ?

  • Oui
  • Non

Non : le meilleur choix local (la ville la plus proche) ne mène pas toujours au meilleur trajet global.

5. Programmer le glouton

Algorithme : complète la fonction qui trouve la ville la plus proche de actuelle dans liste_villes.

def dist(v1, v2, donnees):
    dx = donnees[v2][0] - donnees[v1][0]
    dy = donnees[v2][1] - donnees[v1][1]
    return (dx**2 + dy**2)**0.5
def ville_proche(actuelle, liste_villes, coords):
    d_min = float("inf")
    prochaine = None
    for v in liste_villes:
        d = [[dist(actuelle, v, coords)|dist(v, actuelle, coords)]]
        if d < [[d_min]]:
            d_min = [[d]]
            prochaine = [[v]]
    return prochaine
coords = {"Chirongui": (-12.932, 45.148), "Tsimkoura": (-12.912, 45.131),

def dist(v1, v2, donnees):
    dx = donnees[v2][0] - donnees[v1][0]
    dy = donnees[v2][1] - donnees[v1][1]
    return (dx**2 + dy**2)**0.5

def ville_proche(actuelle, liste_villes, coords):
    d_min = float("inf")
    prochaine = None
    for v in liste_villes:
        d = dist(actuelle, v, coords)
        if d < d_min:
            d_min = d
            prochaine = v
    return prochaine

def tournee_gloutonne(depart, liste_villes, coords):
    visitees = [depart]
    a_voir = list(liste_villes)
    while len(a_voir) > 0:
        prochaine = ville_proche(visitees[-1], a_voir, coords)
        visitees.append(prochaine)
        a_voir.remove(prochaine)
    visitees.append(depart)
    return visitees

Mémo

Tuple : immuable, il peut servir de clé de dictionnaire. Glouton : choix local optimal, rapide mais pas toujours parfait. Complexité : la force brute échoue face à l'explosion factorielle (n! trajets pour n villes).
