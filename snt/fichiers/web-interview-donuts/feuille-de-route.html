Buffet des balises : <h1> / <p> : titre / texte normal · <em> / <strong> : italique / gras · <ul> / <ol> : liste à puces / liste numérotée · <a> : les liens hypertextes vers mon site ou un autre.

L'emballage structuré : le HTML sans <div>, c'est comme des ingrédients posés en vrac sur une table. Les « div » servent à créer des cartons de rangement. En leur donnant une classe (un nom), on permet au CSS de savoir quel carton décorer. Le « container » est la grande boîte qui garde tout bien aligné au centre, pour éviter que le texte ne touche les bords de l'écran.

Transfert : sens des balises. Peux-tu expliquer pourquoi on ne doit avoir qu'un seul <h1> par page ?

  • Parce que le navigateur refuse d'afficher un deuxième <h1> sur la page
  • Parce que <h1> écrit le texte en très gros, et ça prend de la place
  • Parce que <h1> est le titre principal : la hiérarchie reste claire
  • Parce que <h1> est réservé au nom du site, dans l'onglet

Pense au sommaire d'un livre : combien a-t-il de titres principaux ?

<h1> est le titre principal : il dit de quoi parle toute la page. Les sous-titres sont <h2>, <h3>… Avec un seul <h1>, la hiérarchie est claire pour les lecteurs, les lecteurs d'écran et les moteurs de recherche.

Transfert : les listes. Comment choisir entre <ul> et <ol> pour une liste d'ingrédients ?

  • L'ordre des ingrédients ne compte pas : <ul> (liste à puces)
  • Toujours <ol> : une liste doit être numérotée
  • Selon le nombre : <ul> pour une liste courte, <ol> pour une longue
  • C'est pareil : les deux affichent des puces

Les ingrédients d'un mataba ou d'un gâteau : doit-on les acheter dans un ordre précis ?

On regarde si l'ordre compte. Pour des ingrédients, non : <ul> (liste à puces). Pour les étapes de la recette, oui : <ol> (liste numérotée).

Pourquoi utiliser un framework comme Bootstrap ? Imagine que tu doives ouvrir une pâtisserie : vas-tu fabriquer tes propres moules, construire ton four et inventer chaque recette ? Non, tu vas utiliser des outils professionnels pour gagner du temps. C'est exactement le rôle de Bootstrap.

1. L'importation de styles (la mise en forme immédiate). Au début de ton fichier HTML, nous avons lié une copie de Bootstrap, rangée dans le dossier vendor (on peut aussi la charger depuis un CDN, un site qui distribue ces fichiers). C'est comme si tu connectais ton site à une immense bibliothèque de design. Avantage : tu n'as plus besoin d'écrire 50 lignes de CSS pour créer un bouton arrondi avec une ombre. En ajoutant simplement class="btn btn-primary", ton bouton devient instantanément bleu, réactif au clic et esthétique. C'est le principe du « standard » : ton site ressemble à une application moderne dès la première seconde.

2. L'importation de composants (les structures prêtes à l'emploi). Un « composant », c'est un objet web complexe (comme un carrousel ou une barre de navigation) que des expert·e·s ont déjà codé pour toi. Le carrousel est l'un des plus sophistiqués. Bootstrap fournit la « recette » HTML précise. Si tu respectes l'emboîtement (la grande boîte .carousel qui contient une boîte .carousel-inner qui contient chaque image .carousel-item), le framework s'occupe de tout le calcul mathématique pour faire défiler les images de manière fluide.

3. Le responsive : un site « élastique ». L'un des plus gros avantages de Bootstrap est le responsive design. Le framework est conçu pour que ton site soit aussi beau sur un écran géant que sur le petit écran d'un smartphone. Grâce à son système de grille (grid), les éléments se rangent ou se redimensionnent automatiquement, sans que tu aies à coder chaque version.

Transfert : pourquoi l'ID ? Que se passerait-il si deux carrousels sur la même page avaient exactement le même ID ?

  • Rien : les deux carrousels marcheraient chacun de leur côté
  • Les deux carrousels fusionneraient en un seul, avec toutes les images
  • La page ne s'afficherait plus du tout, à cause de l'erreur
  • Les boutons du 2e carrousel feraient défiler le 1er

Comment les boutons « précédent » et « suivant » savent-ils quel carrousel faire défiler ?

Un ID est unique dans une page. Les boutons « précédent » et « suivant » visent leur carrousel par son ID ; avec deux fois le même ID, le navigateur prend le premier : les boutons du 2e carrousel font défiler le 1er.

Transfert : la classe active. Pourquoi le carrousel a-t-il besoin qu'au moins une image possède la classe « active » ?

  • Pour dire quelle image montrer : sans elle, aucune n'est affichée
  • Pour que l'image soit cliquable et ouvre une autre page
  • Pour que le carrousel tourne plus vite, sans attendre de clic
  • Pour charger l'image depuis Internet au lieu du dossier local

Que voit-on dans un carrousel au chargement de la page ?

Bootstrap cache toutes les images du carrousel (.carousel-item : display: none) sauf celle qui a la classe .active. Sans elle, le carrousel est vide au départ.

Transfert : maintenance. Si tu veux changer la couleur de tous les badges du site, est-il plus rapide d'utiliser Bootstrap ou du CSS pur ? Pourquoi ?

  • Dans les deux cas, il faut modifier chaque badge du site, un par un
  • Le CSS pur, car on ne peut pas changer les couleurs de Bootstrap
  • Ni l'un ni l'autre : la couleur d'un badge est fixée par le navigateur web
  • Bootstrap : les badges partagent une classe, on la change à un seul endroit

Combien d'endroits faut-il modifier quand tous les badges portent la même classe ?

Avec Bootstrap, tous les badges utilisent la même classe .badge (et une classe de couleur) : on change la couleur à un seul endroit (la classe de couleur, ou une règle pour .badge), et tous les badges du site suivent.

Rendre le site vivant (UX et JS). L'UX (User Experience) est l'art de rendre la visite du site agréable et logique.

  • Le retour visuel : le :hover n'est pas juste « joli ». Il confirme à l'utilisateur·rice que l'élément est cliquable. C'est une réponse du site à l'action humaine.
  • Le JavaScript (JS) : c'est le langage qui gère l'intelligence du site. Un popover ne peut pas s'ouvrir « tout seul » en HTML : il faut un script qui surveille le clic. Bootstrap nous offre ces scripts (fichiers .js) : il nous suffit d'ajouter des attributs data-bs pour les activer.
  • L'équilibre : trop d'animations perdent le·la lecteur·rice. On utilise les finitions (lettrines, popovers) avec parcimonie, comme le sucre glace sur un gâteau.
  • Le professionnalisme : la favicon est le petit logo de 16 × 16 pixels dans l'onglet. C'est le détail qui transforme un projet scolaire en un véritable site web crédible.
  • Popover ou tooltip : le popover est fait pour du texte plus long (descriptions), tandis que le tooltip est une simple étiquette rapide.
  • L'accessibilité : ces interactions codées par des pros permettent aussi aux personnes qui utilisent un clavier ou un lecteur d'écran de naviguer sans encombre dans tes menus.

Transfert : expérience utilisateur. Pourquoi est-il risqué de mettre trop de popovers sur une seule page ?

  • L'information est cachée partout : on clique sans arrêt, on s'y perd
  • Parce que le navigateur limite le nombre de popovers sur une même page
  • Parce que les popovers effacent le texte de la page
  • Aucun risque : plus il y a de popovers, plus la page est claire
